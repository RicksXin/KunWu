# 面板、列表、按钮与交互状态

## 1. 面板层级

- `Panel/Level2`：建筑点击后拉起的基础通用面板。
- `Panel/Level1`：在 Level 2 基础上叠加独立顶部和底部装饰，用于更高层级或更完整的主面板。
- 面板标题、正文、按钮和列表内容始终是独立图层；背景图不得包含动态文字。
- 同类面板通过九宫格、Auto Layout 和内容槽适应高度，不为每个建筑生成近似边框。

## 2. Panel Item V2（Approved）

正式逻辑尺寸：`288×80`。  
推荐整图交付：`864×240 (@3x)`。  
组件集：[195:1138](https://www.figma.com/design/9uaK9zzfEzxGYZsCC1Njix/昆吾禁地?node-id=195-1138)。

### Default

- 偏黑的深黛底板，建立稳定承载面。
- 不使用实体边框、角标、墨渍、暗斑或黑色横纹。
- 仅保留极轻的暖色纤维纹理，不能干扰文字。
- 左右保持完整底板，不出现右侧突然变成纯黑的断层。

### Selected

- 左侧使用明确但克制的赭金光晕，选中态比常规态更突出。
- 赭金从左向右连续衰减，右侧平滑淡回深黛底，不出现硬边或黑色截断。
- 不增加实体描边，不用淡黑纹理表示选中。
- Default 与 Selected 共用 `Theme/Text/Primary` 和 `Theme/Text/Secondary`，不在切换状态时更换文字色。

### 编辑和实现

- 光晕、底色、纤维纹理分别保留为可编辑图层。
- 若导出整图，两种状态分别导出完整不透明底板，由同一 Sprite 切换。
- 若在 Cocos 组合实现，需记录底板、光晕、纹理的节点映射和 Blend/Opacity；不得只凭截图重做。
- Selected 状态还应配合选择语义或内容变化，不能仅靠极微弱色差。

## 3. 列表 Item 与按钮的语义边界

| 类型 | 用途 | 是否持续选中 | 视觉要求 |
|---|---|---:|---|
| `PanelItem/V2` | 列表行、面板内项目背景 | 是 | 整行承载信息，Default/Selected |
| `Button/Inline` | 资源行、卡片内紧凑操作 | 否 | 比升级按钮轻，不抢面板标题层级 |
| `Button/Footer` | 面板底部主/次操作 | 否 | 与行内按钮明显区分；轮廓简洁，不使用阶梯形 |
| `Button/ToggleSmall` | 筛选、分页、模式选择 | 是 | Normal/Selected 完整底图；不代替执行型按钮 |
| `IconButton` | 设置、加减、关闭 | 视功能而定 | 可见图可小，触控区保持 `48×48` |

“通用底部按钮”不得再误标为列表 Item 背景板；两者在 Figma 组件名、导出名和 Cocos Prefab 中都必须分开。

## 4. 按钮状态

执行型按钮按需提供：

```text
default → pressed → default
disabled
loading（有异步提交时）
```

持续选择型组件按需提供：

```text
default ↔ selected
disabled
locked（有解锁条件时）
```

- `pressed` 可由纯代码实现：在约 `100ms` 内先缩小再恢复，推荐 `1.0 → 0.96 → 1.0`。
- 参考节奏为前 `50ms` 缩小、后 `50ms` 回弹；避免改变布局尺寸，应缩放独立视觉节点。
- 按下动效不能替代 pressed 视觉反馈；必要时叠加轻微明度或颜色变化。
- disabled 必须保留禁用原因或可读提示，不能只把按钮整体变透明。
- 底部主按钮和次按钮通过层级、明度或装饰密度区分，不采用不规则阶梯外轮廓。

## 5. 信息文字背景

修士卡等复杂图片上的四行信息可加矩形柔光底：

- 中心区域较实，向四周渐变到透明。
- 外形保持方形/矩形，边缘不可读成椭圆。
- 不形成实质描边，不覆盖人物关键轮廓。
- 从上到下建议层级：灵息值用 Info；姓名用 Primary；职业·等级与道阶·天赋用 Secondary。
- “待上阵”等占位文案使用 Secondary 或 Disabled，但需保持在常规和选中底板上均可读。
