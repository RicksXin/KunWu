## 2. 设计状态

| 状态 | 含义 | 可否作为实现依据 |
|---|---|---|
| `Draft` | 结构、视觉或素材仍在探索；未标状态也按 Draft 处理 | 否 |
| `Review` | 已形成可评审方案，等待用户确认 | 否 |
| `Approved` | 用户已明确确认指定节点或版本 | 是 |

状态应标在方案 Frame 或组件集名称前，例如：

```text
[Draft] Event Panel
[Review] Cultivator Card
[Approved] Panel Item V2
```

批准对象必须精确到节点或版本。批准一个组件，不代表批准同页上的其他组件、素材或历史方案。

## 4. 评审流程

1. 方案 Frame 进入 `Draft`，保留目的、复用范围和变更说明。
2. 自检逻辑尺寸、文字可读性、状态完整度和资源边界后改为 `Review`。
3. 用户确认具体节点后改为 `Approved`，记录日期和确认范围。
4. 实现侧只读取 Approved 节点；若实现需要的状态缺失，退回 Figma 补齐，不口头补设计。
5. Approved 组件发生外观或结构变化时创建新版本；旧版本保留追溯，不原地悄悄覆盖。
