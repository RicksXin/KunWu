# 图片导入与组件化规范

## 1. PNG 导入后的定位

PNG 导入 Figma 后仍只是位图图层，不会自动变成可维护组件。推荐流程：

1. 将原图放入 `Assets / Source` Frame，保留透明画布和原始像素尺寸。
2. 检查主体是否过小、透明边缘是否异常、画布是否包含无意义留白。
3. 在逻辑尺寸 Frame 中放置图片，设置 Scale/Fit、锚点和裁切方式。
4. 用语义化 Frame 组合图片、文字、状态标记和触控区。
5. 将组合 Frame 创建为 Component；有状态差异时合并为 Component Set/Variants。
6. 页面只使用组件实例，避免复制后各自漂移。

位图不能自动获得 Auto Layout、状态、文字覆盖或 Cocos 行为；这些能力来自外层 Component 结构。

## 2. 素材画布整理

- 同类素材先统一逻辑占位框，再按视觉主体对齐，不用强行缩放画布本身掩盖留白问题。
- 头像、边框、空槽剪影必须共享同一逻辑尺寸和锚点。
- 装饰框与头像分层；头像不得越过装饰框的可视/遮罩范围。
- 对需要局部越界的建筑或特效，在总览稿中展示完整素材，在运行时 Frame 中通过 Clip/Mask 表示实际可见范围。
- 原始图片与整理后组件分区保存，避免把导入源图直接当最终组件。

## 3. Component 与 Variant

- 同一结构、不同内容：使用组件实例覆盖图片和文字。
- 同一结构、不同状态：使用 Variant，例如 `state=default/selected/disabled`。
- 外形或层级完全不同的控件不要为了“通用”强塞进同一组件集。
- 图片背景、纹理、光晕、边框、内容和点击热区分别命名；所有可编辑效果不得扁平化为一张截图后继续设计。
- 页面专属内容通过 Slot/实例覆盖表达；通用组件内不保存建筑名、修士名等具体业务文案。

## 4. PNG 序列、图集与 JSON

- 透明 PNG 序列本身不要求配 JSON。按统一命名导入 Cocos 后，可以直接创建 AnimationClip。
- JSON 通常来自 TexturePacker 等图集工具，用于描述整张 Atlas 中各帧的位置；它不是 GPT Image 生成序列帧的必备文件。
- GPT Image 可辅助生成独立帧，但帧间位置、轮廓、透明边缘和光照需要人工校正。
- 图集应由 Cocos 自动图集或 TexturePacker 从独立 PNG 打包，不让图像模型直接绘制整张排版图集。
- Figma 可把多帧做成 Prototype 预览，或导入 GIF 观察效果；它不替代 Cocos 的运行时序列帧资源与 AnimationClip。

推荐短循环范围：烟雾、灯火、旗帜、传送阵光效使用 `4–8` 帧；浮尘、光点优先使用 Cocos 粒子系统，只提供粒子贴图。

## 5. Spine 边界

- Spine 可以导入分层图片，但不会从一张合成图自动生成可用的骨骼、权重和动画。
- GPT Image/Figma 可提供角色或建筑的分层部件与动作参考；骨骼绑定、网格、权重和动画仍需在 Spine 编辑器制作。
- 当前阶段建筑主体优先静态透明 PNG，建筑成长等级使用关键等级静态图；仅在确有长期复用的复杂角色动画时评估 Spine。

## 6. 不应组件化的内容

- 仅用于灵感或对照的第三方截图。
- 未清理版权和来源的临时图片。
- 一次性评审草图、重复历史输出和无逻辑尺寸的截图。
- 已被新 Approved 版本替代的旧视觉；旧稿应移入 Archive，而不是继续出现在 Assets 搜索结果中。
