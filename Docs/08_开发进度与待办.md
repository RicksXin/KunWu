## 0. 当前结论

当前可见流程已接通到首个建筑功能页：

```text
Boot 启动页 → Camp 营地大厅 → 灵圃生产弹窗
```

营地当前为三层横滑大厅：顶部真实资源与主线、中部建筑/NPC、底部系统入口和灵石余额均已接线。灵圃已接入岗位分配、在线生产、杂役招募、资源储量升级与存档；其余建筑入口继续显示锁定或未开放反馈。修士、地图和战斗已有较完整的纯逻辑与测试，尚未串成玩家可操作流程。

最近一次已记录的工程健康状态（本轮 API First 改造后待用户复验）：

- TypeScript 类型检查通过。
- 678 个单元测试通过。
- Boot、数据与 Bundle 基础可运行；Camp 模块拆分的历史场景校验欠账仍在 1.2.8 跟踪。
- P0 自动门禁 11/11 通过。
- Web 构建产物约 8.2 MB，低于 25 MB 预算。
- P0 技术条目 20 项完成 18 项，剩真机适配和人工评审。

## 1. 当前最高优先级：localhost 最小可玩闭环

目标流程：

```text
新档进入营地
→ 分配杂役生产
→ 在入山整备面板中查看并编成修士
→ 携带灵粮入山
→ 地图移动并揭开迷雾
→ 触发一场固定战斗
→ 获胜并回城结算
→ 刷新页面后进度仍在
```

## 5. Todo 维护规则

- Todo 以页面为主，技术任务写在所属页面下面。
- “逻辑有测试”只代表前置完成，不代表页面完成。
- 页面只有在 localhost 可进入、可操作、可返回时才能标记完成。
- 涉及资源或队伍状态的页面还必须通过刷新恢复验证。
- 不允许保留无反馈的按钮；未开放功能必须明确显示锁定或提示。
- 测试数量是健康指标，不作为产品进度百分比。
- 每完成一个页面，同步更新“页面总览”和对应验收结果。
