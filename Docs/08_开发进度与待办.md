按 PRD-10 §4 四步写入流程实现：序列化校验 → 旧主档进 backups → 同一 transaction

  原先 `map_03 → map_04` 的无条件预载会抹掉 `map_02 → map_04` 的条件预载。
  按 PRD-05 §3 修正为「条件预载以来源地图为键」——地图 3 到地图 4 是常规出口，
  地图 2 到地图 4 才是隐藏条件出口。

### `#17b` P0-TECH-003b 引擎侧：`CocosBundleHost` — 已完成

`presentation/CocosBundleHost.ts`，三个方法映射到 `cc.assetManager`：

| 接口方法 | 引擎 API |
|---|---|
| `load(name)` | `assetManager.loadBundle` 包成 Promise |
| `release(name)` | `bundle.releaseAll()` + `assetManager.removeBundle(bundle)` |
| `isLoaded(name)` | `assetManager.getBundle(name) !== null` |

`release` 必须同时 `removeBundle`：只 `releaseAll` 会留下空壳，
`getBundle` 仍返回非 null，导致 `isLoaded` 误报已加载。

加载策略全在 `BundleLoader`（26 测）。构建产物已验证地图包独立分离
（`assets/map_01`、`assets/map_02` 各 8KB，不进主包）。

## 7. 维护约定

- **状态只有两种**：`- [ ]` 未完成、`- [x]` 已完成。不设「进行中」「半完成」。
- 一项做到一半就不能勾——**拆成两个条目**，已完成的那半勾上，剩下的另立编号
  （范例见 §1 拆分说明：`P0-TECH-003` → `#2` + `#17`）。
- 勾选时同步：§1/§2 清单的复选框、§0 现状的完成计数、条目详情标题的
  「已完成 / 未完成」后缀，并把条目从 §4 移到 §3。
- 每个未完成条目应写明「完成判定」，避免完成与否靠主观判断。
- 新增需求沿用 PRD 编号；PRD 里没有的临时任务用 `#序号` 并注明来源。
