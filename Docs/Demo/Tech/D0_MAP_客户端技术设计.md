# D0 地图探索客户端技术设计

版本：0.6
日期：2026-08-02  
范围：`map_01`「破禁山麓」可玩样机

## 1. 目标与裁剪

本轮只接通营地到地图探索的最小可玩流程，不等待正式美术，也不提前实现完整战斗、
随机事件池、采集、跨图和完整结算。D0 地图包含固定敌人、一次性剧情事件和一次性宝箱。
地图正式逻辑边界仍为 `48×64`；D0 只开放其中一个 `15×15`
紧凑区域，其余坐标返回不可通行，D1 可以沿原坐标继续扩建。

Demo 阶段按约定不强制 API First。客户端直接使用 `MapApplicationService`，但领域坐标、
移动、迷雾和存档模型仍与正式架构保持一致。

## 2. 页面与素材

- UI 唯一逻辑基准为 `375×817`，顶部 HUD、地图视口和底部操作区均固定在该窗口内。
- Tile 源像素为 `16×16`，逻辑显示为 `48×48`，保持 Nearest 过滤。
- 地形暂用仓库已有 Puny Dungeon CC0 素材；许可与来源见地图 Bundle 内
  `third_party/puny_dungeon/PROVENANCE.md`。
- CC0 素材导入失败时显示同布局的可操作像素灰盒，不能阻断状态流。
- `Map.scene` 只保存 Canvas、Camera 和 `MapPresenter` 挂载点；D0 HUD 和地图运行节点由
  Presenter 按 `375×817` 逻辑尺寸创建，后续替换正式 Prefab 时不影响领域层。

## 3. 状态流

```text
营地选择 map_01
→ 入山整备再次校验队伍、灵息、负重和灵粮
→ MapApplicationService 暂存 pending departure（仅内存，不扣资源）
→ Router 确保 map_01 Bundle 已加载并进入 Map.scene
→ MapPresenter 成功读取 map_01_demo.json
→ MapApplicationService 原子扣队伍灵息与携带灵粮、冻结灵息恢复锚点、创建 ExpeditionState 并保存
→ 地图解锁输入
```

地图 Bundle、场景或数据加载失败时，pending departure 取消或保持未提交状态，玩家资源不变。
正式进入地图后若存档写入失败，应用服务回滚 Wallet、修士灵息和 ExpeditionState。

启程时开山镐与探灵镜从营地库存转入 `ExpeditionState.carriedItems`。D0 已用
探灵镜校验敌情探查资格，本阶段查看不消耗；开山镐尚无实际资源点消耗点。
后续对象需要消耗工具时，必须在应用服务中与对象结果原子保存。

## 4. 地图运行状态

复用现有 `Profile.expedition`：

- `mapId`：当前地图；
- `position`：`GridCoord`，领域层不接触像素；
- `remainingGrain`：本次携带且尚未消耗的灵粮；
- `revealedTiles`：三态迷雾中已探明坐标；
- `temporaryLoot`：本次入山获得、尚未安全带回营地的临时战利品。
- `partyMemberIds`：启程时冻结的队伍成员，用于野外负重、队伍面板和休整疗伤。
- `grainCapacity`：本次启程时的灵粮容量，野外补给不得超过此值。
- `grainDepletionSteps`：灵粮归零后已完成的衰竭位移数，范围 `0–4`。
- `carriedItems`：启程时从营地库存转入的开山镐、探灵镜等携带物。
- `restUsesRemaining / isResting / restHealingUsed`：休整次数与刷新恢复状态。

Profile 以 `completedMapObjects: Record<string, boolean>` 持久保存对象状态，键为
`map_id.object_id`。宝箱和一次性剧情跨入山保留；普通野外敌人的完成标记只在本次入山保留，
创建新的 `ExpeditionState` 时按当前地图配置原子清除。对象状态于 v6 引入；v7 增加启程队伍、携带物、
灵粮容量与休整状态，并为 v6 存档发放 1 张初始归营符；v8 增加
`grainDepletionSteps`，旧档迁移默认补 0。`expeditionPreparation` 仍只保存营地中的
队伍和下次携带偏好。

## 5. 移动、迷雾与镜头

- 只允许上下左右相邻一格；点击非相邻格只提示，不自动寻路。
- 普通石地消耗 1 灵粮，碎石地消耗 2 灵粮，已激活的入口传送阵格消耗 0。剩余灵粮
  小于本步成本时耗尽剩余量并完成本步，从下一次位移开始计算断粮衰竭。
- 灵粮归零后，每次成功位移都令 `grainDepletionSteps + 1`，零成本地形也计步；第 4 步
  返回 `partyWiped: true`，之后不再允许继续移动。
- 每次成功移动后，以半径 2 更新迷雾，再保存位置、剩余灵粮、衰竭步数和已探明格；保存成功后才由
  表现层播放圆点从旧格中心到新格中心的 `0.32s` 代码 Tween，使用
  `cubic-bezier(0.333, 0, 0.667, 1)` 缓入缓出；业务失败时不播放假移动。
- 移动动画期间 HUD 使用移动前的灵粮快照，抵达后才切换到本步结算后的灵粮与衰竭
  文案，避免角色尚未走完就提前显示下一阶段。
- 圆点抵达后，镜头用 `0.18s` Tween 跟随至新位置；镜头在 `15×15` 开放区域边缘夹取，
  不能露出空白。动画期间锁定移动输入，避免并发提交下一步。
- 顶部常驻显示剩余灵粮、当前坐标和按 Dijkstra 计算的入口返程估算。灵粮归零后，
  灵粮数值替换为“断粮 / 气血亏空 / 步履维艰 / 生机将绝”，地图上方同时显示
  “警告：灵粮已尽，护体灵息仅可支撑 x 步”。
- 顶部和底部 HUD 复用全局安全区适配，地图操作按钮不会压到系统手势区。

## 6. 地图对象、休整、遭遇与归营

- 顶部左侧常驻“地图名称（坐标）/负重/灵粮”；右侧为休整、归营、队伍、背包、
  设置。两区下方复用营地主线任务摘要组件。
- D0 每次入山只有 1 次休整。进入休整立即原子保存；休整中锁定地图输入。
- 补充灵粮按外置配置消耗 `beast_meat`（妖兽肉）或 `bigu_cake`（辟谷饼），没有食材
  时只提示，不修改灵粮。运功疗伤每次休整仅可执行一次。
- 背包面板只读取 `temporaryLoot`，使用五列 `48×48` 物品格平铺展示；格内为物品图标和右下角数量。
  已有物品图标从 camp Bundle 复用，缺失图标的物品使用可辨识灰盒图形降级；队伍与设置暂显示“功能待定”。
- 归营从任意坐标原子消耗 `return_talisman`（归营符）并按安全返回结算。无归营符时
  只能补粮后继续行动或在衰竭步数耗尽前返回入口，不提供紧急撤离。
- 角色移动 Tween 抵达入口格后才打开归营确认层；启程初始化和刷新恢复在入口时
  不自动弹出。确认使用无符的安全归营，取消只关闭弹窗。
- 归营结算成功后不打开结果面板；持久全局遮罩以 `0.28s` 正弦缓动变为纯黑，在黑屏中
  切换到营地，再以 `0.36s` 正弦缓动恢复。转场期间全程拦截输入；保存失败不开始转场。

- 固定敌人「残禁石傀」位于配置坐标；只有进入当前视野时才显示标记。
- `MapEventPanelController` 统一管理敌人、故事、宝箱、NPC、资源点和秘境入口的
  信息区与行动区。`map_01_demo.json.eventActions` 决定当前显示“迎战、探灵、
  交谈、具体操作、闲谈、离开”中的哪些按钮；操作按钮文案由对象配置为
  “开采”、“破禁”、“开启”或“进入”。
- 战斗、正式对话、闲谈、资源操作与秘境入口分别使用 `map.encounterTriggered`、
  `map.dialogueRequested`、`map.smallTalkRequested`、`map.resourceOperationRequested` 和
  `map.dungeonEntryRequested` 交给后续模块；均携带 `mapId + objectId`，战斗额外携带 `enemyId`。
- 踏入敌人格只打开面板；点击“迎战”才发出 `map.encounterTriggered`。点击“探灵”
  先校验 `carriedItems.lens`，有探灵镜时在信息区展开敌方特性。
- 一次性剧情事件「残碑留痕」和宝箱「封禁木匣」在格子至少被探明后显示代码图形标记。
  纯阅读故事保存完成状态后展示；宝箱必须点击“开启”才结算，“离开”不发奖励。
- 宝箱奖励为 1 把开山镐，开启成功时先写入 `temporaryLoot`，与对象完成状态在同一次保存中提交；
  保存失败同时回滚二者。正常归营时奖励合并进 Inventory。
- 安全归营返还剩余携带物、合并临时战利品，随后清空 ExpeditionState。
- 第 4 个衰竭步的移动与镜头动画结束后，`MapGrainDepletionController` 调用应用服务进行断粮阵亡
  结算，不触发终点格对象。应用服务将本次入山修士生命归零、标记阵亡并从所有队伍
  槽位移除，合并携带物与临时战利品后返还 `floor(总量 / 2)`，清除
  `ExpeditionState`，再返回营地并刷新还魂殿待处理提示。
- D0 Profile 尚无野外装备实例范围，因此当前阵亡减半只覆盖 `carriedItems + temporaryLoot`；
  装备模型接入后必须按 PRD-05 的稳定实例 ID 规则补齐，不能在页面层随机删除。
- 入山期间不结算灵息自然恢复；返营保存成功时才以当前 UTC 时间重建恢复锚点。

## 7. 刷新、失败与恢复

- 每次成功移动都进入全局存档队列；写入失败时回滚本步位置、灵粮和迷雾。
- 移动保存同时覆盖衰竭步数；补充灵粮成功将步数重置为 0，补给保存失败时连同食材、
  灵粮一起回滚。
- Boot 发现 `Profile.expedition != null` 时先加载对应地图 Bundle，再直接恢复 Map.scene，
  不固定回到 Camp。
- 刷新恢复到 `grainDepletionSteps === 4` 时，地图保持锁定并优先重试阵亡结算；保存
  失败时继续保留第 4 步存档并提示刷新重试，不能重复返还物品。
- 地图数据无法解析时保持现有存档，不静默清空进度；界面提示返回营地重试。
- 地图免费素材加载失败时不回滚业务状态，继续使用灰盒地形。

## 8. 人工验收

由用户从 Boot 场景启动预览，依次确认：

1. 从传送阵整备并选择「破禁山麓」，场景成功切换后才扣灵息和携带灵粮。
2. 点击相邻格、底部方向按钮和键盘方向键均只能四向逐格移动；角色圆点平滑移动到下一格，
   抵达后镜头跟随，动画中连续输入不会重复提交。
3. 普通地形扣 1、碎石地形扣 2；剩余量不足整步成本时耗尽为 0，不出现负数。
4. 迷雾随移动揭示，走远后已探明地形保留、敌人实时标记隐藏。
5. 进入 `(5,4)` 打开「封禁木匣」事件面板；点“离开”不发奖，再次进入后点
   “开启”才获得 1 把开山镐。进入 `(7,8)` 显示「残碑留痕」故事和“离开”。
6. 进入 `(9,9)` 显示「残禁石傀」的“迎战 / 探灵 / 离开”；有探灵镜时能看到
   敌方特性，无探灵镜时给出明确提示，只有点“迎战”才发出战斗交接。
7. 休整次数为 1；无食材时补给提示正确，有食材时消耗 1 份且不超过启程灵粮容量。
8. 运功疗伤只恢复本次入山队伍的存活修士，同一次休整不能重复执行。
9. 休整中刷新仍恢复休整面板，次数不退回；结束休整后坐标不变。
10. 地图背包只显示本次入山所得；队伍和设置点击显示“功能待定”。
11. 任意坐标消耗 1 张归营符后，剩余携带物和临时战利品正常入库；无符时不扣物品。
12. 从其他格返回入口后弹出二次确认；确认归营不消耗归营符，取消后留在原格。
13. 灵粮归零时出现正式警示，顶部从“断粮”依次变化为“气血亏空 / 步履维艰 /
    生机将绝”；归零后的第 1 步仍为“断粮”，第 4 步动画结束后全队阵亡。
14. 阵亡修士生命为 0、从队伍槽位移除并使还魂殿出现待处理提示；携带物与临时
    战利品按合并总量向下取半返还，不能重复结算。
15. 在第 1–3 个衰竭步休整补粮后，顶部恢复灵粮数字且衰竭步数归零；补给失败不改状态。
16. 地图中刷新浏览器后恢复原位置、灵粮、衰竭步数、迷雾和携带物，不重复扣出发成本；
    第 4 步结算保存失败后刷新会重试。
17. `375×817` 下顶部信息、五个操作入口、任务区、断粮警示、地图视口和底部方向键完整显示。

本轮按工程约定不由 Codex 代跑类型检查、单测、构建或浏览器视觉验收。
