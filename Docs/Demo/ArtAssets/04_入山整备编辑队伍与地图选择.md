## 6.2 尺寸与导出总则

- UI 唯一逻辑基准和玩家可见窗口为 `375×817`。
- 每张新 UI 素材都必须同时标注逻辑尺寸和最终 PNG 实际尺寸；本批默认交付
  `@3x` RGBA PNG。
- `360×640` 不参与本节任何 UI 布局或 UI 素材尺寸推导；`1080×1920` 只表示迁移中的
  旧工程坐标，不能静默换算成新素材尺寸。
- 像素边缘必须落在整数坐标，使用硬边缘、无抗锯齿和 Nearest 过滤。若 GPT Image
  无法直接输出精确尺寸，先生成高清透明母版，再离线裁切、像素化并缩放到表中尺寸。
- 九宫格素材表中填写的是“九宫格源图逻辑尺寸”，运行时可拉伸到指定目标尺寸；边角、
  纹样和描边必须全部位于不可拉伸区。
- 修士名、职业、等级、灵息、战力、境界、灵根资质、队伍编号、地图名、地图消耗、数量、重量、
  锁定原因和所有按钮文案均由 Cocos Label/本地化表渲染，不得烘焙进 PNG。
- 模态暗色遮罩、禁用态降亮度和按钮按下反馈优先由 Cocos 颜色/透明度过渡完成，不单独
  占用美术图片。修士卡信息直接叠在人物立绘上，不制作或运行时绘制信息黑底、渐隐底板。

## 6.6 修士卡框与空位剪影提示词

#### 修士卡通用边框

```text
生成一张79×205逻辑尺寸、237×615像素@3x的竖向修士卡边框，透明中心，透明画布。使用纤细黑玉外框、旧青铜小护角和极少量云纹刻线，边框宽度控制在2–3个逻辑像素。人物信息会直接叠在立绘下半区，因此边框下段保持简洁且中心完全透明，不制作信息底板。边框不表示资质和职业，不使用固定颜色品质光，不画人物、文字、星星或底色，不允许拉伸。
```

#### 空槽人物剪影

```text
生成64×112逻辑尺寸、192×336像素@3x的匿名修士空位剪影，透明背景。正面略侧身，中性人物比例，束发、短披肩和简洁道袍形成原创中国修士轮廓；人物内部使用黛黑与极暗青灰两级像素块，只保留头、肩、衣摆的大形，不出现面部、武器、职业、性别特征或文字。剪影四周至少留4个逻辑像素透明边。
```

修士卡边框必须把现有 `ui_camp_avatar_frame.png` 与 `ui_ling_pu_panel_frame.png` 作为
图像输入，只延展其黑玉、旧青铜、深木的边角语言，不另创一套银色或高亮品质框。

## 6.12 制作顺序

1. 先从 Cocos 导出三张 `375×817` 灰盒截图，锁定实际信息密度和安全区。
2. 把已生成的灵圃面板、资源行、加减按钮、大厅头像框、灵粮和灵石图标，以及
   [灵圃分册 §5.4.4](03_灵圃生产弹窗.md#544-通用行内按钮与通用底部按钮) 的通用行内按钮和重做后的通用底部按钮合成到三张灰盒截图；底部按钮重做前可使用纯色占位，
   不把现有阶梯形按钮作为最终合成基线。
3. 制作修士卡框并先生成石岩一张立绘，验证卡内人物居中、直接叠字可读性和 `50×50` 头像裁切。
4. 石岩通过后，以其眼高、像素密度和光照为参考生成陆清、白灵、墨言。
5. 制作空槽剪影、开山镐、探灵镜和通用锁，同时检查正常、选中、禁用与锁定状态。
6. 只有合成或真机验收明确失败时，才制作 §6.10 对应的可选优化素材。
7. 统一离线裁切为目标 `@3x` 尺寸，再由 Cocos Creator 导入并生成 `.meta`。
