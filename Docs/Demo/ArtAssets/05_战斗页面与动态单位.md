## 5.1 已确认的画面规则

- 玩家可见窗口与 UI 唯一设计基准为 `375×817`；此前口述的 `385×817` 不作为制作尺寸。
- 页面底部至少保留 `54px` 安全区；我方修士不得压入该区域。
- 普通敌群位于中上方并排显示；首领居中，召唤单位可采用三角阵或环绕阵。阵型只影响
  视觉排版，不产生前后排、距离或承伤规则。
- 我方最多四名修士位于底部安全区上方并排显示。
- 敌我双方都使用单张静态战斗立绘。角色本体不制作 Idle、技能、受击或阵亡逐帧动作；
  技能释放、受击、治疗和阵亡通过立绘 Tween/Tint、伤害治疗数字及 Sprite Sheet 特效反馈。
- 页面只提供正常速度，不显示或预留 `2×` 按钮。
- 达到战斗配置规定的生命阈值或剧情条件时，右上角显示“逃生”；未满足条件时不显示禁用
  占位。
- 所有角色名、技能名、生命数字、伤害/治疗数字和状态层数都由 Cocos Label 与本地化表
  渲染，不得烘焙进 PNG。

### 5.1.1 单位信息顺序

敌方单位从上到下固定为：

```text
静态立绘
名称
族类图标 + 生命条
行动条
状态图标
```

我方修士使用相同顺序。敌我差异通过名称颜色、生命条颜色和自动施法标记表达，不改变
信息位置。

“名称、族类图标 + 生命条、行动条、状态图标”不是立绘外的独立纵向区域，而是全部
覆盖在静态立绘底部。标准单位立绘逻辑框暂定 `86×205`；底部 `56px` 为信息覆盖区，
人物仍可在该区域后方显示，但服装纹样、武器尖端和关键动作剪影不得只依赖这一区域辨认。

标准单位覆盖区自上而下建议按以下尺寸合成；这是素材制作和 Prefab 初始布局基线，后续
可以在 Cocos Creator 中微调位置，不应因此重新生成角色图：

| 信息         | 逻辑高度 | 布局要求                                  |
| ---------- | ---: | ------------------------------------- |
| 名称         | `12` | 水平居中；敌方在暖白描边，我方在青白描边；点击我方名称切换自动施法     |
| 族类图标 + 生命条 | `10` | `12×12` 图标在左，生命条在右；数字由 Label 覆盖在条内或上方 |
| 行动条        |  `5` | 与生命条右侧对齐；填充比例由代码控制                    |
| 状态图标       | `14` | 从左向右排列，超出当前可见数量时显示“+n”Label，不缩小图标     |
| 行间距与安全边    | `15` | 分散到各行之间及底部，避免像素贴边                     |

普通敌群与四人队伍都使用同一套覆盖层组件。首领立绘可以扩大到逻辑 `172×256`，但信息
覆盖层只在立绘底部居中扩展到最多 `112×60`，不能把条形 UI 等比放大到遮住主体。

## 5.2 静态立绘与特效的交付口径

Demo 表现路线冻结为“静态单位立绘 + Sprite Sheet 特效”：

| 内容 | 本阶段方案 | 交付物 | 运行时表现 |
| --- | --- | --- | --- |
| 我方修士 | 复用入山整备四张静态立绘 | 每人一张 RGBA PNG，不新增角色动画包 | 出招缩放/轻位移，受击闪白/位移，治疗 Tint，阵亡变暗/淡出 |
| 普通敌人/首领 | 每单位一张静态立绘 | 每单位一张 RGBA PNG | 与我方使用相同的 Tween/Tint 反馈 |
| 技能与通用反馈 | Sprite Sheet + Cocos `AnimationClip` | 图集、帧数据、FPS、锚点/挂点和事件对齐说明 | 由 `CombatEvent` 触发播放，不反向参与伤害结算 |
| Live2D Cubism | 不采用 | 不制作分层 PSD、`.moc3`、Motion 或运行时接入 | 不进入 0.1 Demo 范围 |

角色静态立绘不需要 `idle`、`skill_01`、`skill_02`、`skill_03`、`hurt`、`death` 六组动作。
技能辨识主要由技能图标、技能名称、静态立绘的轻量代码反馈和对应 Sprite Sheet 特效共同完成。

## 5.5 不需要单独出图的内容

| 内容                  | 实现方式                                  |
| ------------------- | ------------------------------------- |
| 角色名、敌人名、技能名、生命数字    | Ark Pixel/Cocos Label + 本地化表          |
| 伤害数字、治疗数字、状态层数和剩余时间 | Label、对象池和 Tween；伤害与治疗用符号/颜色双重区分      |
| 生命与行动填充比例           | Sprite Mask、Fill Range 或裁切，不生成每档百分比图片 |
| 技能冷却遮罩与倒计时          | Cocos 灰度/扇形遮罩 + Label                 |
| 技能按钮按下、禁用           | `100ms` 缩放、Tint、透明度；有效触控区至少 `48×48dp` |
| 普通敌群、三角阵、环绕阵        | 布局配置，不制作阵型背景图                         |
| 受击闪白、轻微位移、屏幕震动      | Cocos Tween/材质，不烘焙进特效图                |
| 信息覆盖层中的文字描边         | Label Outline/Shadow，不生成带字名称牌         |

## 5.6 GPT Image 共用提示词与生成规则

每条具体提示词都应包含以下字段，避免只写一句风格描述：

```text
Use case：用于《昆吾禁地》375×817竖屏战斗页面的正式可切图美术资产。
Asset type：2D pixel art，按具体条目说明是背景、静态战斗立绘、UI组件、图标或VFX关键帧。
Primary request：严格执行该条目的主体、逻辑显示尺寸、最终PNG尺寸与文件名。
Style/medium：中国修仙像素美术，清晰像素簇，硬边缘，无抗锯齿，Nearest缩放；与营地现有深木、黑玉、旧青铜、黛青暖褐色盘一致。
```

## 5.14 推荐制作顺序

1. 先搭 Combat 灰盒，导出单敌、敌群、技能就绪和单位覆盖层四张 `375×817` 截图。
2. 直接复用四张入山静态立绘，在 `86×205` 单位槽中检查裁切、并排间距和底部 `56px`
   信息遮挡；只有裁切无法满足可读性时才制作同身份静态替换图。
3. 制作残禁石傀单张静态立绘，不生成敌人动作组。
4. 生成并接入背景，确认敌我静态立绘区域的明暗对比。
5. 完成生命条、行动条、族类图标和状态图标，在 `86×205` 单位槽内检查实际可读性。
6. 先制作十二个炼气技能 ID 对应的十二张图标，各取一个角色完成三图小组，确认同角色
   三个技能能靠剪影区分；再按 §5.10.3 处理八个筑基分支的二十四个技能 ID（其中 16 个
   新增、8 个复用），并将全部三十六个技能 ID 映射后的二十八张 PNG 放入对照板检查。
7. 制作十二套技能 Sprite Sheet，并按结算事件定义对齐 `cast_commit/hit_frame`，再制作
   行动就绪、通用受击、治疗和阵亡 Sprite Sheet。
8. 最后制作自动施法与逃生入口，并检查不满足逃生条件时页面不存在空按钮。
