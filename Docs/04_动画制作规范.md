# 《昆吾禁地》动画制作规范

版本：0.3  
形式：探索俯视像素动画 + 战斗动态立绘像素动画 + UI/场景轻动画

## 1. 动画目标

动画优先服务：

1. 战斗时机：何时出手、何时命中、何时可被打断。
2. 职业辨识：金刚禅修、五行法修、玄箓修、剑修四个初始职业有各自动作语言，筑基后进一步
   区分八条分支的防护、输出、控制或辅助职责。
3. 状态表达：受伤、控制、中毒、濒死、复活。
4. 氛围：营地有生活感，禁地有沉寂与不稳定。

不追求高帧数堆量，而追求关键 Pose、清楚预备动作和有重量的命中帧。

## 2. 动画形式选择

| 场景 | 方案 | 原因 |
|---|---|---|
| 方格探索 | 四方向 Sprite Sheet | 低成本、像素一致、易换装 |
| 半自动战斗 | 单方向动态立绘 Sprite Sheet | 技能可读、人物信息叠压在立绘底部、资产量可控 |
| 大型 Boss | 分层骨骼 + 局部序列帧 | 方便阶段变形和部件破坏 |
| 营地 | 局部循环帧 + Tween | 建筑烟火、旗帜、NPC |
| UI | Tween/AnimationPlayer | 响应快、无需大图 |
| 剧情 | 角色立绘切换 + 镜头推拉 | 避免制作大量演出动画 |

0.1 Demo不引入Spine付费工作流。1.0四个Boss若帧动画产能不足，再评估Spine、DragonBones或Cocos骨骼动画组件。

## 3. 帧率与帧数基线

### 3.1 探索角色

| 动作 | 方向 | 帧数 | 播放速度 |
|---|---:|---:|---:|
| Idle | 4 | 4 | 6 FPS |
| Walk | 4 | 6 | 10 FPS |
| Interact | 4 或复用 | 4 | 8 FPS |
| Alert | 1 | 4 | 8 FPS |
| Hurt | 1 | 3 | 12 FPS |
| Down | 1 | 6 | 8 FPS |

逐格移动总时长建议 0.16–0.22 秒，脚步动画与坐标插值同步。

### 3.2 战斗角色

标准单位使用 `86×205` 逻辑框；运行时动画帧按 `86×205 px (@1x)` 像素清稿并由 Cocos
按逻辑尺寸显示。`258×615 px (@3x)` 只用于 GPT Image 角色母版、静态卡面复用与人工
清稿输入，不把每个动画帧都以 `@3x` 打入 Web 图集。首领逻辑框最大 `172×256`，按部件
或动作拆图集。单位底部 `56px` 是名称、族类、生命、行动和状态信息覆盖区，关键动作
剪影不得只落在该区域。

| 动作 | 帧数 | 速度 | 备注 |
|---|---:|---:|---|
| Idle | 4–6 | 6–8 FPS | 呼吸幅度不超过 1–2 px |
| Attack A | 6–8 | 12 FPS | 常规攻击 |
| Attack B | 8–10 | 12 FPS | 强击 |
| Cast | 8–12 | 10–12 FPS | 明确蓄力帧 |
| Hurt | 3–4 | 12 FPS | 不打断所有技能时用色闪替代 |
| Block | 4 | 10 FPS | 保持防御 Pose |
| Death | 8–12 | 8–10 FPS | 魂火逸散交给特效 |
| Revive | 6–8 | 8 FPS | 可反播部分 Death，但末帧重制 |

Boss 动作可增加到 12–18 帧，但单个普通技能演出不超过 1.2 秒。

## 4. 职业与筑基分支动作语言

每个职业阶段固定三个技能。动画资源按“炼气职业公共动作 + 筑基分支差异动作 + 技能特效”
组合，避免四个初始职业与八个筑基分支全部从零制作。

### 金刚禅修

- 初始：赤足宽站、徒手结印，掌击强调肉身重量；金刚怒目用正面定身 Pose 和胸前掌印表现
  嘲讽，不使用盾牌或西式重甲。
- 护法金身：重心稳定、受击位移小；狮吼震心强调胸腔发力，镇狱掌印短促下压，金轮反照
  必须从受击动作自然衔接反震。
- 魔相力士：动作前倾、贴身爆发；魔纹开体增加呼吸与肌肉脉动，三相轰杀只用短暂臂影，
  筑基阶段不出现完整三相法身。

### 五行法修

- 初始：法盘、法镜悬浮，手势以牵引五行和归元收拢为主；不使用法杖。
- 雷法术式：起手短、命中突然，雷链需要以手势或法盘转向清楚表达多目标跳跃与群体减速。
- 蜃景幻法：动作舒展而内收，镜花惑心使用镜面错位，蜃雾蚀神用持续引雾动作，夺念还元
  以从目标回吸自身结束。

### 玄箓修

- 初始：手势短而精确，朱砂符匣、法印和符纸长带负责大幅次级运动；恢复使用经脉符纹，
  不使用圣光、祈祷或药师动作。
- 镇幽符脉：镇幽符宝为单点掷符，诛邪符阵以地面镇纹展开，安魂回元箓以群体符纹回流收势。
- 万象符脉：破灵符矢保持单体直射；六甲增元箓只连接一个恢复目标；力士符傀必须表现
  “符纸折叠成傀—临时生命外壳闭合—傀儡引敌”三个阶段。

### 剑修

- 初始：以剑匣和神识御使飞剑，飞剑点星、剑光分化、养剑诀分别使用单点、分光和回匣蓄养
  动作，人物不直接持剑挥砍。
- 青冥剑修：全程剑不入手，重心轻、起手短；分光追影用连续飞剑残影，剑煞归流表现剑光
  回旋与蚀痕汇聚。
- 玄岳剑修：改为双手持重剑，重心低且收招慢；玄岳破甲强调单点停顿，剑脊震岳为低伤震击，
  横剑断山用势大力沉的大幅群体横斩。

### 4.1 三技能动画复用规则

- 同一职业节点的三个技能必须至少拥有不同起手剪影。
- 同一初始职业的两个转职分支可共享 Idle、Hurt、Death，但 Attack/Cast 至少重制 2 组。
- 技能变化不能只靠换特效；青冥飞剑与玄岳重剑必须在人物是否持剑、重心和收招速度上直接可辨。
- 结丹沿用筑基分支的骨架与基础帧，只增加名阶强化后的关键 Pose 和特效层，不重做第二套三技能动画。

## 5. 动画状态机

### 5.1 探索

```text
Idle
├─ Move → Walk → Idle
├─ Interact → Idle
├─ Alert → Encounter
└─ Down
```

### 5.2 战斗

```text
Idle
├─ Attack/Cast → Recover → Idle
├─ Block → Idle
├─ Hurt → Idle
├─ Disabled → Idle
└─ Death → Dead
Dead → Revive → Idle
```

战斗模拟拥有状态真值，Cocos Animation 状态机只负责表现。动画结束事件不能决定技能是否造成伤害。

## 6. 事件标记

每个攻击动画至少标记：

- `windup_start`
- `cast_commit`
- `projectile_spawn` 或 `hit_frame`
- `recover_start`
- `animation_end`

其中伤害由战斗模拟在 `cast_commit` 后安排；表现事件对齐 `hit_frame`。战斗页面只提供
正常速度；即使动画因卡顿、跳帧或降级播放缩短，结算顺序也不得改变。

## 7. Aseprite 制作规范

### 7.1 图层

```text
guide
body_base
clothes
hair_headgear
weapon_back
weapon_front
fx_reference
shadow
```

- `guide` 和 `fx_reference` 不导出。
- 角色脚底锚点在所有帧保持一致。
- 阴影独立，探索与战斗可以在引擎里统一生成。
- 标签命名：`idle_s`、`walk_n`、`attack_01`。

### 7.2 导出

- PNG RGBA。
- 无边距紧密图集或固定网格二选一；同一动画集不得混用。
- Sprite Sheet 必须带 JSON 帧信息或在文档中注明格子尺寸。
- 禁止导出缩放过的抗锯齿版本。

## 8. Cocos Creator 导入

### 8.1 普通 Sprite Sheet

- Texture Filter 使用 Point。
- Mipmaps 关闭。
- Wrap Mode 使用 Clamp。
- 像素资源使用无损或高质量压缩，逐浏览器检查色偏。
- 将图集切为 SpriteFrame，并用 `AnimationClip` 建立序列帧。
- 动画资源按角色集保存，不在运行时代码里逐帧临时创建。

### 8.2 Animation 与骨骼

适用于：

- 大型 Boss 分层骨骼。
- 带多个装备挂点或转职覆盖层的战斗角色。
- 需要混合或多轨道控制的动画。

标准动态立绘优先 SpriteFrame `AnimationClip`，避免复杂度。

## 9. 换装与挂点

Demo 只实现武器和背部法宝挂点：

- `hand_main`
- `hand_off`
- `back`
- `head_fx`
- `body_fx`
- `foot_fx`

1.0再增加衣服分层换装。像素角色如果每帧挂点抖动，可为动画帧保存挂点表：

```json
{
  "attack_01": [
    {"hand_main": [18, 22]},
    {"hand_main": [20, 20]}
  ]
}
```

## 10. 动画资源采购与现有素材

本地已收集的免费资源：

| 素材 | 可用动作 | Demo 角色 |
|---|---|---|
| `SamuraiTopdown_CC0` | 移动、剑斩、死亡 | 剑修探索 |
| `SamuraiSideview_CC0` | Idle、Run、Attack、Hurt、Dead | 战斗节奏参考 |
| `Monk_CC0` | Idle、Attack、Fly、Read、Transition | 金刚禅修、五行法修、玄箓修的节奏参考 |
| `AnimatedMonsters_CC0` | Idle、Walk、Attack、Hurt、Dead | 尸傀、残魂 |

路径与许可见 `ThirdParty/DemoAssets/README.md`。

Demo 改造最低要求：

- 武士头盔改为发髻/玉冠。
- 甲胄改为道袍与护肩。
- 刀改为飞剑、阵旗或法器。
- 去除剖腹、断肢等不需要的血腥帧。
- 增加储物袋、剑匣、药篓等轮廓。
- 统一到项目色盘。
- 使用同一身体底层快速制作剑修、青冥剑修和玄岳剑修，优先验证“筑基后三技能表现发生变化”，
  同时确保青冥剑不入手、玄岳双手持剑。

1.0替换原则：

- 不能只在免费素材上简单换色。
- 新角色从剪影和关键 Pose 开始原创。
- 可保留动作时长作为参考，但不得逐帧描摹来源动画。

## 11. 场景动画

### 营地循环

- 旗帜：8 帧，8 FPS。
- 炉火：6 帧，10 FPS，随机起始帧。
- 炊烟：粒子而非大序列帧。
- 杂役：短距离巡逻 + 3 种停留动作。
- 建筑升级：局部脚手架消失、屋檐/灯火逐级增加。

### 禁地

- 石门：分三段开启，0.8–1.2 秒。
- 法阵：符文逐点亮，循环 1.5–3 秒。
- 宝箱：锁断、盖开、光溢出。
- 机关：动作必须早于伤害。
- 传送：角色先溶解，再触发场景切换。

## 12. 剧情演出

1.0使用轻量演出模板：

1. 背景立绘或像素场景。
2. 角色半身剪影/头像。
3. 镜头平移、推近、轻震。
4. 关键物件特写。
5. 少量表情替换。

不制作长篇逐帧动画。单段不可跳过时间不超过 3 秒，完整对话可快进、可回看。

## 13. 动画性能

- 同屏非战斗环境动画不超过 25 个。
- 离屏 Sprite 动画组件暂停。
- UI 不可见时停止 Tween。
- 大 Boss 分层不超过 12 个 Sprite。
- 动画贴图按章节加载，返回营地时释放。
- 角色图集单张优先控制在 2048×2048 内。
- Web 首发按职业和地图拆分图集，不把四个初始职业与八个筑基分支全部打进首屏加载包。

## 14. 动画交付清单

每套动画需要：

- `.aseprite` 或等价源文件。
- Sprite Sheet PNG。
- 帧数据 JSON。
- 动画列表和 FPS。
- 命中/发射事件帧。
- 锚点与挂点表。
- 10 秒预览 GIF/MP4。
- 许可与作者信息。

## 15. 验收标准

- 探索角色四方向脚底不滑。
- 同职业动作语言一致。
- 转职后仍能认出父职业，但三个技能动作与另一个分支明显不同。
- 普攻从起手到命中不超过 0.45 秒。
- 治疗、护盾、控制的前摇清楚。
- 动画跳帧、打断或降级播放时不漏技能事件。
- 角色死亡后没有继续播放 Idle。
- 低端机同时 10 个单位动画仍保持目标帧率。
