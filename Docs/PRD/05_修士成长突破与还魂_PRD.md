## 页面 09：修士名册、详情、升级与技能策略

页面 ID：`roster`  
需求前缀：`V10-ROSTER`  
状态：固定四人范围已冻结；数值读取配置

### 1. 上游与边界

成长与七维读取 [成长分册](../1.0策划案/数值/16_1.0成长经济与战斗数值_草案.md)，技能读取
[职业技能分册](../1.0策划案/数值/17_1.0职业技能数值_草案.md)。本页只管理石岩、陆清、白灵、墨言，
不提供招募、改名、遣散、容量或随机资质生成。

### 2. 入口与信息架构

- 从营地底部 HUD、整备页修士卡或战斗失败建议进入；返回恢复来源页和所选修士。
- 一级为四人名册；二级详情标签为 `概览`、`七维`、`技能策略`、`装备`、`成长记录`。
- 名册卡显示头像、等级/境界、当前职业、生命、灵息、战力、阵亡/可突破/可升级状态。
- 详情必须区分裸装七维、装备增量、状态增量和最终值，战力只作展示。
- 每名修士灵息上限 `100`，只在营地每 `5` 分钟恢复 `1` 点；独立保留不足 5 分钟的余数。
- 主线每章完成时免费将四人灵息回满；不提供道具、付费或超上限恢复。

### 3. 页面状态

| 状态 | 要求 |
|---|---|
| 默认 | 固定四人按剧情顺序显示，不出现“容量” |
| 可升级 | 显示下一等级变化、魂晶成本和确认入口 |
| 达到境界门槛 | 升级禁用并链接 PRD 10 突破页 |
| Lv30 | 显示 1.0 等级上限，不出现 Lv31 预览 |
| 阵亡 | 主操作改为“前往还魂殿”，升级/策略修改按规则禁用 |
| 灵息恢复中 | 显示剩余时间与恢复规则，不提供付费加速 |
| 数据缺失 | 对应数值区显示错误，资源操作禁用 |
| 保存错误 | 恢复升级前状态并保留当前标签 |

### 4. 升级

- 升级只消耗魂晶；灵石不用于普通等级提升。
- 确认页显示当前/目标等级、七维变化、生命变化、魂晶成本和是否触发突破门槛。
- 成本、成长与上限读取已冻结成长配置；配置缺失时禁用升级，不以 0 或临时常量执行。
- `LevelUpCultivator(cultivatorId)` 原子扣除魂晶、写入成长段、更新等级/七维/生命并保存。
- 连续升级必须逐级结算并在每级重新校验，不允许一次越过待突破等级。

| 目标等级 | 单人累计魂晶 | 说明 |
|---:|---:|---|
| Lv10 | 470 | 炼气上限，待筑基 |
| Lv20 | 3130 | 筑基上限，待结丹 |
| Lv21 | 3650 | 含 Lv20→21 的 520 魂晶，不含结丹物料 |
| Lv24 | 5670 | 1.0 推荐通关节点 |
| Lv30 | 12805 | 1.0 等级上限 |

下一级确认页继续逐级读取成长分册§2.2的完整表，不把上述累计节点当作跨级扣款。
固定四人全部到达 Lv24 共需魂晶 `22680`；1.0 十小时主支线与固定探索总投放基线 `25150`，容错余量 `2470`。
页面不向玩家显示“十小时预算”，但该总量是主线无资源本通关的跨系统验收基线。

### 5. 七维与成长记录

七维内部键固定：

```text
strength magic technique speed constitution armor resistance
```

- 灵根倍率、炼气成长、筑基/结丹路线成长、一次性突破属性和装备逐层展示来源。
- `careerHistory` 或等价累计成长记录是权威来源；普通登录、换装或刷新不得重算历史成长。
- 页面可展示计算说明，但不得从当前职业反推 Lv1 至当前等级。

### 6. 技能策略

- 当前职业阶段始终恰好三个主动技能；显示稳定技能 ID 对应名称、目标、冷却、效果和自动条件。
- 每个技能可设置自动开关及上游允许的目标/阈值策略；非法组合立即显示原因。
- 保存前提供变更摘要；保存成功后用于后续战斗，不追改进行中的 CombatSnapshot。
- 结丹只显示同三个技能的“精通”数值，不额外出现可自由混装的旧技能池。

### 7. 装备入口

- 四槽固定为武器、防具、饰品一、饰品二。
- 点击槽位进入 PRD 11 的兼容装备列表，返回后刷新人物详情。
- 已出征快照中的修士不可从营地远程换装；页面显示原因。
- 装备比较显示器纹、固定属性和总七维变化，不显示装备等级。

### 8. 命令与恢复

- `LevelUpCultivator(cultivatorId)`
- `UpdateSkillStrategy(cultivatorId, strategy)`
- `OpenCompatibleEquipment(cultivatorId, slotId)`

升级和策略保存均防重复提交。刷新后读取权威修士状态；不得保留已扣魂晶但未增加等级的中间态。

### 9. Figma 必需稿件

- 四人名册：默认、可升级、可突破、阵亡、灵息恢复、Lv30。
- 详情：概览、七维来源展开、成长记录长列表、四槽装备。
- 升级确认：可执行、魂晶不足、突破阻断、提交中、失败。
- 技能策略：默认、修改未保存、非法组合、保存中、进行中战斗不追改提示。
- 所有数值支持长文本和正负增量，不只用颜色区分。
- 升级确认需要覆盖 Lv9→10、突破阻断、Lv20→21 和 Lv29→30，确认单级成本与累计节点不混用。

### 10. 美术素材

引用 [通用图像槽](../ArtAssets/06_通用方形图像槽.md)、
[灵根资质框](../ArtAssets/07_通用事件标记选项按钮与战利品图标.md) 和
[修士名册、突破与技能策略素材](../ArtAssets/11_修士名册突破与技能策略.md)。需要四人头像/半身像、
四职业与八分支徽记、七维图标、三技能状态、境界和阵亡标记。

### 11. 验收

- `V10-ROSTER-001`：名册始终只有固定四人，不出现容量、改名、遣散或随机资质入口。
- `V10-ROSTER-002`：普通升级只扣魂晶，连点、失败和刷新不跳级或重复扣款。
- `V10-ROSTER-003`：七维来源可追溯，换装和刷新不重算历史成长。
- `V10-ROSTER-004`：每人恰好三个当前主动技能，策略只影响后续战斗。
- `V10-ROSTER-005`：四槽换装兼容性正确，任何页面都不显示装备等级。
- `V10-ROSTER-006`：四人 Lv24 需求 22680 魂晶，首轮总投放 25150、余量 2470；不挑战资源本仍可达成。

### 12. 不做

随机修士、姓名编辑、遣散、馆级上限、技能自由拼装、重置灵根、自动升级和付费加速灵息。

## 页面 10：筑基、结丹与专精重置

页面 ID：`breakthrough`  
需求前缀：`V10-BREAK`  
状态：流程冻结；成本和成长数值读取上游/配置

### 1. 上游与边界

突破条件、分支、成长重建和专精重置读取
[成长分册](../1.0策划案/数值/16_1.0成长经济与战斗数值_草案.md)，技能差异读取
[职业技能分册](../1.0策划案/数值/17_1.0职业技能数值_草案.md)，降尘丹来源读取
[炼器坊策划](../1.0策划案/数值/33_炼器坊升级与炼制机制_草案.md)。

### 2. 入口与页面结构

- 从修士详情“突破/专精重置”进入，返回保持所选修士。
- 页面上部显示当前等级、境界、职业路线和条件清单。
- 筑基显示同一初始职业的两个分支对照；结丹只显示已选路线的线性晋升。
- 底部显示消耗、突破后的成长/技能变化、确认动作和不可逆/可重置说明。

### 3. 状态

| 状态 | 要求 |
|---|---|
| 条件未满足 | 逐项显示等级、任务/试炼、在营地、存活、材料条件 |
| 筑基可选 | 两分支并列，默认不替玩家预选 |
| 筑基已完成 | 显示当前分支和专精重置入口 |
| 结丹可执行 | 显示对应称号、精通变化、降尘丹和灵石 |
| 材料不足 | 链接炼器坊或合法来源，不提供购买捷径 |
| 阵亡/出征中 | 操作禁用，说明还魂/归营要求 |
| 提交中 | 全页锁定，防止重复选择 |
| 保存失败 | 所有资源、境界、等级、技能和成长回滚 |
| 数值缺失 | 禁止确认，显示配置项错误 |

### 4. 筑基流程

1. 条件均满足后，玩家比较两条分支的职责、成长、三个技能、形象差异和剧情背景。
2. 选择分支后显示完整二次确认；不得用“推荐”替代玩家选择。
3. `BreakthroughFoundation` 原子处理灵石、分支、境界、等级跨越、成长段和技能。
4. 突破固定成功，不存在概率、失败惩罚或额外丹药。

每人筑基固定消耗灵石 `300`，不消耗魂晶、丹药或职业信物。突破完成后在同一事务中另支付
Lv10→11 的魂晶 `130`；确认页必须将两笔消耗分栏显示。四阵眼首次完成时固定发放灵石 `1200`，
保证固定四人首次筑基。

### 5. 结丹流程

- 只沿已选筑基分支晋升，不再二次分叉。
- 必须满足上游定义的等级、主线、个人试炼、在营地、存活及材料条件。
- 降尘丹是必要突破物，不是成功率加成；突破固定成功。
- 确认页同时显示灵石、降尘丹、结丹称号、一次性属性和三个技能的精通变化。
- `BreakthroughCoreFormation` 的扣除、境界/等级、成长、技能精通和保存同成同败。
- 每人结丹基础消耗灵石 `1200`＋降尘丹 `1`；完成“借阵结丹”后实际灵石为 `900`，降尘丹不变。
- 突破完成后同一事务另支付 Lv20→21 的魂晶 `520`，不得把魂晶合并成灵石或丹药价格。
- 降尘丹的冻结配方为凝丹灵草 `1`＋灵晶 `15` → 1；地图 3 主线保底四人所需灵石 `4800`、凝丹灵草 `4`、灵晶 `60`。

### 6. 高成本专精重置

- 仅已筑基、在营地、存活且不在战斗/任务锁定状态的修士可执行。
- 只消耗灵石：筑基修士每次 `3000`，结丹修士每次 `9000`；不随次数、日期或当前余额变化。
- 不新增洗点道具、冷却或现实时间等待。
- 保留灵根、等级、境界、累计魂晶、装备、剧情选择、突破和试炼记录。
- 把筑基以来成长段、结丹称号/一次性属性和三个技能整体替换为另一分支。
- 按稳定基础与目标路线确定性重建裸装七维；这是唯一允许主动重建成长的入口。
- 当前生命按重置前比例折算，存活者最低保留 1 点，不借重置免费回满。
- 确认页必须并列展示前后职业、技能、七维、生命和灵石成本。

### 7. 命令与原子性

- `BreakthroughFoundation(cultivatorId, branchId)`
- `BreakthroughCoreFormation(cultivatorId)`
- `ResetSpecialization(cultivatorId, targetBranchId)`

三类命令均带操作 ID。任何步骤失败全部回滚；刷新只恢复已提交完成的结果，不能重选随机属性，
因为突破与重置本身不含随机结果。

### 8. Figma 必需稿件

- 条件清单：全部满足、多个未满足、阵亡、出征中、数据缺失。
- 筑基双分支对照：四个初始职业各一组，含长技能说明与二次确认。
- 结丹：八条路线结果态、降尘丹不足、灵石不足、成功表现。
- 专精重置：前后对照、比例生命提示、材料不足、提交中、失败回滚。
- 不可逆说明与重置说明不能只依赖 Tooltip。

### 9. 美术素材

引用 [修士名册、突破与技能策略素材](../ArtAssets/11_修士名册突破与技能策略.md) 和
[炼器坊素材](../ArtAssets/13_炼器坊铁胚器纹与永久强化.md)。需要四初始职业、八筑基/结丹路线徽记、
突破光效、降尘丹、条件状态和前后对照装饰；数值与技能正文使用 Label。

### 10. 验收

- `V10-BREAK-001`：筑基两分支信息完整，未明确确认前不写入选择。
- `V10-BREAK-002`：筑基 `300 灵石＋130 魂晶`，结丹 `1200/900 灵石＋1 降尘丹＋520 魂晶`；条件/资源不足不会部分扣除。
- `V10-BREAK-003`：结丹只沿筑基路线推进，技能 ID 与精通规则一致。
- `V10-BREAK-004`：专精重置按筑基 `3000`/结丹 `9000` 灵石扣费并确定性替换成长/技能，不保留混合技能池。
- `V10-BREAK-005`：重置不回满生命，失败和刷新不重复扣费或破坏职业历史。

### 11. 不做

突破概率、装备保护符、随机悟道、第二次结丹分支、洗灵根、自由技能池和元婴以上可玩突破。

## 页面 14：还魂殿

页面 ID：`revive_hall`  
需求前缀：`V10-REVIVE`  
状态：功能规则与还魂成本已冻结

### 1. 上游与边界

阵亡与还魂规则读取 [1.0 总案](../1.0策划案/15_1.0版本完整策划案_草案.md)，魂晶用途读取
[基础材料与资源循环](../1.0策划案/数值/34_1.0基础材料与资源循环_草案.md)。还魂固定成功且只消耗魂晶，
不附加降级、资质损失、装备损坏、限时保留或其他惩罚。

### 2. 入口与页面结构

- 点击还魂殿建筑进入；修士名册、整备阻断和失败报告可直接定位到阵亡修士。
- 无阵亡修士时显示建筑说明和空状态，可正常返回大厅。
- 阵亡列表只可能出现固定四人，显示等级、境界、职业、装备保留状态和魂晶成本。
- 详情页显示还魂后保留项、当前魂晶、成本和固定成功说明。

### 3. 页面状态

| 状态 | 要求 |
|---|---|
| 无阵亡 | 明确“当前无人待还魂”，不显示可点击空卡 |
| 单人/多人阵亡 | 每人独立选择，已选择项显示总成本 |
| 魂晶不足 | 确认禁用，链接合法魂晶来源，不提供付费入口 |
| 最终防卡死 | 无任何存活可出征修士且魂晶不足时，显示免费还魂一人 |
| 出征结算未完成 | 只读等待结算，不能提前还魂绕过损失 |
| 数值缺失 | 对应修士操作禁用，显示配置错误 |
| 提交中 | 锁定所选修士和确认按钮 |
| 保存失败 | 修士保持阵亡、魂晶不扣，允许重试 |
| 成功 | 显示恢复状态并从待处理列表移除 |

### 4. 还魂流程

1. 玩家选择一名或多名阵亡修士，查看逐人及总魂晶成本。
2. 确认页再次说明：固定成功；保留等级、境界、职业、技能、装备与全部成长。
3. `ReviveCultivators(cultivatorIds)` 重新校验阵亡状态和魂晶。
4. 原子扣魂晶、恢复存活/生命状态、重置营地恢复锚点并保存。
5. 成功后刷新名册、整备可用性和建筑事件标记。

还魂费用按当前境界和等级计算，并向上取整到 5 的倍数：

```text
炼气：20 + 8 × 当前等级
筑基：100 + 15 × (当前等级 - 10)
结丹：300 + 25 × (当前等级 - 20)
```

Lv10/20/24/30 分别为 `100/250/400/550` 魂晶。预览和实际扣款必须读取同一结果。
若名册中没有任何可出征的存活修士且魂晶不足，必须提供一次“免费还魂一名固定修士”的最终防卡死操作。
该操作使用 `EmergencyReviveCultivator(cultivatorId)`，提交时重新校验“无存活可出征修士＋魂晶不足”，
只恢复选定一人；完成后条件立即失效，不能连点免费恢复其余阵亡修士。

### 5. 原子性与恢复

- 批量还魂要么所选全成功，要么全部回滚；若产品改为逐人执行，必须在 UI 中逐笔明确，不得半成功却显示总成功。
- 重复操作 ID 返回第一次结果，不重复扣魂晶。
- 在成功保存后切页前刷新，修士保持已还魂；不得再次进入待处理列表。
- 修士从不因阵亡或还魂从名册删除，装备实例不移动、不损坏。
