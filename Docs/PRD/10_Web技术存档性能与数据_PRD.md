- Bundle之间不互相引用业务脚本。

## 4. 存档

IndexedDB：

```text
kunwu_game
├─ profiles
├─ backups
├─ settings
└─ telemetry_local
```

存档包含：

- Schema版本。
- 游戏版本。
- UTC时间。
- 校验值。
- Payload。

写入：

1. 序列化和校验。
2. 旧主档进入backups。
3. 同一transaction写入新档。
4. 失败保留旧档。

当前工程存档基线为 Schema v8；v5 是灵根资质与境界字段迁移的历史节点，不是 1.0 的
目标版本。1.0 新增任务、职业历史、装备实例、商店保底和结局记录前，必须在技术设计中
冻结新的 Schema 版本，并以追加迁移的方式承接 v0–v8，不能改写既有迁移。

其中 v5 已冻结的修士数据规则继续保持：

- 灵根资质只保存 PRD-03 定义的六种 `spiritualRootId`。
- 修炼境界保存稳定 `realmId`；1.0 只允许炼气、筑基、结丹并开放至 `Lv30`。Schema 可以
  保留更高境界 ID，但 1.0 不能生成、进入或显示元婴以上状态。
- 旧七档资质兼容值与旧境界数据由历史 v5 迁移完成转换；迁移成功后不再写回旧字段。
- 战力由最终七维实时派生，不写入存档；读取旧档时也不得以历史战力缓存覆盖领域层计算结果。
- 三支队伍分别保存队伍成员和装载方案。
- 修士实例保存固定/随机来源、形象属性模板、最终Lv1随机七维、累计升级魂晶、历次突破实际
  道具成本和免费改名使用状态；随机结果一经招募不得按新配置重抽。
- 招贤馆保存馆级、当前名册容量来源、当前候选批次ID/种子、3个候选结果、已招募槽位、
  当前自然小时序号、付费刷新序号与`nextFreeRefreshAtUtc`。只保存当前批次，不保存可找回的历史批次。
- 0.1 Demo存档首次迁入1.0时，根据现有修士最高等级补足到能够容纳该等级的最低馆级；迁移不
  降低等级、不重算七维、不生成候选奖励，也不修改历史迁移文件。

招贤馆自然批次以UTC自然小时为稳定边界，UI转换为本地倒计时显示。进入招贤馆或恢复前台时，
若当前小时晚于存档小时，则只生成当前小时的3名候选；跨过多个小时也不生成、排队或发放历史批次。
设备时间回拨不得恢复已失效候选，系统保留已见过的最大自然小时并显示时间异常提示。

### 4.1 进行中入山快照

存档最多包含一个有效的 `ExpeditionState`，表示当前正在进行的一次入山或资源副本挑战。它至少包含
模式、地图/副本/难度 ID、队伍方案 ID、出发成员 ID、格子坐标、已结算灵息、剩余装载物、临时战利品、已揭示格子和
生命周期状态。

- 该快照只在最终校验通过后创建，并在地图交接成功后生效；它是刷新恢复和防止营地/野外
  物资重复的事实源。
- 正常回城或全队阵亡结算完成后清除快照。
- 地图加载失败不得留下有效快照，也不得扣除灵息、灵粮或库存物品。
- 启程时停止出发修士的灵息恢复；回城时以当前 UTC 重建恢复锚点，野外时长不补算。
- 资源副本另保存发现状态、各难度首清、快捷入口和最近挑战设置；不保存或补算按现实时间增长的收益。

### 4.2 操作原子性与保存失败

- 解锁队伍必须原子完成灵石扣除与解锁保存；任一步失败都同时回滚扣款和解锁。
- 启程必须原子完成最终校验、资源转移、灵息结算、地图交接和有效入山快照建立；地图加载
  失败时玩家状态保持启程前不变。
- 普通编队和装载修改保存失败时保留内存中的最新编辑状态，明确提示尚未保存并提供重试；
  不得静默丢弃修改或显示保存成功。
- 自然换批、付费刷新、招募、后续改名、馆级升级和遣散均使用单一事务。付费刷新只替换当前
  批次并增加付费序号，不更新`nextFreeRefreshAtUtc`；事务失败保留原候选和余额。
- 招募事务再次校验批次、槽位、容量和余额，原子扣费并创建随机修士实例。确认期间跨整点时
  先使旧候选失效，招募失败且不扣费。
- 遣散事务先验证装备可退回与所有占用可清理，再一次性退装、返突破道具、返80%累计升级魂晶、
  清理引用并删除实例；任一步失败完整回滚。
- 资源副本结算以`dungeon_id + difficulty_id + challenge_run_id`作为幂等边界；首次奖励、重复奖励、
  首清状态和快捷入口必须在同一事务写入，失败时不发部分奖励。

## 6. 数据驱动

数据源：

- CSV：扁平数值。
- JSON：职业树、任务、地图、事件。

构建前校验：

- ID唯一。
- 引用存在。
- 每职业恰好三个技能。
- 地图对象坐标合法。
- 出口目标存在。
- 掉落权重合法。
- 文本Key存在。
- 每职业恰有3个形象属性模板，模板和灵根使用独立权重表。
- 每馆级模板权重、灵根权重分别归一；杂灵根概率始终高于90%，异灵根始终低于0.5%。
- 1.0招贤馆只配置1–9级，等级上限、境界权限和容量与PRD-02一致；不得存在可调用的10–24级升级配置。
- 1.0必须且只能配置`rd_map03_refire_mine`、`rd_map04_soul_echo`两座可重复资源副本；难度、遭遇、
  奖励、解锁和快捷入口引用均可解析，且重复奖励不含主线唯一物。

## 8. 错误处理

- Bundle失败：重试、返回大厅、显示错误码。
- IndexedDB失败：保留内存状态并提示导出。
- 队伍解锁失败：回滚灵石与解锁状态；普通编队/装载保存失败：保留内存状态并提示重试。
- 地图加载失败：返回入山整备，不扣除灵息或物资，不建立有效 `ExpeditionState`。
- WebGL上下文丢失：暂停并尝试恢复。
- 浏览器后台：暂停表现，恢复后按各系统规则补算；有效入山期间不得补算修士灵息。
- 数据Schema失败：阻止进入游戏，显示版本。
- 弱网：不影响已加载地图，禁止切图时明确提示。

## 11. 验收

- 连续刷新20次不坏档。
- 20个历史存档可迁移。
- Bundle不进入错误的首屏包。
- 浏览器后台30分钟恢复正确。
- 清理网站数据后可通过导入恢复。
- 四张可玩地图连续切换没有持续内存增长；`map_05`锁定入口不会加载可玩地图资源。
- 两座资源副本连续挑战、刷新恢复和返回营地不复制奖励、修士、装备或挑战快照；快速重返不补扣灵息或行路灵粮。
- 断网时已加载内容仍可运行。
- v0–v7 历史存档可沿既有迁移链进入当前 v8；1.0 新 Schema 冻结后，v0–v8 均可继续
  迁移到目标版本。迁移后灵根资质与境界 ID 合法，战力不进入存档。
- 刷新页面可从有效 `ExpeditionState` 恢复，营地与野外不存在重复物资。
- 队伍解锁失败完整回滚；地图加载失败不扣资源；普通编队和装载保存失败可从内存状态重试。
- 离线跨一个或多个整点后只恢复当前小时批次；付费刷新不改变自然整点，时间回拨不找回旧候选。
- 在付费刷新、招募、改名、馆级升级和遣散事务的每个写入点模拟失败，刷新后均只存在完整的
  操作前或操作后状态，不出现重复扣费、重复返还、孤儿装备或半删除修士。
- 0.1存档迁入1.0后馆级自动满足现有最高等级，固定四人的等级、灵根和历史成长不变。
