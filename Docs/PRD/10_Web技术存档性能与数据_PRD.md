## 3. Asset Bundle

```text
start-scene
shared
camp
career_base
career_tier_1
map_01
map_02
map_03
map_04
map_05
```

- 首屏只加载启动和shared最小资源。
- 营地加载后预载map_01。
- 接近有效出口时只预载主线顺序中的下一张地图：`map_01→map_02→map_03→map_04`。
- 0.1 不存在地图 2直达地图 4的隐藏出口。
- `map_05`仅保留稳定 Bundle ID 或锁定入口资源，不包含可进入地图内容；不得预载、创建
  `ExpeditionState`或通过技术配置绕过锁定。
- Bundle使用版本Hash。
- Bundle之间不互相引用业务脚本。

## 4. 存档

IndexedDB：

```text
kunwu_game
├─ profiles
├─ backups
├─ settings
└─ telemetry_local
```

存档包含：

- Schema版本。
- 游戏版本。
- UTC时间。
- 校验值。
- Payload。

写入：

1. 序列化和校验。
2. 旧主档进入backups。
3. 同一transaction写入新档。
4. 失败保留旧档。

当前工程存档基线为 Schema v8；v5 是灵根资质与境界字段迁移的历史节点，不是 0.1 的
目标版本。0.1 新增任务、职业历史、装备实例、商店保底和结局记录前，必须在技术设计中
冻结新的 Schema 版本，并以追加迁移的方式承接 v0–v8，不能改写既有迁移。

其中 v5 已冻结的修士数据规则继续保持：

- 灵根资质只保存 PRD-03 定义的六种 `spiritualRootId`。
- 修炼境界保存稳定 `realmId`；0.1 只允许炼气、筑基、结丹并开放至 `Lv30`。Schema 可以
  保留更高境界 ID，但 0.1 不能生成、进入或显示元婴以上状态。
- 旧七档资质兼容值与旧境界数据由历史 v5 迁移完成转换；迁移成功后不再写回旧字段。
- 战力由最终七维实时派生，不写入存档；读取旧档时也不得以历史战力缓存覆盖领域层计算结果。
- 三支队伍分别保存队伍成员和装载方案。

### 4.1 进行中入山快照

存档最多包含一个有效的 `ExpeditionState`，表示当前正在进行的一次入山。它至少包含地图 ID、
队伍方案 ID、出发成员 ID、格子坐标、已结算灵息、剩余装载物、临时战利品、已揭示格子和
生命周期状态。

- 该快照只在最终校验通过后创建，并在地图交接成功后生效；它是刷新恢复和防止营地/野外
  物资重复的事实源。
- 正常回城或全队阵亡结算完成后清除快照。
- 地图加载失败不得留下有效快照，也不得扣除灵息、灵粮或库存物品。
- 启程时停止出发修士的灵息恢复；回城时以当前 UTC 重建恢复锚点，野外时长不补算。

### 4.2 操作原子性与保存失败

- 解锁队伍必须原子完成灵石扣除与解锁保存；任一步失败都同时回滚扣款和解锁。
- 启程必须原子完成最终校验、资源转移、灵息结算、地图交接和有效入山快照建立；地图加载
  失败时玩家状态保持启程前不变。
- 普通编队和装载修改保存失败时保留内存中的最新编辑状态，明确提示尚未保存并提供重试；
  不得静默丢弃修改或显示保存成功。

## 8. 错误处理

- Bundle失败：重试、返回大厅、显示错误码。
- IndexedDB失败：保留内存状态并提示导出。
- 队伍解锁失败：回滚灵石与解锁状态；普通编队/装载保存失败：保留内存状态并提示重试。
- 地图加载失败：返回入山整备，不扣除灵息或物资，不建立有效 `ExpeditionState`。
- WebGL上下文丢失：暂停并尝试恢复。
- 浏览器后台：暂停表现，恢复后按各系统规则补算；有效入山期间不得补算修士灵息。
- 数据Schema失败：阻止进入游戏，显示版本。
- 弱网：不影响已加载地图，禁止切图时明确提示。

## 11. 验收

- 连续刷新20次不坏档。
- 20个历史存档可迁移。
- Bundle不进入错误的首屏包。
- 浏览器后台30分钟恢复正确。
- 清理网站数据后可通过导入恢复。
- 四张可玩地图连续切换没有持续内存增长；`map_05`锁定入口不会加载可玩地图资源。
- 断网时已加载内容仍可运行。
- v0–v7 历史存档可沿既有迁移链进入当前 v8；0.1 新 Schema 冻结后，v0–v8 均可继续
  迁移到目标版本。迁移后灵根资质与境界 ID 合法，战力不进入存档。
- 刷新页面可从有效 `ExpeditionState` 恢复，营地与野外不存在重复物资。
- 队伍解锁失败完整回滚；地图加载失败不扣资源；普通编队和装载保存失败可从内存状态重试。
