## 页面 04：灵源院生产与储量

页面 ID：`spirit_farm`  
需求前缀：`V10-FARM`  
状态：生产、招募与储量首轮数值已冻结

玩家可见名称统一为“灵源院”。`spirit_farm`、`V10-FARM`以及现有`ling_pu`配置、存档键和资源路径仅作为
兼容内部ID保留，不进入玩家文案，也不因本次改名迁移或复制数据。

### 1. 上游与边界

资源分类和用途读取 [基础材料与资源循环](../1.0策划案/数值/34_1.0基础材料与资源循环_草案.md)，
周期、岗位和储量读取 [营地后勤与野外循环](../1.0策划案/数值/36_营地后勤与野外循环机制_草案.md)，
灵液领取节点读取 [1.0剧情任务详细剧本](../1.0策划案/剧情/20_1.0剧情任务详细剧本_草案.md)，
离线结算结构读取 [技术实现方案](../01_技术实现方案.md)。本页只生产灵粮、灵木、玄铁、灵晶、
庚精；不生产灵石、魂晶、区域稀有材料、铁胚或器纹。

### 2. 入口与信息架构

- 营地点击灵源院进入主面板，关闭后回到原横滑位置。
- 顶部显示杂役总数、已分配/空闲人数、离线结算状态。
- 主列表按策划解锁顺序显示五种生产资源；未解锁行显示条件，不提前显示产量。
- 每行显示库存/上限、当前岗位人数、净产量、增减分配和储量升级入口。
- 底部显示当前生产周期进度、盗天灵液等级、下一阶段剧情条件、最近结算提示、杂役招募与关闭。

### 3. 页面状态

| 状态 | 要求 |
|---|---|
| 默认 | 只显示已解锁资源行和真实当前分配 |
| 首次进入 | 解释“先结算旧配置，再保存新分配” |
| 离线结算 | 一次性列出有效时长、各资源实际入库与溢出 |
| 空闲杂役为零 | 增加按钮禁用并说明无空闲杂役 |
| 资源满仓 | 标记停止入库，不继续累计隐藏产量 |
| 储量满级 | 隐藏升级动作，显示当前 1.0 上限 |
| 灵液未获得／已升级 | 显示当前周期`30/25/20`秒和已领取滴数；未达剧情节点只显示条件，不显示领取按钮 |
| 数值缺失 | 对应行显示“数据未配置”，操作禁用 |
| 时间回拨 | 暂停离线收益并提示重新校时；不倒扣资源 |
| 加载/保存错误 | 保留最后权威分配，允许重试，不显示乐观产量 |

### 4. 核心流程

#### 4.1 调整岗位

1. 点击增减时先以旧配置结算至当前可信时间。
2. 校验空闲杂役、已分配人数和资源是否已解锁。
3. 原子写入新分配与结算锚点，成功后刷新净产量。
4. 连续点击串行执行；不得产生负人数或超过杂役总数。

#### 4.2 离线结算

- 进入营地、打开灵源院、改变岗位和离开游戏前按同一结算器处理。
- 未取得盗天灵液时以`30`秒为一个结算周期；1.0第一、二滴取得后固定改为`25`秒、`20`秒。
  前台、后台和完全离线统一读取当前`time_dew_level`派生周期。
- 不足一周期的进度按岗位保存，不向上取整；不设独立离线上限或离线倍率。
- 单名杂役的周期数值为：

| 岗位 | 每生产周期产出 | 每生产周期灵粮维护 | 开放条件 |
|---|---:|---:|---|
| 灵粮 | 12 | 0 | 初始 |
| 灵木 | 6 | 2 | 初始 |
| 玄铁 | 3 | 2 | 初始 |
| 灵晶 | 1 | 2 | 最高进度到达地图 2 |
| 庚精 | 每 2 周期 1 | 每周期 2 | 最高进度到达地图 3 |

- 灵粮不足时，非灵粮岗位按灵木→玄铁→灵晶→庚精的固定顺序结算；无法完整支付当周期维护的岗位暂停且不扣粮。
- 到达储量上限的部分不进入库存；结算页明确显示溢出量。
- 同一结算锚点重复打开或刷新只返回已保存结果，不再次发放。

#### 4.3 杂役招募与储量升级

- 新档初始有 `6` 名杂役，1.0 上限 `12` 名；第 7–12 名的单次招募成本依次为
  `300/450/650/900/1200/1600` 灵粮。弹窗显示当前人数、本次成本和招募后人数。
- 储量升级按资源分别显示当前/下一级上限与灵木成本。
- 确认时重新校验余额；扣除、人数/等级变化、结算锚点和保存同成同败。

| 储量等级 | 灵粮容量/升级木 | 灵木容量/升级木 | 玄铁容量/升级木 | 灵晶容量/升级木 | 庚精容量/升级木 |
|---:|---:|---:|---:|---:|---:|
| 1 | 400/0 | 300/0 | 200/0 | 100/0 | 20/0 |
| 2 | 800/80 | 800/100 | 500/120 | 250/160 | 50/220 |
| 3 | 1600/220 | 2000/300 | 1200/360 | 600/480 | 120/650 |
| 4 | 3200/600 | 5000/900 | 3000/1050 | 1500/1400 | 300/1900 |
| 5 | 6000/1600 | 12000/2600 | 7000/3000 | 3500/4000 | 700/5200 |

斜线后为“从上一级升至本级”的灵木成本。五类储量均从 1 级开始，1.0 最高 5 级。

#### 4.4 盗天灵液升级

盗天灵液由支线任务奖励直接融入灵源院阵心，不进入背包，也不在灵源院提供独立领取动作。1.0只实现前三个
可达状态：未获得`30秒`、C01第一滴`25秒`、C04第二滴`20秒`。完整策划保留的C07第三滴`15秒`与
C09第四滴`10秒`属于后续章节，不进入1.0任务、UI可达状态或本页发布验收。

任务奖励提交时必须在同一事务内：先按旧周期结算到当前可信时间，再校验`reward_claim_id`，写入
`time_dew_claims`、新`time_dew_level`和新生产锚点。事务失败全部回滚；重复提交、回看对白或迁移
不得再次升级。五种岗位的单周期产出、维护、庚精双周期余数和储量上限不随等级改变。

### 5. 命令与数据

- `SetWorkerAllocation(resourceId, workerCount)`
- `RecruitWorkers(quantityConfigId)`
- `UpgradeResourceCapacity(resourceId)`
- `SettleFarmProduction(settlementReason)`

数据至少包含`time_dew_level: 0|1|2`、`time_dew_claims: Set<reward_claim_id>`与统一生产时间锚点；
`cycleSeconds`只由版本化的`30/25/20`档位表计算，不作为第二份可独立修改的存档事实。灵液通过通用
`ClaimQuestReward`事务触发，不新增灵源院侧用户命令。

生产只记录时间锚点与状态，不依赖页面常驻 Timer 维持业务真相。显示进度可逐帧更新，但到期入库
只能由结算命令确认。

### 6. Figma 必需稿件

- 三行/五行资源列表、长库存数字、满仓、未解锁、无空闲杂役、单行数据错误。
- 灵液状态：未获得30秒、第一滴25秒、第二滴20秒、下一滴属于后续章节，以及重复领取只读状态。
- 离线结算：正常、部分溢出、全部满仓、时间回拨。
- 招募确认：可执行、灵粮不足、提交中、失败。
- 储量升级：可执行、材料不足、满级、数值未配置。
- 行组件覆盖 `normal/selected/disabled/locked/loading/error`，优先使用 Approved `Panel Item V2`。

### 7. 美术素材

引用 [灵源院生产弹窗](../ArtAssets/03_灵源院生产弹窗.md)、
[营地 HUD](../ArtAssets/02_营地HUD.md) 和 [通用图像槽](../ArtAssets/06_通用方形图像槽.md)。
沿用五类资源图标、通用面板、列表项、进度条和加减按钮；离线、满仓和时间异常图标由
[启动、存档与全局反馈素材](../ArtAssets/09_启动存档与全局反馈.md) 补齐。

### 8. 验收

- `V10-FARM-001`：灵源院只出现五种生产资源，解锁与列表状态正确。
- `V10-FARM-002`：调岗前先结算旧配置，连点和刷新不多产、不吞产。
- `V10-FARM-003`：达到储量上限停止入库，溢出量与原因可见。
- `V10-FARM-004`：招募和储量升级失败不扣资源、不改变人数或等级。
- `V10-FARM-005`：时间回拨不会制造收益，恢复正常时间后可继续结算。
- `V10-FARM-006`：周期、产量、维护、招募和储量与冻结表一致；配置缺失时不以 0 代替执行。
- `V10-FARM-007`：第一、二滴只允许按剧情顺序把周期`30→25→20`秒，每滴claim只能成功一次。
- `V10-FARM-008`：升级前先按旧周期结算并原子写入新等级与锚点；失败、连点、刷新和时间回拨不多产。
- `V10-FARM-009`：周期缩短后五岗位单周期产出、维护、庚精余数和储量均不变；15/10秒状态在1.0不可达。

### 9. 不做

生产灵石/魂晶、广告翻倍、离线战斗、手动领取宝箱、超过仓储上限的隐藏累积、建筑施工等待，以及
1.0提前开放第三／第四滴盗天灵液。

### 1. 上游与边界

可购买物、限量物和禁止投放项读取
[基础材料与资源循环](../1.0策划案/数值/34_1.0基础材料与资源循环_草案.md)，地图商品与开放条件读取
[地图分册](../1.0策划案/地图/README.md)；价格、库存、权重和刷新读取
[营地后勤与野外循环](../1.0策划案/数值/36_营地后勤与野外循环机制_草案.md)。交易行是单机系统商店：只允许玩家购买，
玩家不能出售任何物品、装备或材料，也不存在回购队列。

### 2. 信息架构

页面只有“购买”业务，内容固定分为 `常备栏` 和 `随机栏`。

- 常备栏固定显示 4 种防卡死用品；种类常驻但当批库存有限。
- 随机栏固定 `6` 格，按玩家永久最高地图进度选取已开放商品池。
- 每格显示价格、当批库存、用途、开放条件和蓝图的永久解锁状态。
- 顶部固定显示灵石；魂晶不作为交易货币。
- 顶部同时显示下次自然刷新剩余时间、本次手动刷新费用和整批刷新入口。

### 3. 商品边界

- 交易行只出售装备蓝图，不出售任何装备成品；蓝图购买后永久解锁并移出随机池。
- 随机栏可出照影石、凝丹灵草、五类资源包和对策装备蓝图。照影石从地图 2 进度开放，凝丹灵草从地图 3 进度开放。
- 四象阵砂、魔髓碎屑、古宝残片、任务核心、证据、突破物、特定装备成品和古宝不进入商品池。

### 4. 购买流程

1. 选择商品与数量，预览灵石成本、购买后余额、储量/仓库容量和用途。
2. 提交时重新校验商品批次、限量状态、余额和容量。
3. `BuyMarketItem` 原子扣灵石、减商品库存、增加物品/资源并保存。
4. 批次变化、余额不足或容量不足时不扣款，保留选择并解释变化。

### 5. 刷新

- 每 `2` 小时自然整批刷新一次，前台、后台和完全离线均计时。
- 离线跨过多个刷新点时，只保留当前最新批次，不累计历史库存或商品。
- 手动刷新不设每日次数上限，也不改变下次自然刷新锚点。
- 手动整批刷新费用为 `600 + 300 × (最高已到达地图序号 - 1)` 灵石；地图 1–4 分别为
  `600/900/1200/1500`。确认层必须同时显示费用和自然刷新剩余时间。
- 刷新一次性补满常备栏库存并重新生成六个随机格；批次、库存、灵石扣除和蓝图移池必须原子保存。

### 6. 页面状态

| 状态 | 要求 |
|---|---|
| 无商品/未解锁 | 显示条件或稍后刷新，不显示假货 |
| 商品刷新中 | 保留旧批次只读，购买禁用 |
| 灵石不足 | 购买禁用并显示缺口 |
| 刷新费不足 | 手动刷新禁用，不改变当前批次 |
| 容量不足 | 购买禁用，链接百宝库或储量处理 |
| 批次冲突 | 刷新商品并提示价格/库存已变化 |
| 数据错误 | 对应商品/刷新禁用，不以零价购买或刷新 |

### 7. 命令与原子性

- `RefreshMarketView(marketId)`
- `RefreshMarketBatch(marketId, expectedBatchId)`
- `BuyMarketItem(offerId, quantity, batchId)`

所有命令防重复提交；购买与整批刷新必须在库存、货币、批次和蓝图解锁记录之间同成同败。

### 8. Figma 必需稿件

- 购买：常备四商品、随机六格、蓝图移池、售罄、锁定、价格/库存变更。
- 刷新：两小时倒计时、自然刷新、四档手动费用、费用不足、批次冲突。
- 全部覆盖灵石不足、提交中、保存失败和长价格数字。

### 9. 美术素材

引用 [交易、还魂、招贤与乌婆素材](../ArtAssets/14_交易还魂招贤与乌婆馈赠.md)、
[通用图像槽](../ArtAssets/06_通用方形图像槽.md) 和

限量/售罄/蓝图标记、刷新倒计时与交易反馈；物品图标必须复用库存同一资源。

### 10. 验收

- `V10-MARKET-001`：页面只有购买；所有物品、装备和材料均无出售或回购入口。
- `V10-MARKET-002`：常备 4 种商品、随机 6 格、开放边界、价格、库存与权重和冻结表一致。
- `V10-MARKET-003`：批次冲突、连点、容量不足和保存失败不重复扣款或复制物品。
- `V10-MARKET-004`：自然/手动刷新均整批替换；手动刷新不改变自然刷新锚点且蓝图不重复。
- `V10-MARKET-005`：价格、栏位、库存、权重和刷新值来自冻结配置；缺失时不允许零价购买或刷新。

### 11. 不做
