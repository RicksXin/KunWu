## 页面 05：入山整备、编队、装载与地图选择

页面 ID：`expedition_prep`  
需求前缀：`V10-PREP`  
状态：页面规则已定义；数值 `BAL-TBD`

### 1. 上游与边界

普通地图与入山压力读取 [1.0 总案](../1.0策划案/15_1.0版本完整策划案_草案.md) 和
[地图分册](../1.0策划案/地图/README.md)；工具读取
[炼器坊策划](../1.0策划案/数值/33_炼器坊升级与炼制机制_草案.md)。本页只创建出征快照，不执行移动、
战斗或副本奖励结算。

### 2. 入口与层级

- 营地传送阵进入整备页；资源副本快捷入口进入 PRD 07 的副本模式。
- 一级顺序固定为“编队 → 装载 → 地图选择 → 启程确认”，可回看前一步。
- 关闭整备返回大厅，不扣资源、不消耗工具、不改变装备归属。
- 已存在有效出征快照时显示“继续出征”，不得同时创建第二次出征。

### 3. 编队

- 1.0 名册只列石岩、陆清、白灵、墨言；正常出征为四人固定队。
- 卡片显示生命、灵息、等级/境界、职业分支、四槽装备摘要和阵亡状态。
- 阵亡修士不可出征，并链接还魂殿；灵息不足显示具体缺口但不自动消耗道具。
- Boss 情报只提示已知职能建议和硬条件；战力为建议值，不替代策划定义的入口校验。

### 4. 装载

- 显示公共灵粮可装载量、出征灵粮、当前/上限负重和预计最低携粮。
- 可装载策划允许的补给、食物与单次出征工具；资源包不可装入。
- 开山镐每次最多携带一把，启程成功后转为本次出征有效状态。
- 归营符和其他物品按配置数量装载；任务保护物不占普通可丢失池。
- 增减操作只编辑草稿；关闭页面不会保存为已消耗库存。

### 5. 地图选择与确认

| 状态 | 要求 |
|---|---|
| 已开放 | 显示地图名、章节、探索进度、推荐信息、携粮提示 |
| 当前出征 | 仅提供继续，不允许重新选图 |
| 已发现未开放 | 显示上游定义的解锁条件 |
| `map_05` | 只显示后续版本锁定，不泄露可操作内容 |
| 数据加载 | 地图卡骨架屏，启程禁用 |
| 队伍/资源不合法 | 确认页逐项列原因并给出页面内修正入口 |
| 数值缺失 | 显示 `BAL-TBD` 配置错误，禁止启程 |

启程确认必须列出：四名修士、地图、消耗灵息、装载灵粮、工具/补给、负重、探查半径、休整次数和
已知入口条件。成本数值不在 PRD 固定。

### 6. 启程原子事务

`StartExpedition(preparationDraftId)` 同时：

1. 重新校验修士、地图、库存、灵息和唯一出征约束；
2. 扣除四人对应灵息与公共灵粮；
3. 扣除装载物并生成本次出征物资；
4. 固化四人状态、装备实例、探查半径、休整次数和地图入口；
5. 创建唯一 `ExpeditionState` 并保存。

任一步失败全部回滚。按钮提交中锁定；重复请求按 `preparationDraftId` 返回同一次出征。

### 7. 刷新恢复

- 整备草稿可只保留到当前会话；已成功启程必须从持久快照恢复。
- 在保存成功但场景切换前刷新，重新进入时显示“继续出征”，不得再次扣款。
- 装备或修士被其他页面改变后，返回整备必须重新校验草稿并标出变化。

### 8. Figma 必需稿件

- 编队：四人正常、单人阵亡、灵息不足、装备缺失、Boss 职能建议。
- 装载：空、正常、超重、库存不足、任务保护物、工具已达上限。
- 地图：四图开放组合、未解锁、`map_05` 后续锁定、继续出征。
- 确认：可启程、多个阻断原因、提交中、保存失败。
- 提供步骤切换和返回 Prototype，不能用三层以上堆叠模态代替页面。

### 9. 美术素材

引用 [入山整备素材](../ArtAssets/04_入山整备编辑队伍与地图选择.md)、
[通用图像槽](../ArtAssets/06_通用方形图像槽.md) 和
[野外、资源副本与四图素材](../ArtAssets/15_野外探索资源副本与四图内容.md)。
需要四名修士卡面、四图缩略图、补给/工具图标、负重与灵息状态；数字和条件均由 Label 渲染。

### 10. 验收

- `V10-PREP-001`：1.0 只列固定四人，阵亡、灵息不足和已出征状态不能绕过。
- `V10-PREP-002`：装载只改草稿，关闭不扣库存；启程成功才一次性扣除。
- `V10-PREP-003`：`map_05` 只有后续锁定说明，不可通过命令进入。
- `V10-PREP-004`：启程连点、保存失败和切场景刷新不重复扣灵息、灵粮或工具。
- `V10-PREP-005`：出征快照冻结探查半径和休整次数，本次途中升级炼器坊不追改快照。

### 11. 不做

随机修士替补、自动配队、扫荡、体力券、多人并行出征、野外即时换装和动态战力缩放。

## 页面 06：野外探索 HUD、地图对象、扎营与归营

页面 ID：`exploration`  
需求前缀：`V10-EXPLORE`  
状态：四图内容读取上游；页面稿与世界资产待制作

### 1. 上游与边界

地图尺寸、坐标、固定对象、回访状态和出口读取 [地图分册](../1.0策划案/地图/README.md)；
资源包、食物和工具读取 [基础资源循环](../1.0策划案/数值/34_1.0基础材料与资源循环_草案.md)；
剧情对象读取 [剧情剧本](../1.0策划案/剧情/20_1.0剧情任务详细剧本_草案.md)。页面不自行生成坐标、
奖励或检定阈值。

### 2. 页面结构

- 顶部固定 HUD：地图/区域名、出征灵粮、负重、休整次数、归营入口。
- 世界视窗：Tile、迷雾、队伍位置、固定对象、前景遮挡和路径预览。
- 底部操作区：队伍摘要、当前对象交互、任务追踪、扎营。
- 遭遇战进入 PRD 08；资源副本入口首次从本页发现，但副本内流程使用 PRD 07。

### 3. 移动、迷雾与对象

- 只允许四方向移动；长按目的地只在已知可行走格内寻路。
- 迷雾固定为 `UNKNOWN/DISCOVERED/VISIBLE`，未知区不泄露对象。
- 每步先保存坐标和消耗，再触发对象/遭遇表现；表现层不得倒写领域结果。
- 对象使用稳定 `map_object_id`，状态至少覆盖未发现、可交互、已处理、条件锁定、可重复。
- Boss、宝箱、任务对象和捷径按各自持久状态恢复；普通敌群按上游刷新规则处理。
- 前景遮挡在队伍进入时淡出，但不改变阻挡格和可交互区域。

### 4. 对象面板与检定

对象面板显示已知描述、合法选项、成本、检定字段、成功/失败可知后果和返回。七维内部字段只使用：

```text
strength magic technique speed constitution armor resistance
```

- 只展示当前已解锁的解决方式；禁用项显示缺少的工具、任务状态或属性。
- 检定阈值、概率或固定结果读取对象配置，未冻结值标 `BAL-TBD`。
- 结果、奖励、对象状态和任务 Flag 同一事务保存；刷新不允许重掷。

### 5. 灵粮、负重与战利品

- 移动按地形配置消耗出征灵粮；不足反馈不使用公共灵粮自动补扣。
- 灵粮归零后按领域规则持久推进衰竭计数，达到结算条件时进入失败报告。
- 野外资源包、食物、装备和材料先进入出征战利品；公共钱包即时资源按上游结算类型处理。
- 负重变化实时展示。超重处理、阵亡减半和任务物保护由统一结算器执行，不由 UI 自选丢弃结果。
- 资源包在野外不可打开；食物只能在扎营时转化为本次出征灵粮。

### 6. 扎营与归营

#### 6.1 扎营

- 每次扎营提供一次免费“运功疗伤”，只恢复存活修士，不消耗物品。
- 可选择允许的野外食物补充灵粮；食物不恢复生命。
- 扎营次数使用启程快照，操作完成、食物消耗和新状态原子保存。

#### 6.2 归营

- 地图入口安全归营不消耗归营符；其他位置按上游规则判断归营符与禁用区域。
- 确认页预览可带回战利品、未完成对象和归营后状态；不显示尚未结算的随机结果。
- 归营事务清除出征快照、转移战利品、更新修士恢复锚点、任务/捷径状态并创建一次结算记录。
- 全队阵亡使用失败结算，受保护物完整保留、可损失物按上游规则处理。

### 7. 状态与异常

| 状态 | 要求 |
|---|---|
| 默认探索 | HUD 清晰，任务追踪不遮挡移动区 |
| 路径不可达 | 停在原地，不扣灵粮，标出首个阻挡原因 |
| 对象处理中 | 锁定移动和重复交互 |
| 满负重/超重 | 明示后果与可用退出路径 |
| 灵粮归零 | 明示衰竭进度与安全归营选择 |
| 归营符失效区 | 禁用并显示解除条件 |
| 存档失败 | 停止继续移动，保留已确认权威步并允许重试 |
| 刷新恢复 | 从最后保存坐标、对象状态和战利品恢复 |

### 8. 命令

- `MoveExpedition(expeditionId, path)`
- `InteractMapObject(objectId, optionId)`
- `MakeCamp(expeditionId, foodItemIds)`
- `ReturnToCamp(expeditionId, method)`
- `ResolveExpeditionDefeat(expeditionId)`

移动可批量提交路径，但必须逐步结算并保留首个中断事件；重复请求不能跨过遭遇或多扣灵粮。

### 9. Figma 必需稿件

- 四图各一张默认探索稿；`UNKNOWN/DISCOVERED/VISIBLE` 对照稿。
- 对象：采集、宝箱、NPC/传讯、剧情、Boss、捷径、资源副本入口、条件锁定。
- HUD：正常、长数字、满负重、灵粮归零、归营符禁用、存档错误。
- 扎营：免费疗伤、选择食物、无食物、次数用尽、提交失败。
- 归营：安全归营、归营符确认、失败报告、部分损失、待处理战利品。

### 10. 美术素材

引用 [通用事件与战利品](../ArtAssets/07_通用事件标记选项按钮与战利品图标.md) 和
[野外、资源副本与四图素材](../ArtAssets/15_野外探索资源副本与四图内容.md)。需要四图 Tile/遮挡/地标、
队伍棋子、迷雾、对象图标、探索 HUD、路径与检定反馈、扎营和归营结算素材。

### 11. 验收

- `V10-EXPLORE-001`：四图固定坐标、迷雾和对象状态在归营、重进和刷新后保持一致。
- `V10-EXPLORE-002`：不可达路径不扣粮；路径被事件打断时不跨事件继续走。
- `V10-EXPLORE-003`：检定刷新不重掷，奖励与对象/任务状态同成同败。
- `V10-EXPLORE-004`：资源包不能野外打开，食物只能扎营补出征灵粮且不治疗。
- `V10-EXPLORE-005`：归营与阵亡结算各只执行一次，任务保护物不丢失。
- `V10-EXPLORE-006`：`map_05` 出口锁定，不存在越序进入路径。

### 12. 不做

斜向移动、未知区自动寻路、随机大地图、野外即时换装、远程仓库、离线探索、扫荡和表现层决定结果。

## 页面 07：资源副本选择、整备、结算与连续挑战

页面 ID：`resource_dungeon`  
需求前缀：`V10-DUNGEON`  
状态：结构冻结；绝对收益、敌群和掉率 `BAL-TBD`

### 1. 上游与边界

完整规则读取 [资源副本策划](../1.0策划案/地图/32_可重复资源副本与新修士追赶机制_草案.md)。
1.0 只包含：

| 稳定 ID | 显示名 | 主产出 |
|---|---|---|
| `rd_map03_refire_mine` | 铸灵堂·回火矿窟 | 灵石 |
| `rd_map04_soul_echo` | 封魂间·镇魂残响 | 魂晶 |

每座副本三个固定难度、永久解锁、每难度一次首通奖励；不含词条、门票、每日次数、离线扫荡。

### 2. 入口与返回

- 首次发现但未首通基础难度时，只能从大地图入口进入。
- 基础难度首通后，营地传送阵整备页出现“资源副本”分组，可快速重返。
- 快速重返仅跳过已清大地图路程，不自动结算奖励。
- 副本结算可选择“再次挑战”或“返回营地”；返回不得落回已清剧情 Boss 区。

### 3. 选择与整备

- 副本卡显示主产出、世界说明、已开放难度、最近阵容和首通状态。
- 难度行显示机制摘要、推荐境界/职能、固定奖励结构和首通标记；绝对数值读取配置。
- 锁定难度显示世界里程碑或境界条件，不按现实日期轮换。
- 复用 PRD 05 的四人编队、装备与校验，但不扣行路灵粮、入山灵息或门票。
- 1.0 不提示“培养/招募新修士”；固定四人为合法完整队伍。

### 4. 挑战状态

| 状态 | 要求 |
|---|---|
| 未发现 | 营地列表完全不显示 |
| 已发现未首通 | 仅地图入口可进，基础难度可选 |
| 可快速重返 | 营地显示，记住最近合法难度和阵容 |
| 难度锁定 | 展示解锁条件，不泄露隐藏敌群数值 |
| 首通待领 | 结算时与重复奖励同一事务处理 |
| 挑战中 | 占用唯一 `ExpeditionState`，禁止普通出征 |
| 失败 | 显示机制诊断，可原阵容立即重试 |
| 结算错误 | 保留 `challenge_run_id`，重试同一结算 |
| 数值缺失 | 禁止开始该难度，显示数据未配置 |

### 5. 战斗与结算

- 副本使用短机制阶段与 PRD 08 战斗页，不复活对应主线 Boss 或剧情 NPC。
- 灵石本围绕勘脉、护炉/运输、回火首领；魂晶本围绕辨识残响、稳定阵位、残响首领。
- 魂晶来自阵法回收，不表现为反复炼化真实亡魂。
- 重复奖励可含核心货币、普通地区材料、配置的资源包和低概率凡品至上品制式装备。
- 不掉落珍品、法宝、古宝、特定装备、任务核心、剧情证据或唯一魂魄。
- 奖励预览只显示配置结构和可公开概率；未冻结概率标 `BAL-TBD`。

### 6. 原子性与连续挑战

`StartResourceDungeon(dungeonId, difficultyId, preparationId)` 创建唯一 `challenge_run_id`。

`SettleResourceDungeon(challengeRunId, result)` 原子写入：战斗结果、首通状态、永久捷径、首通奖励、
重复奖励、装备实例和结算幂等记录。

- 结算成功后“再次挑战”创建新 run，不复用旧奖励种子。
- 结算未完成时刷新继续处理旧 run，不能开始新 run。
- 连续挑战无递减收益；按钮连点不得跳过战斗或多结算。
- 失败不扣门票；普通战斗消耗按统一战斗规则保留。

### 7. Figma 必需稿件

- 列表：未发现、单本开放、两本开放、快捷入口加载失败。
- 难度：三档开放组合、首通、锁定、数值缺失、收益详情。
- 整备：正常、阵亡、装备/职能提示、继续未完成挑战。
- 结算：首通、重复、装备掉落、仓库待处理、失败诊断、保存错误。
- 连续挑战：再次挑战提交中、返回营地确认、恢复旧 run。

### 8. 美术素材

## 页面 08：战斗、战利品与失败报告

页面 ID：`combat`  
需求前缀：`V10-COMBAT`  
状态：数据流冻结；数值与内容读取上游

### 1. 上游与边界

技能读取 [职业技能分册](../1.0策划案/数值/17_1.0职业技能数值_草案.md)，敌人与 Boss 读取
[敌人与 Boss 分册](../1.0策划案/数值/19_1.0敌人与Boss战斗数值_草案.md)，掉落读取
[装备与掉落](../1.0策划案/数值/18_1.0装备与掉落数值_草案.md)。本页只负责输入命令、表现事件和结算展示。

战斗数据流必须保持：

```text
CombatCommand → 结算器 → CombatEvent → 表现层
```

### 2. 页面结构

- 顶部：遭遇/Boss 名称、波次或阶段与暂停。
- 战场：敌我单位、HP、行动条、状态、目标与阶段对象。
- 底部：当前行动者、三个主动技能、自动策略状态、目标选择、逃离/战术信息。
- 结算层：胜利战利品、Boss 首杀、失败原因、重新挑战或返回路径。

### 3. 战斗状态与输入

| 状态 | 要求 |
|---|---|
| 进入中 | 加载完整 CombatSnapshot，技能不可点 |
| 自动推进 | 非决策时按结算事件播放，不提前修改 HP |
| 等待决策 | 当前单位、合法技能与目标明确高亮 |
| 技能禁用 | 显示冷却、目标、状态或资源原因 |
| Boss 阶段 | 阶段名称、关键对象和已知机制提示可见 |
| 暂停/后台恢复 | 结算暂停在事件边界，不按离线时间推进 |
| 表现跳过 | 只加速/跳过动画，不改变事件顺序和结果 |
| 战斗错误 | 停止输入，保留快照和错误编号，可恢复或安全退出 |
| 胜利/失败 | 锁定战场输入，只通过结算页继续 |

### 4. 技能、目标与自动策略

- 每个当前职业阶段恰好显示三个有效主动技能；技能 ID 与数据表一致。
- 点击技能后只显示结算器判定的合法目标；目标失效时要求重选，不自动换为高价值目标。
- 自动策略按修士分别保存，页面可临时开关；规则变更从名册技能策略页执行。
- 结丹“精通”只改变上游定义数值/显示称号，不生成另一套技能 ID。
- 战力和职能提示不作为普通战斗命令的替代判断。

### 5. 事件表现与可恢复性

- 表现层只消费 `CombatEvent`：行动就绪、技能施放、命中、伤害、治疗、状态、阵亡、阶段切换、胜负。
- 伤害数字、动画、特效或音效完成与否不决定领域结果。
- 加速、后台切前台和刷新按事件游标恢复；已确认事件不重复播放业务副作用。
- 单位生命为 0 后由结算事件标记阵亡，Presenter 不直接写修士状态。

### 6. 战利品与胜利结算

- 普通掉落、装备、资源包、任务物、Boss 首杀物按来源分组展示。
- 随机结果在战斗结算种子中确定，刷新不重抽。
- 装备显示四槽归属、六档品质、器纹和固定效果，不显示装备等级。
- 第 2、4 位主线 Boss 的唯一魂魄随首杀与 Boss Flag 同一事务保存。
- 仓库容量不足时进入待处理区；任务物和唯一魂魄不得丢弃。

### 7. 失败报告

- 显示直接失败原因、关键阶段、阵亡顺序、已知机制未满足项和可执行建议。
- 建议指向升级、换装、技能策略、突破或已知任务情报，不强制要求随机修士。
- 普通遭遇逃离、Boss 失败、全队阵亡和副本失败按上游分别结算。
- 失败报告不得泄露尚未见过的后续阶段完整机制。

### 8. 命令与原子性

- `StartCombat(encounterId, expeditionId)`
- `SubmitCombatCommand(combatId, actorId, skillId, targetIds)`
- `ResolveCombatResult(combatId)`

每个命令带递增序号；重复序号返回已有事件。胜负结算、掉落、Boss Flag、修士阵亡和快照更新同成同败。

### 9. Figma 必需稿件

- 单敌、多敌、Boss 多阶段、阶段机关对象四种战场布局。
- 当前行动、目标选择、技能冷却/禁用/选中、自动开关和暂停。
- 长状态列表、单位阵亡、低生命警告、后台恢复、战斗错误。
- 胜利：普通、装备、资源包、Boss 首杀魂魄、仓库待处理。
- 失败：普通逃离、Boss 机制失败、全队阵亡、副本失败。
