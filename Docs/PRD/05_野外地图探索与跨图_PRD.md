## 2. 固定地图原则

- 每张地图由若干小格组成。
- 队伍只占一个格。
- 每次只移动上下左右一格。
- 敌人、资源、事件、小型副本、Boss、NPC和出口坐标固定。
- 重新进入地图不改变对象位置。
- 对象可改变完成、冷却、刷新状态。
- 普通野外敌人在同一次入山内被击败后保持消失，网页刷新不重置；结束本次入山并重新启程时全部刷新。
  Boss、剧情敌人和带冷却的特殊敌人按各自配置处理，不套用普通敌人的必然刷新规则。
- Boss 与剧情精英的逻辑位置固定；支线强敌按精英处理，不单独建立“支线 Boss”层级。

- `UNKNOWN`：完全隐藏。

## 6. 灵粮与负重

- 有灵粮时每步按目标地形成本扣除，不得出现负数；剩余灵粮不足整步成本时，
  本步耗尽剩余灵粮并完成移动，衰竭步数从下一步开始计算。
- 灵粮自身占负重。
- 入山整备面板可携带物固定为三类：灵粮、开山镐、探灵镜；各自重量与可携带数量从
  外置数据读取，不在 UI 中硬编码。
- 打开入山整备面板时，灵粮默认填充为 `min(当前灵粮库存, floor((队伍最大负重 - 其他已装载物重量) / 单份灵粮重量))`；
  切换队伍、解锁并切换新队伍或编辑当前队伍成员后立即重算。默认值不限制玩家后续手动减少。
- 开山镐用于玄铁、水晶、庚金等资源点开采，也可用于部分副本推进；没有开山镐时，
  对应副本只能选择数据定义的替代代价。
- 探灵镜允许玩家在战斗开始前观察敌方属性；没有探灵镜时不显示完整敌方属性预览。
- 临时战利品占负重。
- 负重 80% 显示警告。
- 超重后不能继续拾取，但可以移动、丢弃和返回。
- 战斗胜利的待拾取物先停留在战利品弹窗，不提前计入临时战利品。玩家选择“全部拾取”
  时按整批重量校验，成功后才并入本次入山的临时战利品；超重时保持原待拾取状态。
- 战利品弹窗上半区允许管理当前野外背包。点击一种物品每次丢弃 `1` 个，数量与负重保存
  成功后同步刷新；丢弃物不自动进入营地库存，也不计入本场待拾取物。
- 三支队伍分别保存自己的装载方案；切换队伍时恢复该队方案，不覆盖其他队伍的装载数量。
- 最大负重根据该队当前上阵修士的最终属性计算，包含装备与已生效的永久加成。力道、
  肉身和储物法器可按外置规则提高负重，具体数值不在本 PRD 固定。
- 地图 UI显示按当前最短路径返回所需的估算灵粮。
- 地图背包以固定方形物品格平铺展示本次入山所得；每格只常驻显示物品图标和右下角数量，
  不以多行文字列表代替物品格。当前无物品时显示明确空状态。

入山地图选择：

- 点击入山整备面板“启程”后，在其上方打开地图选择面板。
- 每个地图项目显示地图名称、地图编号、单次入山所需灵息、每步灵粮消耗与最低建议
  携带灵粮；锁定地图显示解锁状态。
- 两座资源副本首清后，在同一面板的“资源副本”分组显示名称、主产出、已解锁永久难度、
  建议境界/战力和首清状态；点击后进入难度选择，不与普通地图编号混排。
- 点击已解锁地图项目后再次校验队伍、每名修士灵息、营地持有物、最低灵粮和负重。
- 启程成功后，实际携带物统一从营地持有中转入本次入山状态：灵粮从营地灵粮余额扣除，
  开山镐和探灵镜从百宝库库存扣除。三队保存的是装载方案，不提前占用三份物资。
- 入山扣款、物资转移、灵息结算与地图交接必须作为一个完整结果。地图加载失败时，灵息、
  灵粮、开山镐、探灵镜及其他玩家资源保持启程前状态，也不留下有效的野外状态。

### 6.1 入山状态

`ExpeditionState` 是“一次正在进行的入山或资源副本挑战”的持久化快照，不是额外背包，也不是第四支
队伍。它至少记录：模式、地图/副本/难度 ID、队伍方案 ID、出发成员 ID、当前位置、已结算灵息、剩余携带物、
临时战利品、已揭示格子、断粮衰竭步数以及生命周期状态。

- 只允许在最终启程校验全部通过后创建；地图交接成功后才成为有效的进行中入山状态。
- 生命周期至少区分 `active`（野外进行中）与 `settling`（回城或阵亡结算中）；玩家在营地
  且结算完成后不存在有效快照，整备中的未启程方案也不属于 `ExpeditionState`。
- 有效状态用于网页刷新后恢复当前位置和物资，确保同一份物资不会同时存在于营地与野外。
- 地图加载失败时丢弃未生效状态，不得扣除灵息或转移物资。
- 启程时所有出发修士停止灵息自然恢复；回到营地时以当时的 UTC 时间重新建立恢复锚点，
  野外经过的时间不补算。

### 6.2 回城与全队阵亡结算

正常回城：

- 剩余灵粮全部返还营地灵粮余额。
- 未使用的开山镐和探灵镜全部返还百宝库库存。
- 临时战利品合并进营地库存；仓库满时进入待处理区，不静默丢失。

野外全队阵亡：

- 仅当本次入山队伍所有修士均已死亡时触发；单个修士死亡不触发物品减半。
- 对本次入山内所有“可损失物”统一减半，包括剩余装载物资、普通/消耗/材料物品、临时
  战利品，以及修士携带或穿戴的装备。
- 关键物品和任务物品不参与减半，全部带回营地。
- 可堆叠物的返还数量为 `floor(结算时数量 / 2)`；因此奇数向下取整，数量为 1 时返还 0。
- 非堆叠装备按可损失装备实例组成集合，按稳定实例 ID 升序排列后保留前
  `floor(装备实例数 / 2)`，其余损失；不得依赖 UI 顺序、结算时机或临时随机数。
- 减半后保留的物品按正常回城路径返还营地；结算完成后清除本次 `ExpeditionState`。

物品分类、装备范围和仓库满处理以 PRD-07 为准，持久化与失败回滚以 PRD-10 为准。

断粮衰竭导致的全队阵亡：

- 灵粮归零时，地图显示警示“警告：灵粮已尽，护体灵息仅可支撑 4 步”；顶部原
  “灵粮：0”改为“断粮”。
- 此后每次成功位移均计入衰竭步数，包括零灵粮消耗地形。四步状态依次为：
  第 1 步后仍显示“断粮”，第 2 步后显示“气血亏空”，第 3 步后显示“步履维艰”，
  第 4 步后显示“生机将绝”。警示中的剩余步数同步从 4 递减至 0。
- 第 4 步的移动与镜头表现结束后立即结算全队阵亡，不再触发该格的敌人、事件、
  宝箱、资源点或入口交互。
- 本次入山的所有修士生命归零并标记为阵亡，从全部队伍预设中移除，进入还魂殿
  待处理名单；营地还魂殿显示待处理提示。
- 阵亡物品损失仍按本节“野外全队阵亡”统一口径结算，随后清除本次
  `ExpeditionState` 并回到营地。
- 补充灵粮成功后，断粮衰竭步数立即重置为 0；补给保存失败时灵粮、食材与衰竭
  步数必须一起回滚。
- 网页刷新时恢复已保存的衰竭步数；若存档已经到第 4 步但阵亡结算尚未成功，
  地图页必须先重试阵亡结算，不能允许继续移动或重复触发地图对象。

### 6.3 野外休整与归营

玩家可在可移动的野外格开始“休整”。休整是当前入山状态的一部分，不创建
独立地图对象，也不使用外部参考作品的玩家可见术语。

- 1.0 每次入山基础只能进入 1 次休整；进入时即消耗次数并保存。后续由炼器坊
  对应的储物或行营法器升级提高次数，各等级上限从外置配置读取。
- 休整状态锁定地图移动与其他页面操作，只保留“补充灵粮”、“运功疗伤”和
  “结束休整”三个操作；刷新页面后仍恢复在休整状态。
- 补充灵粮每次消耗 1 份当前入山获得的野外食材，例如“妖兽肉”或“辟谷饼”；
  各物品的恢复量由数据表定义。没有可用食材时提示“没有可用的野外食材”，
  灵粮不得超过本次启程时的携带上限。
- 运功疗伤按配置比例恢复当前入山队伍中所有存活修士的生命，不复活已阵亡
  修士；每次休整只能执行一次。
- 结束休整后回到原地继续探索，不改变队伍坐标。
- “归营”从任意坐标消耗 1 张“归营符”并按正常回城口径结算，不再要求回到
  入口传送阵。归营符属于随队关键符箓，不占普通负重。
- 队伍从其他格移动回入口传送阵时，在移动表现结束后弹出二次确认。确认后按
  正常回城口径结算且不消耗归营符；取消后留在入口格并可继续探索。
- 刚启程生成在入口格时不触发归营确认，避免进入地图后立即弹窗。
- 没有归营符时不能从任意坐标直接归营。玩家仍可在尚有休整机会和野外食材时
  补充灵粮，或在衰竭步数耗尽前返回入口传送阵；不存在绕过断粮阵亡的紧急撤离。
- 休整、食材消耗、疗伤和归营都必须原子保存；保存失败时恢复操作前状态。

### 7.1 地图事件面板

队伍踏入可交互对象所在格后，统一打开地图事件面板。敌人、剧情事件、NPC、
资源点、宝箱和小型副本入口不得各自创建结构不同的弹窗。面板固定分为：

1. 信息区：显示对象类型、标题和正文；正文可以是故事、环境描述、人物话语或副本说明。
2. 行动区：只显示当前对象配置的行动，“离开”始终存在。

玩家可见行动使用《昆吾禁地》术语：

| 行动 | 出现条件 | 结果 |
|---|---|---|
| 迎战 | 敌群或 Boss | 创建战斗交接；打开面板本身不代表已进入战斗 |
| 探灵 | 敌群或 Boss | 持有探灵镜时显示敌方属性与特性；是否消耗由数据配置 |
| 交谈 | 存在可对话人物 | 进入正式对话或触发剧情 |
| 开采/破禁/开启/进入 | 对应资源点、机关、宝箱或秘境入口 | 按对象配置显示具体动词；需要开山镐等工具时先校验携带量 |
| 闲谈 | 可闲聊的人物 | 显示无任务结算的风味对话 |
| 离开 | 全部对象 | 关闭面板，不伪造完成、战斗或奖励结果 |

行动成功前不得提前发放奖励或把主动交互对象标记为 `COMPLETED`。纯阅读的
一次性故事可在正文成功载入时完成，但也必须先保存再向玩家呈现结果。

## 8. 属性检定

聚合方式：

- `SUM`：全队总和。
- `MAX`：最高单人。
- `COUNT`：达标人数。
- `ALL`：全员达标。

示例：

```text
神识总和 ≥ 30：安全拆除。
失败：全队损失当前生命 20%，仍可通过。
```

UI显示属性、口径、当前值、阈值和失败后果。隐藏检定必须由剧情明确说明“结果未知”。

## 9. 跨图出口

出口条件可以组合：

- 主线任务完成。
- Boss已死。
- 持有任务物品。
- 建筑或 NPC 状态。
- 七维检定。

1.0 出口事实：

```text
map_01 → map_02：三盏阵灯完成 + 石灵核心
map_02 → map_03：封坛尸将完成 + 四名固定修士均已筑基
map_03 → map_04：持有塔门令
map_04 → map_05：1.0 不可进入，仅在通关后显示锁定预告
```

出口未满足时必须逐项显示缺失条件，不扣除任务物或改变任务状态。所有单向出口必须提前
提示是否可返回；任何新增跨图路线必须先进入 1.0 策划，再同步本 PRD。

## 10. 地图内容标准

- 四图都必须形成非整块矩形的可玩轮廓，并具备敌群、资源、事件、小副本、Boss、出口和回访点。
- 每图恰好一个 Boss；支线强敌和高难可选敌人统一按精英配置，不因内容扩写新增 Boss。
- 敌群、资源、事件、小副本、剧情对象和空间关系不在本 PRD 重抄，统一读取地图27–31；旧版对象ID、奖励与
  候选坐标可参考`地图/22_1.0四图固定对象与经济清单_草案.md`，但冲突时不得用22覆盖新版地图设计。
- PRD 验收只检查对象可达、引用有效、状态可恢复、奖励不重复和出口不死锁。

## 12. 验收

- 固定对象重新进入地图后位置不变。
- 所有出口、Boss和 POI可达。
- 地图 1→2→3→4的出口条件与策划固定对象一致，1.0 不出现跨章跳图入口。
- `map_05`在通关前后都不可进入，且不会建立有效入山状态或发放奖励。
- 不存在无法返回且未提示的死锁。
- 新玩家五分钟内理解坐标、迷雾、灵粮和负重。
- 没有超过 20 步的无事件空走区。
- 鼠标和触控寻路均不误触 UI。
- 三支队伍的装载方案相互独立，负重按当前队伍最终属性计算。
- 地图加载失败后，队伍灵息、营地物资和进行中入山状态均与启程前一致。
- 正常回城完整返还剩余灵粮与未使用工具；全队阵亡减半含装备，但不损失关键物品和任务物品。
- 灵粮归零后警示、四步衰竭状态、补粮重置和第 4 步全队阵亡顺序正确；刷新不能重置步数或重复结算。
- 回火矿窟与镇魂残响均能从所属地图首次进入，基础难度首清后从营地快速重返；未首清时不泄露捷径。
- 资源副本快速重返不扣灵息、行路灵粮或门票，每次奖励都要求实际完成挑战。
- 完全不挑战资源副本且不培养其他修士时，固定四人仍可完成四图主线；资源副本状态不推进任务或复活主线Boss。

## 13. 不做

- 随机地图生成。
- 随机重排敌人坐标。
- 主路/岔路选择界面。
- 斜向移动。
- 地图内动作战斗。
