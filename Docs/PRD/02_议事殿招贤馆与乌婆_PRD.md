## 页面 03：议事殿、对话、任务日志与身份档案

页面 ID：`council_hall`  
需求前缀：`V10-COUNCIL`  
状态：剧情内容已在上游；页面与状态稿待设计

### 1. 上游与边界

剧情节点、说话人、选项、Flag、奖励和汇流只读取
[1.0 剧情剧本](../1.0策划案/剧情/20_1.0剧情任务详细剧本_草案.md)；地图回访读取
[地图分册](../1.0策划案/地图/README.md)。本页不改写对白，不根据 UI 便利合并任务状态。

### 2. 入口与返回

- 点击议事殿进入人物列表；大厅任务摘要可直接进入任务日志并定位当前主线。
- 人物条目进入对话；任务条目进入详情；身份线索进入档案详情。
- 返回顺序为对话选项确认 → 对话 → 详情 → 标签页 → 大厅原位置。
- 对话存在未提交选项时返回需确认；已提交命令不得靠返回撤销。

### 3. 信息架构

一级标签：`人物`、`任务日志`、`身份档案`。

- 人物：肖像、显示名、身份摘要、所在/通讯方式、可处理状态。
- 任务日志：主线优先，其次支线；显示当前目标、地点、已知条件、完成/失败结果。
- 身份档案：按“现用身份、阵录十三、旧营记录、证词与矛盾、已确认结论”组织线索。
- 未发现内容不显示标题和占位问号；已知但尚未解读的内容可显示“待解读”。

### 4. 页面状态

| 状态 | 要求 |
|---|---|
| 默认人物列表 | 当前可交互人物置顶，其他按剧情顺序排列 |
| 无可处理事件 | 人物仍可回看，不伪造红点 |
| 远程传讯 | 明确通讯状态和来源，不显示为人物实体在营地 |
| 对话播放 | 说话人、肖像、正文、继续区域清晰；长文可滚动 |
| 选项 | 后果已知部分明示；禁用项显示条件；提交后防连点 |
| 任务更新 | 新旧目标差异可见，可一键定位新节点 |
| 档案新增 | 对应分类显示一次性新标记，查看后清除 |
| 加载/错误 | 保留当前标签与滚动位置，支持重试 |
| 结局回看 | 已完成内容只读，不再次发奖励或写 Flag |

### 5. 关键流程

#### 5.1 人物对话

1. `StartDialogue(dialogueId, nodeId)` 返回当前合法节点。
2. 普通继续仅推进展示；遇到选项时显示所有合法选项及禁用原因。
3. `ChooseDialogueOption` 原子写入 Flag、任务状态、奖励和下一节点。
4. 保存成功后才播放结果；失败保留选项并允许重试。

#### 5.2 任务日志

- 日志只显示玩家已知信息，不提前泄露隐藏对象、Boss、死亡分支或最终身份。
- 任务状态固定为 `active/completed/failed`；可回访节点另用目标状态表达。
- 点击地点可在普通地图已知区域设置追踪，不自动传送或揭开迷雾。

#### 5.3 身份档案

- 档案条目由稳定 `identity_entry_id` 解锁；同一条目可追加证词版本但不能复制成多个红点。
- 冲突证词并列显示来源和取得时间，不由 UI 自动判真伪。
- 1.0 结尾必须将玩家身份答案落为明确“已确认结论”。

### 6. 命令与原子性

- `StartDialogue(dialogueId)`
- `ChooseDialogueOption(dialogueId, nodeId, optionId)`
- `TrackQuest(questId)`
- `MarkJournalEntryRead(entryId)`
- `OpenIdentityEntry(identityEntryId)`

选项导致的资源、物品、任务、人物状态和档案更新为单一事务。重复提交使用 `dialogue_action_id`
幂等返回，不重复发奖励。

### 7. Figma 必需稿件

- 人物列表：默认、无事件、远程传讯、人物锁定/离开、加载错误。
- 对话：单人、双人切换、无肖像说话者、长文本、选项、禁用选项、提交中、结果错误。
- 任务：主支线混排、仅已完成、目标更新、失败分支、空搜索结果。
- 身份档案：首次条目、冲突证词、待解读、最终确认、无新线索。
- 人物列表至对话至任务/档案跳转的完整 Prototype，标注返回栈。

### 8. 美术素材

引用 [NPC 头像与对话肖像](../ArtAssets/08_NPC头像与对话肖像.md) 和
[议事殿、任务、对话与身份档案素材](../ArtAssets/10_议事殿任务对话与身份档案.md)。需要人物列表条目、
对话底板、任务/档案分类图标、传讯与线索状态标记；所有姓名、对白和任务内容由 Label 渲染。

### 9. 验收

- `V10-COUNCIL-001`：人物实体、远程传讯和已离开人物按剧情状态正确呈现。
- `V10-COUNCIL-002`：对话选项连点、保存失败和刷新不会重复奖励或跳错节点。
- `V10-COUNCIL-003`：任务日志只显示已知目标，定位不揭雾、不传送。
- `V10-COUNCIL-004`：身份档案能从零散证词推进至 1.0 已确认身份结论。
- `V10-COUNCIL-005`：完成、失败和回看状态不重新触发业务命令。

### 10. 不做

自由输入对白、AI 对话、语音合成、任务自动寻路、未发现内容图鉴化和通过 UI 改写剧情分支。

## 页面 15：招贤馆 1.0 锁定说明

页面 ID：`recruit_hall_locked`  
需求前缀：`V10-RECRUIT-LOCK`  
状态：1.0 范围冻结

### 1. 上游与边界

唯一范围读取 [1.0 总案 §4.7](../1.0策划案/15_1.0版本完整策划案_草案.md)。1.0 只解锁营地
招贤馆建筑与后续功能说明，不制作或调用候选、自然刷新、付费刷新、招募、改名、遣散、馆级、
名册容量、随机修士生成或升级。

### 2. 入口与状态

- 建筑未解锁：大厅显示剧情锁定和解锁条件，不可进入。
- 建筑已解锁：点击进入单页说明；返回大厅原横滑位置。
- 说明页显示建筑名称、世界观说明、“后续版本开放”和当前 1.0 固定四人队提示。
- 页面可以说明未来大方向，但不得展示候选卡、刷新倒计时、价格、概率、馆级预览或不可点击的仿真功能。
- 解锁事件只清除大厅建筑锁，不创建招募批次或随机种子。

### 3. 页面状态

| 状态 | 要求 |
|---|---|
| 未解锁 | 只在大厅展示锁定原因 |
| 首次解锁 | 播放建筑解锁说明，确认后进入静态说明页 |
| 已查看 | 不重复显示事件红点，仍可随时打开说明 |
| 加载错误 | 静态本地说明仍应可读；返回不受阻 |
| 后续版本占位 | 仅文本和封印视觉，无可执行控件 |

### 4. 命令与存档

- `UnlockRecruitHall(storyFlagId)` 只能由合法剧情节点触发。
- `AcknowledgeRecruitHallNotice()` 只保存已查看状态。
- 1.0 存档不得新增 `offers`、刷新锚点、馆级、容量、招募记录或随机修士实例。
- 即使历史/异常存档含旧字段，1.0 页面也不得据此开放功能；迁移策略由技术设计单独定义。

### 5. Figma 必需稿件

- 大厅建筑未解锁、首次可处理事件、已解锁三态。
- 说明页默认、首次解锁说明、加载降级三张稿。
- 封印/后续标记必须可读但不表现为“资源不足”的临时禁用按钮。
- 页面不得出现候选槽、抽取概率、刷新、等级、容量或货币区域。

### 6. 美术素材

引用 [营地建筑](../ArtAssets/01_营地大厅建筑与传送阵.md) 和
[交易、还魂、招贤与乌婆素材](../ArtAssets/14_交易还魂招贤与乌婆馈赠.md)。需要招贤馆建筑、封印遮罩、
后续开放说明插图；建筑与插图不得使用三候选剪影、招募卷轴列表或馆级进度作为视觉锚点。

### 7. 验收

- `V10-RECRUIT-LOCK-001`：剧情前建筑锁定，剧情后只开放说明页。
- `V10-RECRUIT-LOCK-002`：UI、命令、存档和数据表均不存在可执行候选/刷新/招募/馆级路径。
- `V10-RECRUIT-LOCK-003`：查看说明不消耗灵石/灵木，不改变修士名册或成长上限。
- `V10-RECRUIT-LOCK-004`：固定四人可完成所有 1.0 主线和两座资源副本基础内容。

### 8. 不做

除建筑解锁与静态说明外的全部招贤馆经营和随机修士功能。

## 页面 16：乌婆 Boss 魂魄馈赠

页面 ID：`wupo_offering`  
需求前缀：`V10-WUPO`  
状态：两次 1.0 馈赠冻结

### 1. 上游与边界

完整规则读取 [乌婆 Boss 魂魄与魂器馈赠](../1.0策划案/35_乌婆Boss魂魄与魂器馈赠机制_草案.md)。
该功能位于议事殿人物列表中的乌婆交互，不新增建筑、商店、日常任务或独立任务链。

1.0 只处理：

| Boss 序位 | 魂魄 | 固定馈赠 |
|---:|---|---|
| 2 | `item_boss_soul_02_corpse_general` 封坛尸将魂魄 | 上品 `a02_soul_banner_mail` 封坛军魂甲 |
| 4 | `item_boss_soul_04_silver_wing_avatar` 银翅尸煞魂魄 | 珍品 `a04_soul_wing_robe` 银翅魂衣 |

### 2. 入口与解锁

- 持有可交付魂魄时，乌婆人物条目显示“可交付·Boss 魂魄”。
- 若乌婆此前未解锁，首次获得魂魄后在安全归营时完成基础引见并开放此功能。
- 一次只处理玩家主动选择的一枚魂魄；已兑换内容只允许回看对白。
- 魂魄不占负重，不能出售、分解、丢弃、炼化或用于普通配方。

### 3. 页面结构与状态

- 顶部：乌婆肖像、当前功能说明和对白。
- 主区：可交付魂魄列表、来源 Boss、馈赠装备预览和唯一状态。
- 详情：装备品质、四槽中的防具槽、固定器纹、固定效果和“不作为主线门槛”说明。

| 状态 | 要求 |
|---|---|
| 无魂魄 | 显示已知规则，不出现兑换按钮 |
| 可交付 | 预览唯一固定装备，明确不收费 |
| 多枚待处理 | 玩家逐枚主动选择，不自动批量交付 |
| 已兑换 | 只读回看，不显示再次领取 |
| 仓库满 | 显示将进入待处理区，仍可确认 |
| 保存失败 | 魂魄保留、装备不生成、领取状态不写入 |
| 旧档补发 | 说明补发来源，只补一次 |

### 4. 交付流程

1. 选择合法魂魄，展示乌婆对白和固定魂器完整预览。
2. 确认页说明：不消耗灵石/魂晶/记忆；魂魄将被消耗；奖励唯一。
3. `OfferBossSoulToWuPo(exchangeId, soulItemId)` 原子处理魂魄、装备实例/待处理区、领取记录和人物状态。
4. 成功后播放对应短对白并刷新百宝库；失败回到可交付状态。

装备的品质、器纹类型和固定效果固定，领取时不随机；装备没有等级。

### 5. 幂等与迁移

- `rewardClaimId` 是唯一幂等边界；重复提交只返回第一次成功结果。
- Boss 首杀、魂魄生成和 Boss 完成 Flag 在战斗结算事务中完成；本页只处理兑换。
- 已击败 Boss 且既无魂魄又无领取记录的合法旧档补发一次；已有领取记录不补发。
- 仓库满时进入待处理区仍视为兑换成功，不能重复领取。

### 6. Figma 必需稿件

- 乌婆未解锁归营引见、无魂魄、单枚可交付、两枚待处理、已兑换回看。
- 装备预览分别覆盖上品单/双器纹信息和珍品双器纹/固定效果信息。
- 仓库满待处理、提交中、保存失败、旧档补发说明。
- 对话与选择复用议事殿组件，馈赠不是商店购买布局。

### 7. 美术素材

引用 [NPC 头像](../ArtAssets/08_NPC头像与对话肖像.md)、
[交易、还魂、招贤与乌婆素材](../ArtAssets/14_交易还魂招贤与乌婆馈赠.md) 和
[百宝库装备素材](../ArtAssets/12_百宝库装备资源包与分解.md)。需要两枚魂魄、两件魂器、乌婆馈赠光效、
唯一/已交付标记；不得使用抽卡、随机宝箱或炼化活人魂魄的视觉。

### 8. 验收

- `V10-WUPO-001`：只有第 2、4 位主线 Boss 首杀魂魄可进入馈赠。
- `V10-WUPO-002`：未提前解锁乌婆时，获得魂魄后安全归营仍可完成引见和交付。
- `V10-WUPO-003`：两件装备按固定 ID、品质、器纹和效果直接发放，不需要再次打造。
- `V10-WUPO-004`：连点、刷新、仓库满、保存失败和旧档迁移不会复制或吞失魂魄/魂器。
- `V10-WUPO-005`：不领取、不装备或出售合法魂器均不阻断主线。

### 9. 不做

随机奖励、收费兑换、每日轮换、资源副本魂魄、普通亡魂炼制、蓝图替代完整装备和重复领取。
