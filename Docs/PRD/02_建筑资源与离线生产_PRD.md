# 《昆吾禁地》PRD 02：建筑、资源与离线生产

版本：0.6
模块：BLD / ECO  
负责人：系统策划、客户端、数值、UI/美术

## 1. 模块目标

建立可持续的营地经济，使灵粮同时承担高级资源生产成本和野外移动成本。玩家必须在“发展营地”和“立即出征”之间分配资源。

## 2. 资源定义

| 资源 | 用途 | 主要来源 |
|---|---|---|
| 灵粮 | 岗位维护、地图移动 | 灵圃 |
| 灵木 | 建筑、低阶打造 | 林场岗位 |
| 玄铁 | 工具、装备、建筑 | 矿洞岗位 |
| 灵晶 | 高阶建筑、阵法 | 灵脉岗位 |
| 庚精 | 顶级装备、封印工程 | 高阶矿脉/Boss |
| 魂晶 | 修士升级、还魂 | 战斗、任务 |
| 灵石 | 招募刷新、交易 | 任务、出售、探索 |

天符玉只保留数据字段，MVP 不进入消费闭环。

## 3. 杂役和生产

初始周期 30 秒。

| 岗位 | 单人产出 | 单人灵粮维护 |
|---|---:|---:|
| 灵粮 | 1 | 0 |
| 灵木 | 1 | 2 |
| 玄铁 | 1 | 3 |
| 灵晶 | 1 | 4 |
| 庚精 | 1 | 9 |

结算：

```text
周期数 = floor(有效秒数 / 当前周期)
产出 = 周期数 × 岗位人数 × 单周期产出 × 增益
净灵粮 = 灵粮产出 - 其他岗位维护
```

灵粮不足停工顺序：庚精 → 灵晶 → 玄铁 → 灵木。

显示名与存档字段映射：`Wallet.spiritStone` 显示为“灵晶”，`Wallet.immortalCoin` 显示为“灵石”。字段名当前不迁移，领域逻辑不得通过中文显示名判断资源类型。

### 3.1 P1 灵圃分配范围

P1 只通过灵圃开放三种基础岗位：灵粮、灵木、玄铁。灵晶和庚精未开放时不显示
对应资源行，P1 页面不允许提前分配。Prefab 保留这两个资源行节点，待 P2 开放后
直接启用并接入对应配置与交互。

点击大厅中的灵圃后，不切换到独立建筑场景，也不制作灵圃室内背景；只在当前
大厅上方打开一个带半透明遮罩的纵向生产弹窗。弹窗结构固定为：标题、当前阶段
已开放的资源岗位、结算倒计时与进度条、杂役招募和关闭。P1 只显示三条开放
岗位。每条开放资源岗位显示当前库存/最大储量，并在右侧
提供“升级”按钮；P1 不显示产量升级、双倍收益或广告入口。

五个资源行节点使用同一个视图组件和数据定义驱动，逻辑显示尺寸统一为 `312×64`，
行间距为 `5`。图标、名称、库存、当前产量、状态、分配数/可分配上限、升级与
`-`/`+` 各有
独立布局区域，不得相互覆盖；当前阶段所有已开放行必须在 `375×817` 基准弹窗中
完整显示且无需滚动。主面板使用固定高度，不随当前可见资源行数量伸缩；未开放行
隐藏后保留对应布局空间，倒计时、进度条和底部按钮仍处于固定位置。P2 开放灵晶和
庚精时只启用对应行，不新增页面或改变列表结构、面板高度。

升级按钮固定在资源行右上方；资源行右下方按“减号、`x/y`、加号”的顺序排列。
`x` 为该资源当前已投入的杂役数，`y` 为该资源在当前分配状态下可达到的投入上限，
即“该资源当前投入数 + 当前空闲杂役数”。不再额外显示“人数：x”。加减按钮的
视觉尺寸为 `24×24`，触控区仍为 `48×48`。

主面板不再单独显示“杂役总数 / 已分配 / 空闲”的分配总结；当前可继续投入的数量
直接通过每条资源行的 `x/y` 表达。移除总结后，可见资源行、倒计时和进度条整体
上移，三者之间的相对间距保持不变。

资源行不显示存储等级和单人产出/维护拆分，只显示“当前库存 / 当前最大储量”和
“产量 ±X”。灵木、玄铁的产量等于该行已分配人数；灵粮行显示本周期净产量，
即灵粮岗产出减去灵木、玄铁岗位维护，因此向非灵粮岗位分配杂役时必须实时减少。
未开放资源行整体隐藏，不显示锁定占位、`0/0` 或 `--`。

- P1 新档初始杂役为 6 名，当前总数需要写入存档，不能只通过岗位人数临时推算。
- 新档的 6 名杂役全部处于空闲状态，由新手流程引导玩家首次分配。
- 已分配人数为三个开放岗位人数之和；空闲人数为“总数 - 已分配人数”。
- 每个岗位人数必须是非负整数，且总分配人数不得超过当前杂役总数。
- 分配的是杂役岗位，不是直接把已有资源投入某个资源池。

灵圃页面至少显示：当前三种资源库存/最大储量、各岗位的 `x/y` 分配信息，以及按
当前分配实时计算的产量。P1 的 30 秒产量值为：

```text
灵粮产出 = 灵粮岗人数
灵木产出 = 灵木岗人数
玄铁产出 = 玄铁岗人数
灵粮维护 = 灵木岗人数 × 2 + 玄铁岗人数 × 3
预计灵粮净变化 = 灵粮产出 - 灵粮维护
```

页面不再单独显示“下周期”汇总和“全部岗位可正常生产”等全局状态文案；满仓、停工
仍在对应资源行内显示。倒计时只显示“距下次结算 00:XX”，不追加“/ 30秒”。

岗位没有“确认分配”按钮。玩家每次点击 `-`/`+` 都直接调岗：系统先按旧配置
结算已经完成的在线周期，再应用新人数、刷新预计值并保存。快速连续点击必须按
顺序处理，不能重复结算、吞掉在线周期或让总分配人数超过当前杂役总数。

#### 3.1.1 杂役招募

灵圃主弹窗底部固定显示“杂役招募”和“关闭”两个按钮。点击“杂役招募”后，在
主弹窗上方再打开二次确认弹窗，并进一步加深遮罩；二次弹窗至少显示：灵粮图标、
本次需要消耗的灵粮数量、当前灵粮、招募结果“杂役 +5”，以及“招募/取消”按钮。
主弹窗的“杂役招募”始终可点击，即使灵粮不足也允许打开二次弹窗查看消耗；
是否可执行只由二次弹窗中的“招募”按钮表示。

| 配置 | P1 规则 |
|---|---|
| `initial_worker_count` | 新档初始 6 名 |
| `workers_per_recruit` | 每次成功招募 5 名 |
| `recruit_spirit_grain_cost` | 单次灵粮消耗，由平衡数据配置；UI 和业务代码不得硬编码具体数值 |

- 当前灵粮不少于配置消耗时，“招募”按钮可用；点击后原子扣除灵粮、杂役总数
  增加 5、立即保存并关闭二次弹窗，主弹窗随即刷新总数、空闲人数和灵粮库存。
- 当前灵粮少于配置消耗时，“招募”按钮禁用，同时用文字显示“灵粮不足”；
  “取消”按钮始终可用。
- 点击“取消”只关闭二次弹窗，返回灵圃主弹窗，不扣灵粮、不增加杂役。
- 二次弹窗打开期间，主弹窗的岗位按钮、杂役招募和关闭按钮均不可操作；系统返回
  键优先关闭二次弹窗。
- 点击“招募”时必须再次校验最新灵粮库存；若弹窗打开后库存发生变化导致不足，
  本次事务失败且不部分扣款。
- 招募只增加杂役总数和空闲人数，不自动改变任何岗位分配。

#### 3.1.2 资源储量升级

灵粮、灵木、玄铁三条开放资源行的右侧均显示“升级”按钮。该按钮只升级对应
资源的存储等级与最大储量，不提升单位产量、不缩短生产周期，也不改变当前岗位
人数。资源行常驻显示“当前库存 / 当前最大储量”；达到上限时显示“已满仓”。

点击任一资源行的“升级”，在灵圃主弹窗上方打开升级确认弹窗并加深遮罩。弹窗
至少显示：目标资源名称、灵木图标、升级所需灵木、当前灵木、当前最大储量、
升级后的最大储量，以及底部“升级/取消”两个按钮。灵木不足时仍允许打开弹窗
查看消耗和升级收益，只禁用二次弹窗中的“升级”按钮。

| 配置 | P1 规则 |
|---|---|
| `resource_storage_initial_level` | 灵粮、灵木、玄铁的新档初始存储等级，由资源分别配置 |
| `resource_storage_capacity_by_level` | 各资源每级最大储量，由平衡数据配置 |
| `resource_storage_upgrade_spirit_wood_cost` | 各资源升至下一级所需灵木，由平衡数据配置 |
| `resource_storage_max_level` | 各资源在当前版本可达到的最高存储等级 |

- 当前灵木不少于配置消耗时，“升级”按钮可用。点击后先按旧储量上限结算已经
  完成的在线周期，再次校验等级和灵木，原子扣除灵木、提升目标资源存储等级、
  更新最大储量并立即保存。
- 升级灵木自身的储量时，升级消耗同样从当前灵木库存中扣除，不豁免费用。
- 当前灵木少于配置消耗时显示“灵木不足”，二次弹窗中的“升级”按钮禁用；
  “取消”始终可用。
- 点击“取消”只关闭升级确认弹窗，不扣除灵木、不改变存储等级和最大储量。
- 已达到当前版本最高存储等级时，资源行显示“已满级”，升级按钮禁用且不再
  打开确认弹窗。
- 升级确认弹窗打开期间，灵圃主弹窗不可操作；系统返回键优先关闭确认弹窗。
- 快速重复点击只允许一个升级事务成功；消费失败时不得部分扣除资源或提高容量。
- 各资源存储等级必须进入存档。刷新页面后根据存储等级和配置表恢复最大储量，
  不把最大储量作为另一份可漂移的存档数值重复保存。
- 生产结算后的资源库存不得超过当前最大储量；超出部分不进入库存，并在资源行
  显示“已满仓”。

P1 只结算游戏处于前台运行期间的在线生产，不结算关闭页面或浏览器后台期间的
离线收益。游戏保持前台时，离开灵圃进入其他游戏页面不会暂停生产；灵圃打开时
每 30 秒刷新一次完整周期的结算结果。进入灵圃、每次调岗、招募成功、储量升级
成功和关闭灵圃时也执行结算与保存。刷新页面后必须恢复最新已保存的岗位配置、
资源、杂役总数和三种资源的存储等级。

若“当前灵粮库存 + 本周期灵粮产出”不足以支付维护，P1 按玄铁 → 灵木的顺序
停工；一个岗位停工时该岗位本周期整体不产出，不做部分杂役开工。页面必须同时
显示停工岗位、原因和恢复条件。该规则是完整停工顺序在三种 P1 岗位上的子集；
P2 开放灵晶、庚精后使用完整顺序。

P1 不实现灵晶/庚精分配、离线收益、整座灵圃建筑升级和生产加成，但实现本节定义
的三种资源独立储量升级。杂役总数只通过“消耗灵粮、每次招募 5 名”增长，不增加
其他来源。

## 5. 建筑升级

本节的“建筑升级”指整座建筑的等级与综合收益，不等同于 3.1.2 的单项资源储量
升级。P1 只开放灵圃内的资源储量升级；整座建筑 1–5 级仍按下述阶段规划实现。

每座建筑 1–5 级。升级需求由数据表配置：

- 前置任务。
- 玩家主线进度。
- 其他建筑等级。
- 资源消耗。
- 固定 NPC 入驻。

升级立即完成，不加入现实时间施工。

升级收益必须至少属于一种：

- 新功能。
- 新配方、商品或英雄品级概率。
- 容量提高。
- 生产效率提高。
- 离线时间提高。

禁止只有数值很小、玩家不可感知的空升级。

## 6. 离线收益

- P1：不结算离线。
- P2：最多 4 小时。
- P3C：通过建筑升级提高到 8 小时。
- 每次进入营地、修改岗位、退出页面时结算。
- 先按旧岗位结算，再应用新分配。
- 时间倒退超过 5 分钟时暂停离线收益并提示。
- 浏览器后台不视为玩家主动退出。P1 恢复时不计后台时长并重置在线结算起点；
  P2 起按离线收益上限统一结算。

## 8. 资源保护

- 所有资源使用安全整数。
- 任何结算不允许出现负库存。
- 消费失败时不扣除部分资源。
- 重复点击升级只执行一次事务。
- 离线结算有最大周期数。
- 存档迁移不得改变已拥有资源。

## 9. 阶段验收

### P1

- 岗位 `-`/`+` 点击后直接生效并保存，页面中不存在“确认分配”按钮。
- 杂役招募二次弹窗准确显示配置消耗和“杂役 +5”。
- 灵粮充足时招募成功，库存按配置扣除、总数增加 5、原岗位人数保持不变。
- 灵粮不足时招募按钮禁用；取消招募不改变任何资源和杂役数据。
- 页面完整显示灵粮、灵木、玄铁三条资源行及其当前库存/最大储量和升级入口；
  未开放的灵晶、庚精资源行不显示。
- 储量升级弹窗准确显示灵木消耗与升级前后上限；灵木不足时升级按钮禁用。
- 升级成功只提高目标资源最大储量，不改变产量、周期和岗位分配，且刷新后等级保持。

### P2

- 玩家理解灵粮既用于生产又用于移动。
- 灵粮不足会正确停工。
- 关闭页面 30 分钟后收益正确。
- 修改岗位前后的产量无丢失、无重复。

### P3C

- 五种资源均有稳定来源与消耗口。
- 玩家不会因灵粮归零永久无法出征。
- 建筑升级能够改变玩法或容量。

### P4

- 模拟 30 天生产不溢出。
- 修改系统时间不能无限刷资源。
- 经济不存在必须等待数小时才能继续主线的硬墙。

## 10. 灵圃生产弹窗美术与 GPT Image 制作要求

本节参考用户提供的《地下城堡 2》庄园生产面板截图，只借鉴“大厅上方打开纵向
生产面板、资源行右侧提供储量升级、操作后叠加二次弹窗”的信息结构，不复制其
双龙边框、银色浮雕、资源图标、升级按钮造型、工匠招募按钮造型、二次弹窗边框、
双倍收益、货币栏或其他具体视觉。

```text
大厅（保持原位置并变暗）
└─ 灵圃生产弹窗
   ├─ 标题“灵圃”
   ├─ 灵粮岗位：图标、库存/上限、净产量、升级、- / x/y / +
   ├─ 灵木岗位：图标、库存/上限、当前产量、升级、- / x/y / +
   ├─ 玄铁岗位：图标、库存/上限、当前产量、升级、- / x/y / +
   ├─ 任一资源升级：灵木消耗 + 当前上限 → 新上限 + 升级 / 取消
```

### 10.5 制作顺序与验收

1. 先按 3.1 完成灵圃主弹窗、杂役招募弹窗和储量升级弹窗灰盒，截取 10.2 的五张项目截图。
2. 先生成弹窗边框和资源行，在灰盒截图上合成检查 P1 三行无重叠，且库存/上限、升级和分配信息清楚。
3. 生成两张完整加减按钮和一张共用横向按钮；按下/禁用态由运行时 Tint 验证。
4. 复用或补齐资源图标，最后生成周期条。
5. 所有素材导入 Cocos 后设置 Nearest、正确九宫格与表格中的逻辑尺寸。

验收：

- 点击灵圃后只出现一个纵向生产弹窗，大厅在后方变暗且不发生场景切换。
- P1 主弹窗只显示灵粮、灵木、玄铁三条可操作资源行；未开放的灵晶、庚精不显示，
  且没有产量升级、双倍收益、广告或付费入口。
- 玩家能在 3 秒内看到各岗位 `x/y`、库存/上限、当前产量、升级和 `-`/`+`。
- 灵粮行产量随灵粮岗人数增加，并随灵木/玄铁岗位维护实时减少；页面不显示储量等级、
  “下周期”汇总或“全部岗位可正常生产”文案。
- 主弹窗底部只有“杂役招募/关闭”，不存在“确认分配”按钮。
- 招募与储量升级弹窗复用主面板边框、对应资源图标和通用按钮；没有新增专用边框或资源图标。
- 灵粮不足时二次弹窗的招募按钮禁用，取消按钮仍可辨识且可用。
- 灵木不足时储量升级弹窗的升级按钮禁用；灵木充足时明确显示升级后的最大储量。
- 灵粮、灵木、玄铁与大厅顶部使用相同图标文件。
- 弹窗、资源行和按钮缩放后像素清楚，九宫格没有拉伸破损。
- 按钮按下、悬停和禁用 Tint 不改变原图外轮廓，并能清楚区分可用状态。
- 灵粮不足与停工通过文字说明，不只依赖颜色。
- 所有文案和数值由 Label 渲染，PNG 中没有烘焙文字或数字。
- 美术只借鉴参考截图的信息层级，没有复制双龙边框、银色浮雕、图标或按钮。
- 所有按钮节点至少 `48×48dp`，在目标分辨率和安全区内无遮挡。
