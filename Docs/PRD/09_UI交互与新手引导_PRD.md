# 《昆吾禁地》PRD 09：0.1 UI、交互与新手引导

版本：0.1-product.1
日期：2026-08-04
状态：试玩版本产品化落地
模块：UX
负责人：产品、UI/UX、客户端

## 1. 模块目标

在竖屏 Web 中清晰呈现资源、固定四人、四图探索、战斗和五条任务链。UI 必须同时支持
鼠标和触控，不依赖颜色传达唯一信息。剧情文本、人物状态和选择结果读取 PRD-08 绑定的
上游策划数据，UI 不根据章节标题、显示名或旧五图规划自行推断。

## 2. 技术边界

- 使用 Cocos UI。
- 不引入React。
- UI 设计稿基准视窗为375×817；这是玩家可见窗口，不是大厅全景内容宽度。
- `1080×1920` 仅是迁移中的旧 Cocos 工程坐标，不作为新 UI 的尺寸来源；`360×640`
  只可用于世界 Tile、角色等像素素材的内部参考，不参与 UI 布局与 UI 素材尺寸推导。
- 适配浏览器安全区和地址栏变化。
- PC 浏览器按375:817视窗居中展示，高度优先占满可用区域，宽度按比例计算，视窗外为纯黑留边。
- H5、手机和平板同样保持375:817；设备比例不一致时等比缩小并留边，不拉伸视窗。
- 改变视窗尺寸不得把大厅全景、地图或其他横向内容整体压缩进一屏；超出可视窗口的内容继续通过横滑、滚动或分页查看。

## 4. 通用交互

- 最小触控区域48×48dp。
- 高风险操作二次确认。
- 长按显示物品/属性说明。
- 鼠标悬停与触控长按提供同等信息。
- 返回键先关弹窗，再返回页面。
- 加载期间禁止重复点击。
- 所有异步操作显示处理中状态。

## 5. 视觉信息

修士灵根资质、装备品质和危险等级同时使用：

- 颜色。
- 文字。
- 边框形状。
- 图标。

不能只靠颜色区分。

关键提示：

- 灵粮不足。
- 负重80%。
- 无法安全返回。
- 属性检定失败后果。
- Boss危险。
- 死亡和还魂。
- 存档失败。

## 6. 地图UI

地图顶部按两列信息组织，其下常驻当前任务摘要：

- 左上信息区：地图名称（当前坐标）、当前/最大负重 `x/y`、剩余灵粮。
- 右上操作栏：休整、归营、队伍、背包、设置。所有按钮有效触控区不小于 `48×48dp`。
- 任务区：位于信息区和操作栏下方，与营地界面复用同一任务摘要组件与
  文案数据源；无主线时仍显示“暂无主线任务”。
- 休整面板只显示剩余休整次数、可用野外食材和队伍恢复摘要，底部为
  “补充灵粮 / 运功疗伤 / 结束休整”。
- 背包面板只展示当前入山期间获得的临时战利品；完整营地背包不在此复制。
- 队伍移动回入口传送阵后弹出“是否结束本次入山并返回营地”二次确认，
  底部为“确认归营 / 取消”；取消不改变队伍坐标。
- 队伍与设置内容未定义前，点击统一显示“功能待定”，不打开空白面板。

点击格子：

- 已知可达格显示路径和消耗。
- 未知格不显示内部对象。
- 固定POI显示类型、是否完成。
- 条件出口显示缺少条件。

## 6.1 大厅 UI

- 大厅的页面结构、建筑位置、横滑规则和未开放范围以 PRD-01 为唯一事实源。
- 顶部头像、五种生产资源和主线提示固定，不随营地全景横滑。
- 中央营地全景支持触控与鼠标横向拖动，默认定位城堡/入山所在的中部区域。
- 底部左侧固定显示设置、成就、排行榜、邮件、日常进度；右侧显示独立于顶部灵晶的灵石余额。
- 成就、排行榜、邮件、日常进度暂不实现，必须展示禁用或明确未开放状态。
- 天符玉和全部付费入口隐藏，不保留可见占位。
- 横滑位移超过 PRD-01 定义的阈值后取消建筑点击，避免拖动误触。

## 6.2 入山整备、编队与地图选择

入山整备不是独立页面。玩家点击大厅传送阵后，在原大厅上方打开模态层；全屏暗色遮罩
仍按 `375×817` 覆盖，但主面板使用居中的紧凑 `359×570` 逻辑尺寸，不铺满屏幕。顶部与
底部大厅 HUD 被遮罩但不销毁。由上到下固定为：

1. 4 个横向修士槽位：空位为人物黑影与“人选未定”；已上阵卡使用对应静态立绘，
   并直接压在立绘上显示当前灵息、姓名、职业·等级和境界文字，不增加信息底板；灵息
   只显示当前值，不显示 `/100`。修士立绘在卡框内水平居中，灵根资质使用独立边框。
2. 操作栏：编辑队伍、队伍栏、调息。新档队伍栏仅开放 1 队；锁定队伍显示锁定
   标识与灵石费用。三队各自保留上阵修士与装载方案，切换后恢复对应内容并立即重算
   负重。调息当前禁用并标注暂未开放。
3. 当前/最大负重 `x/y`。
4. 灵粮、开山镐、探灵镜三条装载行：显示已携带/当前拥有、单件重量和 `- / +`；触控区
   不小于 `48×48dp`，增减后按该队最终属性立即刷新负重并保存。普通编队或装载保存失败时，
   页面保留当前编辑结果，显示明确的失败原因和“重试保存”入口。
5. 历练、启程、离开三个按钮。历练当前禁用；启程打开地图选择面板；离开无损关闭。

点击“编辑队伍”打开第二层选人面板。面板纵向滚动展示全部已拥有修士，每行包含头像、
境界、灵根资质、姓名、职业、等级、灵息、战力以及选择/取消按钮；选中态同时使用描边、底色和
“取消/槽位编号”文字，不只依赖颜色。系统返回键先关闭选人面板，再关闭入山整备面板。

点击“启程”打开第二层地图选择面板。每行显示地图编号、名称、所需灵息、每步灵粮和
最低携带灵粮；点击已解锁项目即执行最终校验并传送，不再增加一层确认。系统返回键先
关闭地图选择面板。任何修士灵息不足、灵粮不足、负重超限、阵亡或跨队重复都必须用
文字说明具体原因。地图加载失败时返回入山整备状态，并明确说明本次没有扣除灵息或物资。
解锁队伍保存失败时，队伍锁定状态和灵石余额都恢复到操作前，并显示可重试提示。

## 7. 战斗UI

- 页面基准为 `375×817`，底部至少保留 `54px` 安全区；环境背景覆盖全屏，但重要地标
  不得放在单位和信息覆盖区后方。
- 普通敌群在中上方并排；首领居中，召唤单位可采用三角阵或环绕阵。美术站位只用于
  排版，不显示或暗示前后排、距离和站位承伤。
- 我方最多四名修士在底部安全区上方并排。
- 敌方信息从上到下固定为：动态立绘、名称、族类图标 + 生命条、行动条、状态图标。
- 我方采用相同顺序；名称、族类图标、生命条、行动条和状态图标同样全部覆盖在动态立绘
  底部，不在立绘外单独占据纵向区域。
- 敌我名称和生命条必须有不只依赖颜色的阵营差异；嘲讽锁定、控制和增益/减益均使用
  状态图标表达，状态层数或剩余时间由 Label 渲染。
- 我方行动条就绪时显示该修士的三个技能入口；点击修士名称切换自动施法开/关，状态不只
  依赖颜色表达。
- 页面不提供 `2×` 倍速入口。达到配置的敌方生命阈值或剧情条件时，右上角显示“逃生”；
  未满足条件时不显示占位按钮。
- 伤害、治疗、技能名和状态数字由运行时文字与动画渲染，不得烘焙进角色或 UI 图片。

具体素材表、截图要求、动态立绘交付口径和 GPT Image 提示词见
[《昆吾禁地》战斗页面与动态单位美术分册](../ArtAssets/05_战斗页面与动态单位.md)。

## 8. 新手引导

目标：前10分钟完成第一次入山。

| 时间 | 引导 |
|---|---|
| 0–2分钟 | 营地资源和灵圃 |
| 2–5分钟 | 领取固定四人队 |
| 5–8分钟 | 编队、装备、三技能 |
| 8–10分钟 | 灵粮、负重、入山 |
| 10–15分钟 | 逐格移动、迷雾、固定敌人 |
| 15–20分钟 | 属性检定和返回选择 |
| 20–30分钟 | 首次安全归营、打造与还魂入口说明 |
| 30分钟后 | 按地图 1 主线继续教学固定对象、阵灯、队伍成长与 Boss 准备；不承诺 45 分钟内完成首图 |

引导原则：

- 先操作后解释。
- 一次只要求一个动作。
- 可重看。
- 0.1 允许跳过已完成的新手引导，跳过后可从帮助页回看。

## 9. 可访问性

- 关闭震屏。
- 降低闪光。
- 字号档位。
- 音量分组。
- 颜色辅助图标。
- 自动战斗速度可选。
- 键盘Escape/浏览器返回一致。

## 11. 验收

- 新测试者三次点击内从大厅进入入山整备。
- 10分钟内第一次入山。
- 能说出灵粮和负重的区别。
- 能理解属性检定失败结果。
- 能区分 Boss、精英、普通敌群与危险环境；不会看到旧“三类 Boss”图例。
- 地图选择只允许进入已解锁的 `map_01`至`map_04`；`map_05`只显示锁定预告。
- 招贤台只显示试玩版本未开放，不生成候选、不允许消费资源。
- 手机浏览器无被地址栏遮挡的关键按钮。
- 鼠标和触控均完成全流程。
- 切换三支队伍时，成员、装载与负重显示同步切换，不串用其他队伍数据。
- 队伍解锁、普通保存和地图加载失败都显示对应反馈，且资源显示与实际回滚结果一致。

## 12. 不做

- React UI。
- 横屏专用布局。
- 拖拽式大厅建造。
- 复杂手势作为唯一操作。
- 强制观看长教程。
