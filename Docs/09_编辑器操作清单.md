## `#6c` 首次构建验证 — 当前待办

启动场景与工程配置已由脚本生成并校验通过（`pnpm validate:scene`）。
剩下只有构建这一步需要你做：命令行构建会与已打开的编辑器抢工程锁，
实测连 `--help` 都会挂住，所以不宜由脚本代劳。

### 第 1 步：刷新资源

编辑器中 `Cmd+R` 刷新。确认 `assets/bundles/start-scene/Boot.scene` 出现，
双击能打开，节点树为：

```text
Boot
├─ Canvas          [UITransform 1080×1920, Canvas, Widget]
│  └─ Camera       [Camera 正交, orthoHeight 960]
└─ AppRoot         [UITransform, AppRoot, ViewportAdapter]
   └─ SafeArea     [UITransform, Widget 四向对齐]
```

选中 `AppRoot` 节点，确认属性检查器里：

- [ ] `AppRoot` 与 `ViewportAdapter` 两个组件都在，没有显示为「丢失的脚本」
- [ ] `ViewportAdapter` 的 `safeAreaRoot` 指向 `SafeArea` 节点

**`AppRoot` 必须在场景根层级，不能拖到 `Canvas` 下面。**
`cc.d.ts` 写明「目标节点必须位于层级的根节点，否则无效」——
挂到 `Canvas` 下 `director.addPersistRootNode` 会静默失效，
跨场景常驻功能形同虚设且不报错。`pnpm validate:scene` 会检查这一条。

### 第 2 步：确认 Bundle 配置

五个目录已由 `pnpm config:bundles` 配好，检查属性检查器中是否生效：

| 目录 | Bundle 名称 | 优先级 |
|---|---|---:|
| `start-scene` | `start-scene` | 8 |
| `shared` | `shared` | 7 |
| `camp` | `camp` | 5 |
| `map_01` | `map_01` | 3 |
| `map_02` | `map_02` | 3 |

其余包（`career_base`、`career_tier_1`、`map_03`–`map_05`）待对应阶段再建目录，
清单已在 `services/BundleManifest.ts` 声明完整。

### 第 3 步：构建

构建发布 → 平台 Web Mobile → 构建。

`settings/v2/packages/builder.json` 已预置构建选项（起始场景 UUID、
竖屏、`merge_all_json` 压缩、md5Cache），面板里应能直接看到。

### 完成判定

- [ ] 构建成功，无报错
- [ ] 产物能在浏览器打开，显示深色背景的空场景（还没有 UI，这是预期的）
- [ ] 控制台无 `AppRoot 尚未初始化，请确认启动场景挂载了 AppRoot 节点`
- [ ] `build/web-mobile/index.html` 含 `viewport-fit=cover`
      （证明 `build-templates/` 覆盖生效）
- [ ] 首屏网络请求里没有 `map_01`／`map_02` 的资源（`#17` 的验收前置）

构建报错的话把日志贴出来。

## `#18` 竖屏适配真机验证 — 阻塞于 `#6c`

`ViewportLayout` 的算法有 24 个单测，但 `ViewportAdapter` 至今没在引擎里跑过。
构建成功后用真机或浏览器设备模拟验证：

- [ ] 地址栏伸缩时 `SafeArea` 跟随（`canvas-resize` 回调生效）
- [ ] iOS Safari 刘海机型上 `SafeArea` 避开刘海与底部横条
- [ ] 720×1280 与 1080×1920 下像素图无抖动（整数缩放生效）
- [ ] 横屏时显示「请将设备竖持」提示

安全区读不到的话先查 `build/web-mobile/index.html` 里有没有 `viewport-fit=cover`——
少了它 `env(safe-area-inset-*)` 恒为 0，适配会静默失效。

## 已由脚本完成的部分

| 命令 | 作用 |
|---|---|
| `pnpm gen:scene` | 生成 `Boot.scene`（22 个条目，含引用双向配对校验） |
| `pnpm config:bundles` | 配置五个 Bundle 目录的 `userData`（幂等） |
| `pnpm validate:scene` | 校验脚本 UUID、组件挂载、根层级、起始场景一致性 |
| `pnpm check` | typecheck + 246 单测 + 数据校验 + 场景校验 |

场景为何能手写：格式是 `__id__` 数组下标引用，自定义组件用压缩 UUID 作
`__type__`。压缩算法（保留前 5 字符，其余每 3 个十六进制字符编码为 2 个 Base64
字符）已用 Cocos 自带 taxi 模板的已知样本对照验证：

```text
98dcd425-f068-4460-b251-1bc6a9f8487e → 98dcdQl8GhEYLJRG8ap+Eh+   ✓
```

工具见 `tools/uuid-compress.mjs`。

**脚本 `.meta` 仍然只能由编辑器生成**（UUID 须由编辑器分配）。
新增脚本后让编辑器扫一次即可，`validate:scene` 会在 UUID 漂移时报错。
