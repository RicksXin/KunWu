## 1. 0.1 产品基线

《昆吾禁地》0.1 是竖屏 2D 像素修仙单机 Web 游戏的首个完整试玩版本，目标游玩时间
8–12 小时，中位目标约 10 小时。

当前产品边界：

- 四张完整固定地图，并保留 `map_05` 为后续锁定入口。
- 石岩、陆清、白灵、墨言四名固定修士；不开放招贤台和随机招募。
- 剑修、法修、医修、潜修四个初始职业，每个职业两个筑基分支。
- 等级上限 Lv30；覆盖炼气、筑基、结丹。
- 每名修士始终拥有三个当前主动技能；0.1 共 36 个稳定技能 ID。
- 四个装备槽：武器、防具、饰品一、饰品二；四图共 44 件装备定义。
- 每图一个 Boss，共四个；地图 4 Boss 是 0.1 最终 Boss。
- 一条四章主线和四条支线。
- 不包含联网、PvP、充值、付费货币、世界 Boss、日常任务、随机招募和元婴以上内容。

详细版本范围以
[《0.1 版本完整策划案》](0.1策划草案/15_0.1版本完整策划案_草案.md)为源头。

1. 用户最新明确确认。

4. 已完成 0.1 重整的对应 PRD。

未完成重整的旧 PRD 与策划冲突时，必须标记为待同步，不允许程序、美术或验收人员自行

## 4. 与 Demo 文档隔离

- `Docs/PRD/` 只描述 0.1 试玩版本的产品化需求。
- `Docs/Demo/` 只描述 D0/D1 样机、公开 Demo 的范围、技术、进度和阶段验收。
- 两套文档可以复用同一实现，但不得互相充当范围、进度、需求编号或验收事实源。
- PRD 不使用 P1/P2 Demo 阶段编号；0.1 试玩需求统一使用 `V01-<MODULE>-<SERIAL>`。
- Demo 裁剪或进度变化不反向修改 0.1 策划与 PRD；0.1 策划变化也不自动创建或修改
  Demo 任务。
- 需要同步同一实现时，只在对应实施待办中记录引用，不复制规则后各自改写。

## 5. PRD 编写规则

每个 0.1 PRD 必须包含：

- 对应的 0.1 策划事实源链接。
- 本模块范围与明确不做项。
- 页面与交互要求。
- 正常流程、失败反馈、原子操作和刷新恢复。
- 稳定 ID、数据表或配置来源，但不在 PRD 另造策划数值。
- `V01` 功能需求编号和可执行验收条件。

策划中的背景、数值、技能、装备、敌人或剧情发生变化时，先改对应策划分册，再同步现有
PRD。PRD 仅改变页面布局、操作方式、异常处理或验收表达时，不反向修改策划。

## 6. 后续数据表

以下内容从策划分册生成并由 Schema 校验，不继续在多个 PRD 中分别维护副本：

- 灵根倍率、职业成长、等级成本与突破材料。
- 技能 ID、目标、倍率、状态和自动策略。
- 装备属性、特效、配方与来源。
- 地图坐标、固定对象、事件和出口。
- 敌人、Boss、遭遇和掉落。
- 任务节点、对话、变量、奖励和解锁。

数据表必须使用稳定英文小写蛇形 ID，并能追溯到对应策划分册和 `V01` 产品需求编号。
