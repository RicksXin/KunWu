## 1. 产品基线

《昆吾禁地》是一款竖屏 2D 像素风、营地经营与方格探索相结合的修仙题材单机 Web 游戏。

玩家在营地中生产资源、招募和培养修士、打造装备，再组织四人队伍携带有限补给进入固定坐标的大型方格地图。地图以迷雾遮蔽，事件、敌人、资源和副本散布在格子上；战斗采用无前后排的半即时策略机制。

当前产品边界：

- 首个完整版本包含 5 张野外地图，并为后续扩展到 30 张以上保留数据结构。
- 队伍固定为 4 人，不设置前后排；只有嘲讽等状态能强制影响单体目标选择。
- 角色拥有力量、魔力、技巧、速度、体质、护甲、抗性七维属性。
- 首批包含 6 个基础职业、12 个一转职业，每个职业节点固定 3 个主动技能。
- 地图 2 起，每张地图至少包含主线小 Boss、支线 Boss 和野外 Boss。
- MVP 不包含联网多人、PvP、广告和充值系统。
- 未取得原作书面授权前，公开版本仅使用原创名称、剧情、角色和美术资产。

## 3. 文档归属与冲突处理

每类规则只指定一个“事实源”，其他文档只能引用，不能复制后改写。

| 规则类型 | 唯一事实源 |
|---|---|
| 版本范围、阶段目标、删减顺序 | PRD-00 |
| 资源产出、工人消耗、建筑升级 | PRD-02 |
| 职业、品质、七维、转职 | PRD-03 |
| 战斗公式、技能执行、目标规则 | PRD-04 |
| 地图格、坐标、迷雾、补给、跨图 | PRD-05 |
| 敌人、Boss、战斗 AI 和掉落归属 | PRD-06 |
| 物品、装备、仓库、炼器和交易 | PRD-07 |
| 任务状态、剧情解锁和 NPC | PRD-08 |
| 页面、交互、引导和反馈 | PRD-09 |
| 技术结构、存档、性能和兼容性 | PRD-10 |
| 资产规格、动画与特效交付 | PRD-11 |
| 测试方法、验收口径和发布门禁 | PRD-12 |

如果文档之间发生冲突：

1. 先以唯一事实源中的最新版本为准。
2. 再检查 PRD-00 是否改变了阶段范围。
3. 涉及数值平衡时以外置数据表为准，但必须在对应 PRD 记录表名和版本。
4. 仍不能判断时建立变更单，不允许程序或美术自行选择一种解释。

## 4. 分阶段落地

| 阶段 | 目标 | 核心交付 | 进入下一阶段的最低条件 |
|---|---|---|---|
| P0 纸面验证 | 验证核心循环与经济约束 | 流程原型、资源模型、地图纸面推演、战斗模拟 | 核心循环可在 10 分钟内讲清，关键数值无死锁 |
| P1 技术样机 | 验证 Web 技术链路 | 大厅壳、方格移动、迷雾、四人战斗、基础存档 | 主流浏览器可连续运行，流程无阻断错误 |
| P2 Demo | 验证是否“好玩且可展示” | 地图 1 完整、地图 2 预览、6 基础职业、战士双转职、30–45 分钟内容 | 玩家能独立完成首次招募—出征—战斗—回城 |
| P3 MVP | 形成可发布的完整单机版本 | 5 张地图、12 个一转职业、13–15 个 Boss、约 120 件装备、约 60 个任务 | 主线可通关，8–12 小时内容完整，存档和性能达标 |
| P4 扩展 | 增加长期内容与系统深度 | 新地图、高阶转职、更多装备与事件 | 依据 MVP 数据立项，不预先承诺上线范围 |

详细范围与停止条件见 [PRD-00](PRD/00_产品范围与阶段路线图.md)。

## 5. 推荐阅读顺序

策划先阅读 PRD-00、02、03、04、05、06、07、08；程序先阅读 PRD-00、10，再按开发模块阅读对应系统；美术与动画先阅读 PRD-11，再结合 PRD-03、05、06；UI 设计阅读 PRD-01、09；测试以 PRD-12 为入口并引用所有系统验收条目。

开发一个功能前，至少需要确认：

- 所属阶段与优先级。
- 对应需求编号。
- 正常流程、边界条件和失败反馈。
- 数据配置位置与默认值。
- 所需美术、动画、音效或特效资源。
- 可操作的验收步骤。
