## 1. 本轮重建结论

正式需求仍按玩家可识别页面维护，但不再让每个页面占用一个文件。本轮按相邻入口、数据事务和
实现链路合并为六个模块分册；每个页面保留稳定锚点，并继续统一维护：

- 上游事实源与明确边界；
- 入口、退出、返回栈和信息架构；
- 默认、加载、空、禁用、锁定、错误及业务特有状态；
- 正常流程、失败反馈、原子保存与刷新恢复；
- 稳定命令、数据来源和 `V10-<PAGE>-xxx` 验收；
- Figma 必需稿件、组件状态、素材引用和缺口；
- 1.0 明确不做项。

页面编号、页面 ID、命令和 `V10-*` 验收编号均不因合并改变。旧系统型 PRD、逐页文件和退役跳转页
只由 Git 追溯，不继续留在正式目录制造第二套入口。

## 2. 1.0 产品边界

- 四张完整固定地图：`map_01` 至 `map_04`；`map_05` 只保留后续锁定入口。
- 石岩、陆清、白灵、墨言四名固定剧情修士，不存在第五名随机修士。
- 招贤馆只解锁建筑与“后续版本开放”说明；不做候选、刷新、招募、改名、遣散、馆级或容量。
- 四个初始职业，每个职业两个筑基分支；结丹沿已选路线晋升；1.0 上限 Lv30。
- 四个装备槽：武器、防具、饰品一、饰品二；装备没有等级。
- 六档品质：凡品、精制、上品、珍品、法宝、古宝。
- 非古宝装备以铁胚决定品质、蓝图决定 1/2 器纹槽；器纹是七维唯一来源并永久固定。
- 炼器坊共 24 级，只消耗灵木升级，承载铁胚、器纹、装备、工具、突破物和永久探索强化。
- 两座可选主动资源副本：回火矿窟主产灵石，镇魂残响主产魂晶；不挑战也能完成主线。
- 第 2、4 位主线 Boss 首杀魂魄交乌婆后固定获得上品封坛军魂甲、珍品银翅魂衣。
- 交易行只买不卖，固定为常备栏＋6 格随机栏；普通非古宝装备只在百宝库分解。
- 1 条四章主线、5 条支线和一个完成身份揭示与外层封印的 1.0 阶段结局。

不包含联网、PvP、充值、付费货币、日常、挂机派遣、离线战斗、元婴以上可玩成长、装备等级、
强化失败、器纹替换、整件重铸、锻纹尘和古宝打造。

## 5. 数值落地规则

1.0 已启用的成本、产量、概率、倍率、持续时间、掉率、商品栏位和刷新周期已冻结。新 PRD 遵守：

- 玩家需要预览、确认或验收的关键值写入对应页面；完整调参表继续从数值分册和版本化数据表读取；
- UI 预览、服务扣除/产出和验收必须使用同一配置结果；
- 配置缺失时禁用相关操作并显示“数据未配置”，不得填 0、临时值或可执行占位值；
- 后续境界版本未投放的辅材可显示“未开放”，不属于 1.0 数值缺口。

## 6. Figma 与 ArtAssets 交付

- Figma 只决定用户确认后的目标视觉，功能与交互仍以 PRD 为准。
- 每页必须交付默认、加载、空、禁用、锁定、错误和该页特有业务状态。
- 所有页面使用 `375×817`；营地全景逻辑宽 `1050`，固定 HUD 不横滑。
- 只有标记 `Approved` 的节点可实现；当前唯一明确批准的通用组件是 `Panel Item V2`。
- 每页的素材缺口已链接到 [ArtAssets 总索引](ArtAssets/README.md)；PNG 制作清单不复制进 PRD。
- 美术资源必须同时记录逻辑尺寸和交付尺寸，动态文案不得烘焙进 PNG。

## 7. 需求编号、变更与验收

- 页面需求统一使用 `V10-<PAGE>-<SERIAL>`；跨页共同需求使用 `V10-CORE` 或 `V10-COMMON`。
- 策划规则变化必须先修改上游策划，再同步受影响页面；纯页面交互变化只改 PRD。
- 实现前按页面补客户端/服务端/API/Local Adapter 技术设计，并反向链接需求编号。
- 任何资源、物品、修士、任务、出征或唯一奖励操作必须原子、幂等并可刷新恢复。
- 具体验收由用户按各页清单执行；本入口不把代理运行检查、构建或预览当作自动默认步骤。

## 8. 与 Demo 和后续版本隔离

- 本目录不出现 D0/D1/P0/P1/P2 的范围、进度或验收编号。
- 0.1 Demo 可以裁剪同一实现，但不能覆盖 1.0 产品规则。
- 招贤馆未来随机修士、C05 以后地图、元婴以上成长和完整游戏三种宏观结局只在其上游长期策划维护，
  不用灰色按钮、伪数据或隐藏命令提前做进 1.0。
