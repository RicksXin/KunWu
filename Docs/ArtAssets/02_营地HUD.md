## 4.3 UI 共用输出要求与提示词

#### 4.3.1 输出要求

- 本项目的 UI 唯一设计基准和玩家可见窗口为 `375×817`。顶部和底部 HUD 固定在该视窗内，不随 2.8 倍大厅背景横滑。
- 下文每张素材同时标注两种尺寸：“逻辑尺寸”是放入 `375×817` UI 时的显示尺寸；“最终 PNG 尺寸”是实际交付文件尺寸，本批统一使用 `@3x`。
- 例如头像逻辑显示为 `50×50`，最终交付 PNG 为 `150×150 px (@3x)`；导入 Cocos 后必须保持 `50×50` 的 UITransform 显示尺寸，不能按原图像素显示成三倍大小。
- `1080×1920` 和 `360×640` 均不再用于本清单的 UI 尺寸推导。
- 每个资产单独输出透明 PNG，不能嵌入 Base64，也不能贴在展示板或棋盘格背景上。
- GPT Image 若不能直接输出提示词指定的精确尺寸，可先生成更大的高清母版，再离线等比缩放、裁切或补透明边，最终文件必须严格符合对应的 `@3x` PNG 尺寸。
- 横向底板可先生成宽幅大图，最终按指定尺寸交付，并在运行时配置九宫格边框。
- 图标主体居中，占透明画布约 70%–80%，同组图标的视觉体量一致。
- 底板中央必须保留干净区域，方便 Cocos 放置 Label。
- 普通、按下、禁用三态必须保持完全相同的外轮廓和透明边界。
- 运行时使用 Nearest 过滤；最终缩小时保证像素簇清晰。
- 不在图片中画名称、数字、倒计时、红点、锁形文字或“未开放”文字。
- 触控热区由 Cocos 节点保证至少 `48×48dp`，不需要把透明热区画成可见边框。

## 4.6 推荐制作顺序

1. 先截取 `camp_hud_layout_375x817.png`，确认顶部和底部实际留白。
2. 先生成头像框、资源格、任务底板、普通系统按钮和灵石底板，统一材质语言。
3. 生成灵粮图标并确认像素密度，再用它作为其余资源图标的风格参考。
4. 生成设置图标并确认线条粗细，再用它作为其余四个系统图标的风格参考。
5. 用普通按钮原图编辑出按下态和禁用态，禁止重新自由生成。
6. 最后生成封印遮罩，并在大厅灰盒截图上合成检查。
7. 所有高清母版保存到 `ArtSource/`；裁切、缩放和压缩后的 `@3x` 运行时 PNG 放入对应 Cocos Bundle，并由编辑器生成 `.meta`。
8. 导入后将各 Sprite 的 UITransform 设置为表格中的 375 基准逻辑尺寸，禁止直接按 `@3x` PNG 原始像素尺寸显示。

## 4.7 顶部与底部 UI 验收

1. 顶部是否按顺序显示灵粮、灵木、玄铁、灵晶、庚精五种互不混淆的图标？
2. 底部灵石是否与顶部灵晶在轮廓、颜色和材质上明显不同？
3. 设置、成就、排行榜、邮件和日常是否仅凭剪影就能区分？
4. 成就、排行榜、邮件、日常是否明确处于禁用/封印状态，同时仍能看出原图标？
5. 普通、按下、禁用三态是否保持完全一致的尺寸、轮廓和透明边界？
6. 所有底板是否保留干净文字区，并可做九宫格拉伸？
7. 是否没有把资源名称、数值、任务文案、倒计时或“未开放”文字烘焙进图片？
8. 是否完全隐藏宝石、充值、礼包、广告、加号购买按钮和其他付费入口？
9. 顶部与底部 HUD 在 `lobby_left`、`lobby_mid`、`lobby_right` 三种横滑位置中是否保持固定？
10. UI 叠在当前营地背景上是否具有足够对比，同时没有大面积遮挡天空和建筑？
11. 每张 PNG 的实际像素尺寸是否与表格中的 `@3x` 尺寸完全一致，UITransform 是否与逻辑尺寸完全一致？
12. 系统按钮和主线任务的可见图片是否分别置于至少 `48×48`、`250×48` 的交互节点内？
13. 图标缩小到 25% 后是否仍清楚，透明区域是否为真实 Alpha？
14. 是否没有直接复制参考截图中的图标、边框、按钮花纹和付费栏？
