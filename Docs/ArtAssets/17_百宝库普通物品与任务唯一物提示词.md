## 1. 制作边界

本分册只整理普通物品、加工品、工具、突破物、任务物和唯一物的 GPT Image 图标提示词。
装备主体读取 12 分册，战斗技能与状态读取 05 分册，五种生产资源和灵石/魂晶的全局图标继续
复用现有同一文件，不在本分册重画。

- 普通物品包括资源包、野外食物、通用/区域材料、铁胚、器纹、工具、突破物和永久强化主体。
- 任务物只收录剧情中实际持有、提交、保管、选择归属或进入任务保护区的物件。
- 剧情 Flag、完成标记、隐藏坐标、NPC 证词、回看记录、配方解锁和蓝图状态不是物品，不生成背包图标。
- 任务物、唯一核心和 Boss 魂魄不可出售、分解、丢弃或因阵亡损失；保护状态由 UI 叠加，不画进主体。
- 蓝图是永久解锁记录。炼器坊只使用两张通用蓝图卷图标，不为每一张蓝图重复制作卷轴。
- 五种生产资源、灵石和魂晶不占百宝库空间，但在奖励、配方和页面中继续复用全局图标。
- 普通物品不套装备六品质框；铁胚按五档配方表达自身档位，资源包的下品/上品/特级/仙品只表达
  包装与数量层级，两者都不能复用六档装备品质框。
- 所有文字、数量、持有上限、用途、任务名、品质、保护、待处理和缺少材料状态由运行时组件显示。
- 绝对禁止绿色键色背景；所有异形主体必须交付真实 RGBA Alpha。

| 任务物/唯一物 | `48×48` | `144×144 @3x` | `assets/bundles/common/items/quest/` |

运行时组合固定为：

```text
通用方形图像槽或列表 Item 底板
→ 本分册生成的透明物品主体
→ 数量/名称/用途 Label
→ 任务保护、待处理、不可用等独立状态标记
```

任务物不能靠主体上的感叹号、锁、盾牌或金框表达保护；同一图标在任务追踪、战利品结算、百宝库
详情和配方预览中复用。

## 4. 普通物品与任务物共用提示词

每次复制本段，再追加第 5 或第 6 节对应行的 `Specific subject`。

```text
Use case: stylized-concept
Asset type: 原创竖屏2D像素修仙游戏《昆吾禁地》的单个物品主体图标，用于百宝库、炼器坊、任务追踪、战利品结算和物品详情
Input images: 图片1只用于确认375×817页面中的图标层级、明暗和信息密度；图片2用于确认48×48逻辑显示、40×40总内容安全区、普通物品主体不超过34×34和透明留白；图片3是最强的项目图标风格参考，只继承硬像素边缘、左上受光、色盘和材质简化；图片4只证明任务保护由运行时UI叠加，严禁把锁、感叹号、保护框或文字画进主体；若提供图片5，只参考配方行缩小后的清晰度。所有输入图片都不是编辑目标
Primary request: 只生成下方 Specific subject 指定的一个物品图标。先依靠主体剪影和2至4处关键材质识别物品类别，不依赖名称文字、数量、颜色光环或说明面板
Style/medium: 2D pixel art，硬边缘、清楚像素簇、受控阶梯边，无平滑矢量感；中国修仙题材，使用粗布、旧纸、石木、旧铜、乌铁、玉质、灵晶和克制符箓结构，古朴、低饱和、有使用痕迹
Composition/framing: 正方形画布，单个主体严格居中。普通物品的主要实心轮廓约占画布宽高58%至72%，建议收进34×34逻辑像素主体区；开山镐、长令牌等细长尖端最多延伸到40×40总内容安全区。画布四周保留均匀透明边。成组定义本身是“两份命令、三张拓片、一包干粮”等时可画成一个紧凑组合，但不能额外添加无关物件
Readability: 最终逻辑尺寸48×48，交付144×144像素@3x。缩小后先看清大轮廓，再看清主要材质；不依赖可读文字、密集刻纹、细烟、散粒子、柔光或半透明雾辨认
Lighting and palette: 左上克制硬高光、右下短硬暗部；低饱和黛青、深木、灰绿、米白、乌铁、旧铜和少量物件自身辨识色。不要用整圈彩色外发光表达稀有度
Output constraints: 必须输出一张144×144像素RGBA PNG，主体之外为真实Alpha 0，边缘保持硬像素。只输出一个物品主体，不要通用图像槽、品质框、任务框、卡片底板、按钮、展示台、接触投影、地面、场景、页面截图、素材拼版或第二个无关物品
Transparency constraints: 禁止#00FF00和任何绿色、蓝色、白色、黑色或棋盘格键色背景；不得先生成纯色底再抠图。没有真实RGBA透明背景即判定失败并重新生成，不能导入项目
System separation: 不画数量、名称、物品ID、用途、价格、等级、品质文字、持有上限、锁、感叹号、任务角标、选中、待处理、可提交、已使用、配方数量或奖励光柱。任务物的保护与唯一性全部由运行时UI说明
Text constraints: 纸张、令牌、碑拓和封印图只使用无字压线、几何阵纹、撕痕、印泥块和材质差异，不生成可读汉字、伪汉字、字母或数字
Avoid: 西式药水瓶、金币袋、宝箱、礼品盒、扑克牌、现代包装、塑料袋、拉链包、现代工具、枪械、欧洲纹章、十字医疗标、App图标、Q版贴纸、3D渲染、PBR材质、写实照片、厚涂、油画、体积光、景深、柔焦、抗锯齿、文字、水印、Logo
```

若 GPT 先返回较大母图，只能使用普通图像编辑工具等比裁切并以 Nearest 缩放为 `144×144`；
本流程不使用 Python 脚本，也不允许补绿色背景辅助抠图。

3. 多件特定装备只写“首件核心”，没有逐件冻结核心显示名、物理形态和稳定 ID。本文只为石灵核心、
   引雷石、蜃光镜心、禅珠残片、五火法轮残胚、剑灵锋、铸灵核心等已命名对象写正式提示词；
   其余首件核心不得用同一枚发光问号石占位交付。
4. 大部分任务物尚无稳定 `item_id`。在上游内容表冻结前可以按表内美术文件名生成并由用户完成
   视觉 Review/Approved，但导出清单的业务 ID 必须保持 `TBD-upstream`，不得写入 Cocos 配置或存档映射。
5. “血焰留痕”、三条封链修复状态、身份线索阶段、残魂遗愿完成和配方解锁都是 Flag/状态，

## 8. 生成顺序与验收

### 8.1 推荐顺序

1. 先做山行干粮、引灵砂、归营符、石灵核心四张，锁定食物、散料、纸符和任务核心四类基线。
2. 生成五种下品资源包，再以同一资源主体逐级制作上品、特级、仙品包装，先确认包装升级不是品质换色。
3. 完成普通/区域材料、工具、突破物，再生成五档铁胚和七种器纹。
4. 任务物先做裂纹营印、重封令/抽阵令、旧账簿、本命元牌和破损五鬼袋，确认文件、令牌、书册、玉牌、法袋的轮廓区分。
5. 再做装备前置核心、两枚 Boss 魂魄和跨时态物件；未冻结业务 ID 的图片可以完成视觉评审，
   但导出映射继续标记 `TBD-upstream`。

### 8.2 单图验收

- 所有图为 `144×144` RGBA PNG，主体外 Alpha 为 `0`；没有绿色键色、纯色底、棋盘格、投影板或半透明雾边。
- 缩到 `48×48` 后仍能先辨认食物、材料、工具、文件、令牌、核心、法袋或魂魄大类。
- 没有通用槽、品质框、任务框、锁、感叹号、数量、文字、价格、等级、星级或奖励光柱。
- 两份命令、不同通行令和多种核心依靠结构与材质区分，不只改颜色或增加光晕。
- 文件类没有伪汉字；Boss 魂魄与普通魂晶、器灵残片、残翅本源三者轮廓明显不同。
- 任务物主体本身不承担“可提交/受保护/唯一”状态；叠加运行时标记后关键轮廓仍清楚。

### 8.3 同屏与语义验收

- 五种资源包在四种包装档位下同时能辨认资源种类和包装级别；不会被误认成装备六品质。
- 凝露草只表现剧情救治材料，不像通用回血药；凝丹灵草与降尘丹、普通凝露草可区分。
- 归营符、探灵镜、开山镐分别表达归营、探查、破岩工具，不与探索操作按钮本身混用。
- 铁胚五档保持同一主体家族并通过结构升级辨认；器纹七种不出现品质、数值或可拆镶嵌暗示。
- 有意识的五名残魂没有被画成五种可消耗材料；Boss 魂魄明确是唯一魂性残印。
- 所有 `TBD-upstream` 即使视觉已经 Approved，业务 ID 冻结前也不能由文件名直接生成配置或存档 ID。
