Excel 中的 `ART-HALL-001` 后景和 `ART-HALL-002` 地面道路，在本轮合并为一张完整背景。Cocos 中只需要：

```text
完整横向背景
    + 独立建筑 Sprite
    + 独立传送阵 Sprite
    + 固定顶部/底部 HUD
```

背景尺寸口径：

- UI 设计视窗为 `375×817`。
- 横滑有效宽度为 `375×2.8=1050`，所以大厅有效内容区是 `1050×817`。
- 为避免不同设备裁切时露边，最终背景画布建议使用 `1152×896`。
- `1152×896` 中央保留 `1050×817` 安全内容区：左右各多 `51px`，顶部约多 `39px`，底部约多 `40px`。
- 多出的区域只是背景出血，不摆放建筑落点，也不计入横滑范围；Cocos 横滑逻辑宽度仍为 `1050px`。
- 顶部和底部 UI 叠加在背景之上，不画进背景图片。

锁定态、未开放远景和前景装饰先不阻塞首批出图：

- 七座建筑的锁定态可以在主图确认后，通过编辑同一张建筑图继续生成。
- 竞技场、遗迹、圣迹、教会暂不制作。
- 旗杆、木箱、药篓、走动杂役等前景装饰放到下一批。
- 岑守一头像和资源/UI 图标属于独立批次。

## 3.4 完整大厅背景提示词

对应 Excel：`ART-HALL-001`、`ART-HALL-002`

输入：`lobby_left.jpg`、`lobby_mid.jpg`、`lobby_right.jpg`，以及当前 Camp 全景布局截图。

```text
生成一张完整的超宽营地大厅背景。最终交付画布为1152×896，中央1050×817是实际游戏有效内容区，横向宽度相当于2.8个375px竖屏视窗。画布四周多出的区域只延展天空、山体和地面纹理，用作安全出血，不放建筑落点或重要地标。

背景中同时包含天空、封印山体、远处细瀑布、冷青雾云、灰褐营地地面、风化石阶、道路、坡地、低矮挡墙、小溪和建筑落脚台基。

画面从左到右必须连续，横滑到两端也不能露出空白。中央远山略高，左右自然延伸。地面需要预留八个自然落点：左侧三处向左下递进，中部上方和下方各一处，右侧三处向右下递进。

背景里不要画任何正式建筑、传送阵、建筑阴影、人物、建筑名称、点击标记或HUD。建筑和传送阵之后会作为独立透明Sprite叠加。道路需要能连接各个落点，但不能让玩家误以为角色可以在大厅自由行走。
```

输出文件：

`env_camp_panorama_bg.png`

验收：

- 交付画布为 `1152×896`，中央 `1050×817` 有效内容区构图完整。
- 四周出血区只有自然环境延展，不出现建筑落点和重要地标。
- 左右边界没有空白和明显拼接断层。
- 八个建筑落点不会悬空。
- 背景中没有任何建筑和 UI。

## 3.5 建筑共用输出要求

生成每座建筑时，输入已经确认的 `env_camp_panorama_bg.png`，用于统一色盘、视角和光照。

```text
输出单座建筑Sprite，透明背景，最终放入320×240逻辑框，底部中央锚点。建筑本体占画布宽度约80%、高度约85%，四周保留透明空间。保持与输入大厅背景相同的镜头、像素密度、左上方受光和地面接触角度。只画建筑及其不可分离的小部件，不画大片地面、远山、其他建筑、文字和UI。
```

> GPT Image 不一定能直接输出精确的 `320×240`。可先输出较大透明 PNG，再裁切、像素化和缩放到目标逻辑框。

## 3.8 建筑布局

独立素材在 Cocos 中按以下关系摆放：

| 区域 | 建筑关系                          |
| -- | ----------------------------- |
| 左侧 | 招贤馆在中间靠左；百宝库在其左下；还魂殿继续位于百宝库左下 |
| 中部 | 议事殿在中上方；传送阵在中下方               |
| 右侧 | 交易行在中间稍靠右；炼器坊在其右下；灵源院继续位于炼器坊右下 |

默认中部视窗中，议事殿和传送阵必须完整可见，招贤馆和交易行需要可识别。

## 3.9 后续锁定态

首批 9 张图确认后，再把每座建筑原图交给 GPT Image 编辑：

```text
把输入建筑编辑为剧情尚未解锁状态。保持透明背景、画布、镜头、建筑轮廓、占地和底部锚点完全不变。关闭大部分灯火，增加木质封板、交叉封条、少量脚手架或克制的朱砂禁制。仍需看得出是哪座建筑，不能只做灰度或降低亮度。不要添加锁形UI图标、文字、红点或按钮。
```

锁定态文件使用 `_locked` 后缀，例如：

`env_camp_building_yi_shi_dian_locked.png`

## 3.10 快速验收

1. 背景是否只有一张，交付尺寸为 `1152×896`，并完整覆盖中央 `1050×817` 有效内容区？
2. 背景中是否没有建筑、传送阵和 UI？
3. 七座建筑和传送阵是否均为独立透明 PNG？
4. 是否没有照搬参考截图中的 UI、建筑轮廓和哥特构图？
5. 所有建筑的镜头、像素密度、色盘和受光方向是否一致？
6. 建筑缩小到 25% 后是否仍能凭轮廓区分？
7. 透明区域是否是真实 Alpha，而不是画出来的棋盘格？
8. 是否存在抗锯齿、模糊边缘、文字、水印或多余按钮？
