### 3.1 地图重制目标：导航底图优先

地图首先是承载队伍、资源点、敌群、Boss、副本入口和跨图出口的导航底图，不是一张需要单独欣赏的高精度
风景插画。当前方案的失败点是“每个 Tile 都有裂纹、碎石、草叶、光点和局部高光”，造成整图处处高频，覆盖标记放上去后
失去轮廓。新版必须按以下层级重制：

- 可玩区域约 `75%–85%` 使用低饱和、低对比、大面积连续平面，只保留能区分道路、地面、阻挡与高差的大块面。
- 普通地面不允许每格随机散布碎石、草叶、裂纹、灵光、铜屑、尸骸、落叶或独立阴影。少量材质变化必须组成大而稀疏的色块，
  不得形成满地噪点。
- 细节预算只留给一、二级地标、主要进出口、Boss 区轮廓、封链/阵眼等路线导航结构；走路通道、交叉口和普通资源区必须保持平静。
- 普通可行走底面只使用 `3–5` 个接近明度的基础色；全图功能色克制使用。暖白、朱砂、雷蓝、炉橙、封链青银等高对比色只用于关键地标与状态反馈。
- 不为每个 Tile 画黑色闭合外轮廓，不显示棋盘格或网格边界。区域区分依靠大轮廓、高差边、道路宽度与低频明暗，不依赖密集纹理。
- 每个固定对象坐标所在的 `48×48` 逻辑格，中央至少保留一块约 `32×32` 的“标记静区”：只能有单一大色面和极弱材质变化，不放高光点、裂纹交点、小植物、尖锐黑影或与标记同色的点状装饰。
- 普通背景不得靠更亮的图标外发光、白色贴纸边或黑色厚底盘补救可读性。先让底图安静，再使用第 4 节的正常覆盖标记。

#### 3.1.1 纯俯视平面 2D 视角红线

本项目的野外地图不使用 `2.5D`、斜俯视或等距视角。“高差”是关卡阻挡和路线语义，
不表示需要画出立体平台、山崖侧面或可见厚度。生成时必须同时满足：

- 摄像机固定为接近 `90°` 垂直向下的正交投影；画面没有地平线、消失点、近大远小、透视收窄或斜向缩短。
- 所有可行走区域都是一层完全平整的 2D 色块；不显示地面厚度、台阶立面、平台侧壁、崖壁侧面、深坑内壁或向下的空间透视。
- 高差、阻挡与不可走区只用平面轮廓、边界线、局部遮挡关系和大色块区分；不用立体台地、悬浮岛或立体沟壑表达。
- 建筑、山门、阵眼、封链和其他地标使用平面图形或纯俯视顶部剪影；不显示大面积正立面、侧面、厚度、倒角或拱门内部纵深。
- 光影只允许极弱的平面明暗分区；不要体积光、环境遮蔽、边缘受光、材质高光、物体投影或用阴影塑造体积。
- 任意一块普通行走区截图都应像一张平铺的 2D 平面图，而不是站在高处向斜下方观看的小型场景或沙盘。

### 3.2 图层与资产分离

```text
低细节地形底层
→ 道路/高差边界/阻挡的平面大轮廓
→ 关键地标与可淡出前景
→ 世界对象棋子
→ 队伍、资源、敌群、Boss、入口等 UI Overlay 标记
→ 迷雾、选中、锁定与路径预览
```

- GPT Image 地图母图只决定地形底层、大轮廓和关键地标的视觉语汇，不把整图直接当成最终可导入资源。
- 最终仍按 `16×16` 源像素 Tile Set、边缘/转角、阻挡、地标、前景与覆盖标记分层交付，不烘焙为一张包含全部对象的大 PNG。
- 队伍、资源点、敌群、Boss、副本入口、出生点和跨图出口均不得烘焙进地图母图，它们必须在简化底图上后置叠加。

### 3.7 纯俯视低细节地图验收线

- 一眼可以确认摄像机是接近 `90°` 垂直向下的正交纯俯视；画面无地平线、消失点、近大远小、斜 45° 等距视角或透视收窄。

- 高差和阻挡仍保留关卡语义，但只通过平面边界、阻挡剪影、局部遮挡和低频色块区分，不通过立体台地、悬浮岛、沟壑纵深或阴影表达。
- 不叠加标记时，玩家仍能靠道路宽度、阻挡轮廓、高差语义边界和一、二级地标完成基本定向；不需要靠满地小物件提示地形。
