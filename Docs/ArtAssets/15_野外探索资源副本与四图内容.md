## 1. 事实源与交付方式

四图轮廓、坐标、地标、对象、敌群与遮挡以 [地图分册](../1.0策划案/地图/README.md) 为准；敌人和
Boss 以 [敌人与 Boss](../1.0策划案/数值/19_1.0敌人与Boss战斗数值_草案.md) 为准；两座资源副本以
[资源副本策划](../1.0策划案/地图/32_可重复资源副本与新修士追赶机制_草案.md) 为准。

美术清单必须从最终地图对象表和敌人内容表生成，不以截图里“看起来有几个”估算。每项记录
`content_id / map_id / state / sprite_path / animation / source / license / status`。

## 2. 世界像素基线

- 世界 Tile 源像素 `16×16`，逻辑显示 `48×48`；Pixel Art 使用 nearest。
- 地图 UI 仍以 `375×817` 视窗设计，Tile 规格不反推 UI 布局。
- 地形、阻挡、前景遮挡、交互高亮和碰撞语义分层交付，不把整张大地图烘焙成一张图片。
- 屋顶、树冠、拱门、前景山石、封链等遮挡层必须有可淡出区域和锚点说明。

## 5. 两座资源副本

### 5.1 回火矿窟

- 入口/副本卡图、回火炉、真假矿脉、运输阵/炉心、过热提示、矿傀/夺宝者、短机制首领。
- 至少一张专属战斗背景，主色与 map_03 一致但突出回火橙光和炉压，不画普通金矿洞。
- 三难度通过徽记/环境层级表达，不为每个难度复制整套无差别背景。

### 5.2 镇魂残响

- 入口/副本卡图、魂印、命灯/封魂节点、真假残响、记忆完整度、阵法投影首领。
- 至少一张专属战斗背景，表现封魂阵与残响投影，不画反复囚禁真实 NPC 灵魂。
- 三难度沿同一阵法逐层增强，区别不只换颜色。

两本都需：基础/中/高三难度徽记、首通标记、重复挑战标记、机制对象 normal/damaged/failed/success
状态和结算卡图。不得出现门票、体力、每日次数、扫荡或挑战词条图标。

## 6. 敌人、精英与 Boss

- 每个最终 `enemy_id` 至少交付世界棋子与静态战斗立绘；行动、受击和阵亡由 Tween/Tint 与
  Sprite Sheet 特效表达。
- 精英不能只在普通敌人头顶加金框；至少有轮廓、部件或武器差异。
- 四个主线 Boss 各需世界态、战斗多阶段变体、关键机制对象、技能特效、受击和阵亡/退场。
- 第 2、4 Boss 的魂魄与魂器由 14 分册交付，本分册只负责战斗掉落表现和首杀标记。
- 两座资源副本投影不能复用已超度 NPC 的完整肖像作为可刷敌人。

## 7. Figma/灰盒输入要求

美术制作前必须提供：

1. 四图 375×817 探索灰盒和完整地图对象标注导出；
2. 地图缩略图、迷雾、对象面板、扎营、归营与失败报告 Approved 稿；
3. 两座副本选择、三难度、战斗机制与结算 Approved 稿；
4. 每种敌人/Boss 的尺寸对照、锚点和战场占位截图；
5. 前景淡出、Tile 拼接、碰撞和动画状态示意。

## 8. 验收

- 四图在无文字时也能通过地形、建筑、色盘和地标区分。
- Tile 无裂缝、错位或线性过滤；前景淡出后路径和对象仍可读。
- 未知迷雾不泄露 Boss、宝箱、敌人和副本入口。
- 敌人/Boss 尺寸、锚点、朝向和碰撞与灰盒一致，动画不越出关键信息安全区。
- 两座副本世界解释、机制对象和奖励视觉互相区分，且没有扫荡/门票/日常语义。
- 最终导出表覆盖地图对象与敌人内容表中的每个 1.0 稳定 ID，无孤儿素材和缺图 ID。
