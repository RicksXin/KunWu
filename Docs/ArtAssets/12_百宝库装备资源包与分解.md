装备定义以 [1.0 装备与掉落](../1.0策划案/数值/18_1.0装备与掉落数值_草案.md) 为准；资源包与材料以
[基础材料与资源循环](../1.0策划案/数值/34_1.0基础材料与资源循环_草案.md) 为准。装备数量从最终内容表生成
导出清单，不沿用旧“44 件”口径。所有装备只有四槽且没有装备等级。

## 3. 资源包、食物与材料

### 3.1 二十个资源包

必须制作 `灵木/玄铁/灵石/灵晶/庚精 × 下品/上品/特级/仙品` 共 20 个稳定图标：

| 项目 | 规格 |
|---|---|
| 逻辑尺寸 | `48×48` |
| 交付尺寸 | `144×144 @3x`，透明 PNG |
| 路径 | `assets/bundles/common/items/resource_packs/icon_pack_<resource>_<tier>.png` |
| 规则 | 同资源保持核心图形一致，档位改变包装层级；不画随机宝箱或装备品质框 |

### 3.2 食物和材料

- 辟谷饼沿用 07 分册；山行干粮、妖狼肉、地龙肉等按最终食物表每定义一图标。
- 五种生产资源图标复用营地 HUD 同一文件，不为仓库重画。
- 引灵砂、照影石、凝露草、凝丹灵草、器灵残片、四象阵砂、魔髓碎屑、古宝残片各需 `48×48` 图标。
- 任务核心、证据和唯一物按剧情/地图内容表逐项登记，不能用统一问号袋占位交付。

## 4. 装备图标

- 每个冻结 `equipment_id` 至少一张 `48×48` 逻辑、`144×144 @3x` 透明图标。
- 同一蓝图不同品质优先复用装备主体，通过运行时品质框表达；只有策划定义外观变化才新增主体图。
- 四槽轮廓必须一眼可分：武器、身着防具、可装在两个饰品槽的饰品。
- 特定装备、两件乌婆魂器和古宝必须有独立主体图，不用普通模板换色。
- 器纹作为叠加槽显示，装备图标本体不烘焙随机器纹、数值或等级角标。

装备导出清单字段：

```text
equipment_id / display_name / slot / icon_path / visual_variant / source_license /
logical_size / export_size / figma_node / cocos_target / status
```

## 5. Figma 前置与状态

- 七分类列表、空、筛选无结果、待处理区和长数量。
- 六品质装备详情、1/2 器纹、固定效果、古宝、任务保护。
- 换装前后比较、饰品槽选择、出征锁定。
- 开包单个/数量/批量/储量不足；分解单件/批量/排除保护/失败。
- `Panel Item V2` 可直接复用；品质框、器纹槽、物品卡仍需单独 Review/Approved。

## 6. 验收

- 20 个资源包在 48×48 下同时可辨资源种类与包装档位，且不会被误认成装备品质。
- 六品质框在灰度下仍可按轮廓/纹样区分；名称由 Label 显示。
- 装备图标不出现 Lv、强化 `+n`、随机词条数或可拆器纹暗示。
- 分解表现只展示材料回收，不展示完整铁胚、完整器纹或锻纹尘。
- 所有任务/唯一物的透明边缘、文件名、来源和许可记录完整。
