## 1. 正式范围

1.0 只使用石岩、陆清、白灵、墨言四名固定修士。正常整备不显示空槽、候选修士或第五人入口。
本页负责：

- 四名修士的生命、灵息、等级/境界、职业和四槽装备摘要；
- 公共灵粮、出征物资、工具和负重；
- `map_01` 至 `map_04` 普通地图选择及 `map_05` 后续锁定；
- 已满足条件的两座资源副本快捷入口；
- 启程确认、阻断原因、唯一出征恢复和提交失败状态。

地图内容图、四图缩略图和副本卡图由
[野外探索、资源副本与四图内容](15_野外探索资源副本与四图内容.md) 统一制作。

## 2. 页面层级

```text
入山整备
├─ 固定四人队伍摘要
├─ 物资装载
│  ├─ 公共灵粮 → 出征灵粮
│  ├─ 归营符及允许的补给
│  └─ 开山镐等单次出征工具
├─ 地图选择
│  ├─ 普通地图
│  └─ 已解锁资源副本快捷入口
└─ 启程确认 / 继续既有出征
```

页面切换应使用同级步骤或内容切换，不通过三层以上模态堆叠完成。

## 3. Figma 正式状态

必须提供：

- 四人正常、单人阵亡、单人灵息不足、装备缺失、数据加载失败；
- 装载为空、正常、库存不足、超重、工具达到上限、任务保护物；
- 四图不同开放组合、`map_05` 后续锁定、资源副本快捷入口未出现/已出现；
- 继续既有出征、启程确认、多个阻断原因、提交中、保存失败；
- 长地图名、长条件、长数字和 375×817 安全区压力稿；
- 从编队到装载到地图选择再返回的完整 Prototype。

地图锁定、修士阵亡、灵息不足和功能禁用必须同时使用图标与文字，不能只降低明度。

## 6. 视觉方向

- 整备面板表现“出征前检查与取舍”，不用抽卡编队、酒馆选人或角色容量视觉。
- 四人卡保持人物身份锚点一致；职业分支与境界由运行时徽记叠加，不为每个阶段重画一张整卡。
- 物资、工具和食物图标跨百宝库、炼器坊、探索页复用，不另画整备专用版本。
- `map_05` 使用明确封印和后续开放语义，不使用“战力不足”或资源不足样式。
- 所有姓名、生命、灵息、负重、成本、地图条件与按钮文字由 Label 渲染。

## 7. 交付输入

正式出图前提供：

1. 编队、装载、普通地图、资源副本快捷入口四张 Approved 页面稿；
2. 四名修士最终人物设定板和卡面裁切安全区；
3. 四图/副本缩略图及地图锁定状态；
4. 已生成卡框、立绘、工具图标的 1:1 合成截图；
5. 触控热区、九宫格边距、Mask 和 Cocos 节点映射。

灰盒只用于确定信息密度、卡片尺寸与触控区，不是目标视觉。

## 8. 验收

- 正常整备只显示固定四人，无空位剪影、候选列表、容量或第五人入口。
- 四人卡在 375×817 下不遮挡装载和地图动作，人物识别与战斗/名册素材一致。
- 阵亡、灵息不足、超重、地图锁定和保存失败均可理解且不只依赖颜色。
- 四图、`map_05` 和两座副本入口使用统一地图卡系统，未解锁内容不泄露。
- 物品与资源图标跨页面完全复用，动态文案未烘焙进 PNG。
- 所有 Approved 资源有完整路径、逻辑/交付尺寸、许可和 Cocos 映射。

## 9. 不制作

空槽、随机修士候选、自动配队、第五人入口、扫荡、体力券、付费补充灵息、地图内容占位问号和
任何阶段专属整备页面。
