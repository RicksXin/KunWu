## 2. 文档职责与冲突顺序

1. 页面功能、信息层级、状态和交互以对应页面 PRD 为准。
2. Figma `Approved` 节点决定目标视觉、切图区域、组件状态与 Cocos 映射。
3. 本目录决定具体 PNG/序列帧/世界资产的制作、复用、命名、规格、来源与验收。
4. UI 视窗固定 `375×817`；营地全景逻辑宽 `1050`；世界 Tile 源像素 `16×16`、逻辑显示 `48×48`。
5. 当前实现和历史截图只能用于对比，不反向推翻 PRD 或 Approved Figma。

素材分册不得定义资源成本、掉率、剧情 Flag 或页面命令；发现冲突时回到上游策划/PRD 修正。

## 3. 1.0 美术边界同步

- 招贤馆只做建筑解锁、封印和后续开放说明；不制作候选、刷新、招募、馆级、容量或随机修士。
- 角色只制作石岩、陆清、白灵、墨言四名固定修士；NPC/异灵按剧情内容表制作。
- 装备只使用武器、防具、饰品一、饰品二四槽；不制作装备等级或强化角标。
- 装备品质六档：凡品、精制、上品、珍品、法宝、古宝；五档铁胚不含古宝铁胚。
- 器纹固定七种且永久写入；不制作拆卸、替换、重铸或锻纹尘素材。
- 炼器坊 24 级完整链路必须覆盖铁胚、器纹、打造、工具、突破物、行营阵盘和探灵灯。
- 世界内容覆盖 `map_01` 至 `map_04`、四个主线 Boss 与两座首发资源副本；`map_05` 只做锁定入口。
- 1.0 结局只做外层封印成功与深层威胁钩子，不制作完整游戏三种宏观结局。

## 4. 状态词与完成定义

| 状态 | 含义 |
|---|---|
| `缺失` | 已确认需要，但尚无可评审资产 |
| `待 Figma` | 切片/尺寸依赖尚未 Approved 的 Figma，不应提前定稿 |
| `风格探索` | 只可用于方向评审，不能导入运行时 |
| `Review` | 已有候选资产，等待用户人工评审 |
| `Approved` | 用户已确认视觉，可进入导入/实现 |
| `已导入占位` | 工程内存在但未通过视觉验收，不视为完成 |
| `已交付` | Approved、源文件/PNG/许可/导出表/Cocos 映射完整 |

## 7. 每批制作流程

1. 对应页面 PRD 冻结页面状态与交互。
2. Figma 交付默认/加载/空/禁用/锁定/错误和业务特有状态，用户确认至 `Approved`。
3. 检查已有 PNG、Component、九宫格、Tint、Mask 和 Label 能否复用。
4. 在对应分册展开完整资产表：稳定 ID、完整路径、逻辑/交付尺寸、输入截图、提示词/人工要求、许可。
5. 先做母版/差异设定板，再做批量变体；Review 未通过不继续扩量。
6. 人工检查像素、透明边缘、轮廓、色盘、状态与 PRD 语义。
7. 由 Cocos Creator 导入并生成 UUID；禁止手写或脚本伪造 `.meta`。
8. 回填 Figma 节点到 Cocos Prefab/节点映射和最终交付状态。

## 8. 通用交付要求

- UI PNG 同时写逻辑显示尺寸与实际像素尺寸，默认 `@3x`；世界资产按自身源像素规则交付。
- Pixel Art 整数像素对齐、整数倍缩放、nearest，透明边缘无白边和半透明污染。
- 运行时可变内容拆层；不可把红点、数量、品质、冷却或锁定原因固定画进物品主体。
- 动画/特效列明帧数、FPS、锚点、循环、事件时机和低画质降级。
- 第三方素材保留作者、来源、许可证、许可快照与 SHA-256，并与原创目录隔离。
- 任一表内仍有“缺失/待 Figma”且属于页面必做项时，该页面不能标记视觉交付完成。
