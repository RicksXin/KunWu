## 1. 正式范围与事实源

本分册覆盖 1.0 四图全部普通遭遇、精英、四个主线 Boss、两座资源副本战斗、固定四名修士、
三个职业阶段的 36 个稳定技能 ID、状态、战利品和失败报告表现。

- 技能与状态：[职业技能分册](../1.0策划案/17_1.0职业技能数值_草案.md)
- 敌人、精英与 Boss：[敌人与 Boss 分册](../1.0策划案/19_1.0敌人与Boss战斗数值_草案.md)
- 地图环境与资源副本：[四图内容素材](15_野外探索资源副本与四图内容.md)
- 战利品：[百宝库素材](12_百宝库装备资源包与分解.md)
- Sprite Sheet 与事件帧：[动画制作规范](../04_动画制作规范.md)

角色与敌人使用单张静态战斗立绘；Idle、技能、受击和阵亡不制作角色逐帧动作。行动反馈由立绘
Tween/Tint、数字、UI 状态和独立 Sprite Sheet 特效完成。表现只消费 `CombatEvent`，不能反向判伤。

## 2. 画面与布局基线

- 玩家可见窗口和 UI 基准为 `375×817`，底部保留手势安全区。
- 普通敌群位于中上方；Boss 居中，召唤物和机关按战斗定义环绕或分区。
- 四名修士位于底部安全区上方，不压住技能、目标和系统返回区。
- 敌我单位均显示名称、族类、生命、行动条和状态；立绘底色不能破坏信息可读性。
- 战场排版不创造前后排、距离或承伤规则。
- 页面只提供正常速度；暂停、行动决策、目标选择、技能禁用和战斗错误有独立状态。

## 5. 敌人、精英、Boss 与副本单位

完整清单从最终敌人内容表生成，每个 `enemy_id` 登记：

```text
enemy_id / map_id / tier / race / world_sprite / battle_portrait /
phase_variants / mechanic_objects / vfx / anchor / source / status
```

- 每个普通敌人至少一张静态战斗立绘；共享骨架只在外形和职责确实同源时允许。
- 精英至少在轮廓、部件或武器上与普通模板不同，不能只叠品质框。
- 四个主线 Boss 交付世界态、战斗静态立绘、策划要求的阶段变体和关键机制对象。
- 回火矿窟和镇魂残响使用阵法投影/机关，不复用已超度 NPC 作为可刷敌人。
- 世界棋子、战斗背景和机制对象由 15 分册登记，本分册维护静态立绘与战斗表现映射。

## 7. 技能与状态图标

- 36 个稳定技能 ID 全部映射到图标；机制完全相同才允许复用，不按制作阶段裁剪。
- 炼气、筑基、结丹在同一映射表维护；结丹精通不新增 ID 或第二张同义图标。
- 去重技能图标逻辑 `24×24`、交付 `72×72 @3x`，路径
  `assets/bundles/combat/icons/skills/icon_skill_<semantic_group>.png`。
- 状态图标按最终 `status_id` 全量导出，逻辑 `14×14`、交付 `42×42 @3x`。
- 增益、减益、控制、持续伤害、治疗限制和 Boss 机制不能只靠边框颜色区分。
- 图标不包含冷却数字、层数、技能名、职业名或“精通”文字。

映射表字段：

```text
stable_id / display_name / icon_path / semantic_group / reuse_reason /
logical_size / export_size / figma_node / cocos_target / status
```

## 8. Sprite Sheet 特效与事件映射

通用必需特效：行动就绪、普通攻击/施法起势、物理受击、术法受击、治疗、护盾、状态附加/移除、
阵亡魂火逸散、阶段切换和战利品揭示。

每个技能和 Boss 机制按事件登记：

```text
event_type / skill_or_mechanic_id / vfx_id / anchor / start_frame /
impact_frame / duration / loop / screen_shake / low_quality_variant
```

- 同一能量家族可复用色盘和粒子，但命中轮廓与时序必须能区分职责。
- 命中帧只触发表现信号，不执行领域伤害。
- 立绘 Tween/Tint 与 Sprite Sheet 共同表达动作；不把整个人物重新画进技能特效。
- 减少震屏或低画质下仍需保留命中、治疗、机制警告和阵亡语义。


新资源必须由 Cocos Creator 导入并生成 `.meta`。源文件、Sprite Sheet 裁切表、帧序、锚点、许可和
低画质变体与运行时文件一起登记。

## 10. 制作顺序

1. 完成单敌、敌群、Boss 多阶段和机制对象四类 Approved 页面稿。
2. 确认四人静态母版、尺寸和锚点，再验证 Tween/Tint 表现。
3. 从敌人内容表展开普通、精英、Boss 与副本单位全量清单。
4. 完成战斗 UI、族类、技能和状态映射表，先评审小批母版再批量制作。
5. 制作通用 Sprite Sheet 特效，再按技能/Boss 机制补专属表现。
6. 逐场把背景、单位、UI、图标和特效合成到 375×817 页面稿验收。

灰盒只用于尺寸、密度、遮挡和触控验证，不是目标视觉。

## 11. 验收

- 四名修士、全部 1.0 敌人/精英、四 Boss 和两座副本单位均有稳定 ID 到素材映射。
- 36 个技能 ID 与全部 1.0 状态均有合法图标，结丹精通不重复出图。
- 单敌、敌群、Boss 阶段、召唤物和机制对象在 375×817 下不遮挡关键 UI。
- 暂停、选择目标、技能禁用、阵亡、胜利、失败和错误可理解且不只依赖颜色。
- 表现跳过、低画质或 Tween 中断不改变结算，也不丢失命中/治疗/阵亡语义。
- PNG/Sprite Sheet 无烘焙文字和数值，nearest 下无模糊，锚点与 Cocos 映射完整。
