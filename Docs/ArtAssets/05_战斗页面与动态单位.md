## 2. 画面与布局基线

- 玩家可见窗口和 UI 基准为 `375×817`，底部保留手势安全区。
- 普通敌群位于中上方；Boss 居中，召唤物和机关按战斗定义环绕或分区。
- 四名修士位于底部安全区上方，不压住技能、目标和系统返回区。
- 敌我单位均显示名称、族类、生命、行动条和状态；立绘底色不能破坏信息可读性。
- 战场排版不创造前后排、距离或承伤规则。
- 页面只提供正常速度；暂停、行动决策、目标选择、技能禁用和战斗错误有独立状态。

## 7. 技能与状态图标

### 7.1 本批边界与不透明规则

- 36 个稳定技能 ID 全部建立映射；职业进阶中相同的技能视觉母题复用，本批收敛为 `30` 张技能图标。
  结丹“【精通】”只增强数值，沿用筑基技能 ID 与图标，不制作第二套。
- 技能图标是静态方形图，不制作序列帧、角色动作或图标自身动效。技能释放特效仍按第 8 节独立维护。
- 技能图标逻辑 `32×32`、交付 `96×96 @3x`，放入 `38×38` 技能按钮内。图标本体充满整个正方形，
  每一个像素 Alpha 都必须是 `100%`；不得有透明背景、透明四角、半透明烟雾或外侧留白。
- 技能按钮底框、选中、按下、冷却、禁用、目标非法和加载由运行时组件叠加，不为同一技能复制状态图。
- 状态图标逻辑 `14×14`、交付 `42×42 @3x`，同样使用完全不透明的方形底。层数、剩余时间和来源由 Label/
  Tooltip 表达。
- 技能和状态图标均不包含文字、字母、数字、职业名、“精通”、冷却、层数、品质框、按钮边框、水印或 Logo。
- 绝对不使用 `#00FF00`、绿色键色、透明棋盘格或其他伪透明底。


- 减少震屏或低画质下仍需保留命中、治疗、机制警告和阵亡语义。

- 36 个技能 ID 全部映射到本批 30 张去重图标，六组进阶复用有明确理由，结丹精通不重复出图；本批
  13 张 Buff/Debuff 先通过长列表混排，其余 1.0 `status_id` 仍需在内容表冻结后补齐。
- 单敌、敌群、Boss 阶段、召唤物和机制对象在 375×817 下不遮挡关键 UI。
- 暂停、选择目标、技能禁用、阵亡、胜利、失败和错误可理解且不只依赖颜色。
- 表现跳过、低画质或 Tween 中断不改变结算，也不丢失命中/治疗/阵亡语义。
- PNG/Sprite Sheet 无烘焙文字和数值，nearest 下无模糊，锚点与 Cocos 映射完整。
