## 8.1 本批用途与组件边界

本批新增 11 张通用 PNG：营地建筑事件标记 1 张、持续选中型小按钮 2 张、辟谷饼与
魂晶图标各 1 张，以及杂灵根至异灵根的六档资质边框 6 张。

- 建筑事件标记只表示“该建筑当前存在可处理事件”，不表示任务主线、奖励可领取、
  升级条件满足、危险或付费提醒。它位于建筑名称 Label 下方并随建筑横滑。
- 通用小按钮用于筛选、分页、模式和其他具有持续选中状态的选项，不代替点击即执行的
  `ui_common_button_inline_normal.png`。按钮文案由 Cocos Label 渲染。
- 辟谷饼是野外战利品和休整补给物品，进入临时背包并占负重。
- 魂晶是修士升级、突破与还魂使用的资源，由战斗和任务产出；战斗结算时即时入账，
  不进入普通背包，也不作为大厅付费货币展示。
- 六档灵根框只表达修士成长资质，不表达物品品质、修炼境界、职业、正魔阵营、是否
  选中或危险状态。它们作为透明覆盖层叠在通用方形图像槽和修士头像上方，不重画六套
  图像槽，也不单独承担头像内底。

建筑名称、事件说明、按钮文案、数量、奖励数值和“已选择”等状态文字全部由运行时
Label 或独立节点表达，不烘焙进本批 PNG。

## 8.4 本批背景与 Alpha 规则

本批提示词不使用绿色抠图底，也不包含 `#00FF00`：

- 两张按钮必须由底图填满整个矩形画布，所有像素 Alpha 为 `100%`。
- 三张独立图标和六张灵根框要求真实 Alpha；灵根框的中央必须真正透明。画布中不得
  出现绿色、白色、黑色或棋盘格展示背景，也不得出现投影展示板。
- GPT Image 2 若没有产生真实 Alpha，该输出只能作为待清稿母图，不能直接导入游戏；
  不得为了继续生成而自动追加绿色背景。用户可以在 Aseprite、Photoshop 等图像编辑
  工具中人工清理，或另行决定是否采用支持原生透明的生成流程；本批不依赖 Python。

## 8.6 制作顺序与验收

1. 先生成通用选项小按钮普通态，并在 `64×28`、`48×28`、`112×28` 三种宽度下检查；
   通过后只以普通态为编辑目标生成选中态。
2. 使用现有灵粮和灵石图标生成辟谷饼；使用灵晶和灵石图标生成魂晶。两张图必须分开
   生成，不能用一张四宫格素材板代替独立文件。
3. 生成杂灵根基础框并合成检查；通过后每一档都重新以杂灵根框为编辑目标分别生成，
   不串行编辑。六张框分别叠在同一修士头像和通用方形槽上检查颜色与纹样差异。
4. 最后生成建筑事件标记，并分别叠在议事殿、还魂殿和灵源院名称下方检查明暗对比。
5. GPT 输出若不是目标尺寸，使用图像编辑工具按像素方式裁切、清稿并导出到表中尺寸，
   缩放使用 Nearest；不使用 Python 脚本。
6. 用户确认图片后再放入运行时目录，让 Cocos Creator 导入并生成 `.meta`；不得手写
   或伪造 `.meta`。

验收：

- 建筑事件标记在亮灯、暗木和黛瓦建筑上都清楚，但没有被误认成主线任务、红点、奖励
  箱或危险警告；同一建筑不重复堆叠多个感叹号。
- 两种按钮轮廓、尺寸、九宫格切线完全一致；普通态和选中态单独查看都有完整不透明
  底面，选中态不是透明覆盖图，也没有厚重双层边框。
- 辟谷饼在 `24×24` 下能与灵粮谷穗、钱币、月饼、面包和丹药区分。
