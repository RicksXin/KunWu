## 2. 招贤馆 1.0 特别边界

- 建筑主体读取 [01_营地大厅建筑与传送阵.md](01_营地大厅建筑与传送阵.md)。
- 1.0 插图只表达馆舍已经整理、招贤功能尚被封存和后续开放。
- 不画三名候选、刷新沙漏、抽取卷轴、馆级、容量、随机职业剪影或付费货币。
- “后续版本开放”文字由 Label 渲染，插图只交付无字版本。

## 3. 还魂殿视觉边界

- 使用魂灯、引魂阵和四名固定修士身份锚点，表现归位而非抽卡重生。
- 阵亡状态不能遮黑整张头像；保留人物可识别特征并叠加魂灯熄灭/离位符号。
- 成功表现不画装备掉落、等级变化或随机品质，避免误解为重新生成角色。

## 4. 乌婆馈赠视觉边界

- 乌婆肖像复用 08 分册，不另画商店老板版头像。
- 两枚魂魄应表现 Boss 战斗残印：尸将魂旗/军阵、银翅羽刃/遁光；不画可交流真人魂球。
- 封坛军魂甲使用玄甲母题，上品品质框运行时叠加；银翅魂衣使用行衣母题，珍品框叠加。
- 馈赠表现是乌婆超度意识、保留魂性残印，不使用炼化活魂、抽卡翻牌或随机宝箱视觉。

## 5. Figma 前置

- 交易购买/出售/回购的空、锁定、售罄、保底、警告、冲突和错误状态。
- 还魂空状态、单/多人阵亡、魂晶不足、成功/失败。
- 招贤馆大厅未解锁/事件/已解锁和静态说明页。
- 乌婆无魂魄、可交付、已兑换、仓库待处理、旧档补发。

## 6. 验收

- 四页的室内/说明视觉一眼可区分，但按钮、列表和模态复用同一组件系统。
- 交易状态不只靠颜色；回购不会画成随机新商品。
- 招贤馆整页无任何可被理解为 1.0 可招募的功能锚点。
- 两件魂器图标与普通玄甲/行衣模板有可识别特征，且不烘焙品质、器纹或名称文字。
- 所有光效提供低画质降级，不遮挡确认结果与唯一状态。
