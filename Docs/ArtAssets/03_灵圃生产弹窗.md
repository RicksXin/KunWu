# 5. 灵圃生产弹窗

版本：0.1\
日期：2026-08-01\
状态：美术制作唯一事实源分册\
上级索引：[《昆吾禁地》美术素材制作总清单](README.md)


本节参考用户提供的两张第三方游戏截图，只借鉴“大厅上方打开纵向生产面板、
操作后叠加二次确认弹窗”以及两级弹窗的框体继承关系，不复制其具体视觉。

本项目的框体关系冻结为：主面板与二次确认弹窗使用同一张基础九宫格，宽度、材质、
描边粗细和四角结构完全一致，只通过运行时高度区分；主面板再额外叠加独立的顶部、
底部装饰。二次确认弹窗只使用基础九宫格，不生成另一套边框。顶部装饰中央必须保留
标题安全区，标题仍由 Cocos Label 渲染。

参考图中的双龙/双兽、银色金属浮雕、哥特尖刺、资源图标、升级按钮、工匠招募按钮、
双倍收益、货币栏和具体间距均不得进入《昆吾禁地》素材。

```text
大厅（保持原位置并变暗）
└─ 灵圃生产弹窗
   ├─ 标题“灵圃”
   ├─ 灵粮岗位：图标、库存/上限、净产量、升级、- / x/y / +
   ├─ 灵木岗位：图标、库存/上限、当前产量、升级、- / x/y / +
   ├─ 玄铁岗位：图标、库存/上限、当前产量、升级、- / x/y / +
   ├─ 任一资源升级：灵木消耗 + 当前上限 → 新上限 + 升级 / 取消
   └─ 结算倒计时 + 30 秒周期条 + 压在面板背景下边缘的杂役招募 / 关闭
      └─ 杂役招募：灵粮消耗 + 杂役 +5 + 招募 / 取消
```

P2 开放灵晶和庚精时启用 Prefab 中预留的两个资源行节点，不新增页面，也不改变为
滚动列表；尚未开放的资源仍不显示对应行。

## 5.5 制作顺序与验收

1. 先完成灵圃主弹窗、杂役招募弹窗和储量升级弹窗灰盒，截取 §5.2.2 的五张项目截图。
2. 先只生成共用基础九宫格，同时合成一张 `343×650` 主面板和一张 `319×280`
   二次确认弹窗，确认两者的边宽、四角、材质和像素密度完全一致。
3. 基础框通过后依次生成顶部、底部装饰；只给主面板叠加，在标题区放入实际 Label
   检查留白，二次确认弹窗继续只显示基础框。
4. 先生成通用列表项普通底板，并分别拉伸到灵圃资源行、入山装载行、修士列表和
   地图列表的实际尺寸检查；普通态通过后，再以它为编辑目标生成选中态完整底板。
5. 在灰盒截图中同时合成普通项、选中项和锁定项，检查 P1 三行无重叠，且库存/上限、
   升级、分配和选中状态清楚。
6. 保留已通过方向确认的加减按钮和通用行内按钮，按新提示词重做通用底部按钮；
   重点验收连续矩形外轮廓与运行时状态。
7. 复用或补齐资源图标，最后生成周期条。
8. 所有素材导入 Cocos 后设置 Nearest；基础框和列表项使用九宫格，上下装饰使用横向三切片，
   并按表格中的逻辑尺寸显示。

验收：

- 点击灵圃后只出现一个纵向生产弹窗，大厅在后方变暗且不发生场景切换。
- P1 主弹窗只显示灵粮、灵木、玄铁三条可操作资源行；未开放的灵晶、庚精不显示，
  且没有产量升级、双倍收益、广告或付费入口。
- 玩家能在 3 秒内看到各岗位 `x/y`、库存/上限、当前产量、升级和 `-`/`+`。
- 灵粮行产量随灵粮岗人数增加，并随灵木/玄铁岗位维护实时减少；页面不显示储量等级、
  “下周期”汇总或“全部岗位可正常生产”文案。
- 主弹窗底部只有“杂役招募/关闭”，不存在“确认分配”按钮。
- 主面板与招募/储量升级二次弹窗使用同一张 `ui_common_modal_frame.png`；二次确认仅
  改变高度，不存在另一张确认弹窗边框。
- 只有主面板叠加顶部、底部装饰；二次确认弹窗不得出现装饰残片、标题冠饰或底部冠饰。
- 主面板顶部装饰中央能稳定放入不同长度的建筑标题，文字四周留白充足，装饰不穿过
  标题、不压住首行内容。
- 上下装饰的材质、描边和像素密度与基础框一致；底部装饰明显低于、轻于顶部装饰，
  不读作承重底座。
- 普通列表项只靠低对比底色和轻微材质变化形成清楚但低调的分行，不抢正文、图标、
  头像和按钮；多行连续排列时不会形成独立卡片感，也没有可见外框、内框或包角。
- 普通态和选中态底板的尺寸、外轮廓、九宫格切线及画布边界逐像素一致；选中时没有
  跳动、缩放或内容位移。
- 选中态同时具有整行轻微明度变化、左侧朱砂短标及运行时文字，不只依赖颜色；不得
  出现外框、内框、包角、角标结构或发光边，朱砂短标不会被误认成红点、警告或付费入口。
- 选中底板位于头像、资源图标、文字、按钮和进度信息下层；禁用与锁定项继续使用
  降亮度、锁图标和原因文字，不新增第三张背景。
- 灵粮不足时二次弹窗的招募按钮禁用，取消按钮仍可辨识且可用。
- 灵木不足时储量升级弹窗的升级按钮禁用；灵木充足时明确显示升级后的最大储量。
- 灵粮、灵木、玄铁与大厅顶部使用相同图标文件。
- 资源行内的“升级”只使用通用行内按钮，轮廓薄、对比低，不再出现旧按钮的厚木桩和灰白玉牌。
- 主弹窗和确认弹窗底部只使用通用底部按钮；必须是连续规整的横向长方形，不得有阶梯形、外扩侧翼、突出端盖或底部基座。
- 弹窗、资源行和按钮缩放后像素清楚；基础九宫格和上下三切片均没有拉伸破损。
- 按钮按下时在 `100ms` 内完成 `94%` 缩小回弹，不改变热区；悬停和禁用 Tint 能清楚区分可用状态。
- 灵粮不足与停工通过文字说明，不只依赖颜色。
- 所有文案和数值由 Label 渲染，PNG 中没有烘焙文字或数字。
- 美术只借鉴参考截图的组件继承和信息层级，没有复制双龙/双兽边框、银色浮雕、
  外部图标或按钮。
- 所有按钮节点至少 `48×48dp`，在目标分辨率和安全区内无遮挡。
